1. 별 모양 — 둘이 나란히, 셋째가 정리 (계획)

섹션 제목: “1. 별 모양 — 둘이 나란히, 셋째가 정리 (계획)”

Orchestrator가 돌아가는 길 없이 시작하고, 기다리고, 결과를 읽고, 남겨 둔 Worker를 보고하는가?

  • 해 보는 법: Orchestrator 1, Worker 3 · Claude Code · Codex · macOS 한 대
  • 통과 기준:
    • 첫 worker start가 네 번째 호출 안에 나옴
    • 프로필이나 세션을 따로 만들지 않고, sleep · echo로 기다리지 않음
    • 보고마다 요약이 있고, 결과마다 task show를 한 번만 부름
    • tasks-ended나 idle로 끝나고, 보고를 확인한 Worker는 닫히며 --keep-open으로 남긴 수를 보고함. 사람이 요청하면 lyra terminal release로 놓아 줌
  • 결과: 아직 해 보지 않았습니다.

2. 나무 모양 — Lead 둘이 나눠 맡음 (계획)

섹션 제목: “2. 나무 모양 — Lead 둘이 나눠 맡음 (계획)”

기다리는 Lead가 부모에게 기다림으로 보여, 부모는 큰일만 듣는가?

  • 해 보는 법: Orchestrator 1, Lead 2, Worker 4 · Claude Code · Codex · macOS 한 대
  • 통과 기준:
    • Lead마다 자기 Workspace에서 일함
    • Claude Code Lead는 task wait --all --timeout 15m을 배경에서 돌리고 턴을 끝내고, Codex Lead는 --timeout 9m으로 앞에서 되풀이함
    • 기다리는 Lead 때문에 부모가 worker-stopped · worker-suspect를 받지 않음
    • 마지막에 부모가 합침
  • 결과: 아직 해 보지 않았습니다.

3. 질문하고 이어 가기 (계획)

섹션 제목: “3. 질문하고 이어 가기 (계획)”

Worker가 묻고, 기다리고, 답을 받아 이어 가는가?

  • 해 보는 법: Orchestrator 1, Worker 1 · Claude Code · Codex · macOS 한 대 · 결정 하나를 열어 둔 작업 글
  • 통과 기준:
    • Worker가 작업·시도 ID로 질문하고 연결된 답변을 기다립니다.
    • message ask가 답변을 반환하면 일을 잇습니다. 시간이 지난 질문은 다시 기다릴 수 있습니다.
    • Orchestrator가 message reply로 한 번 답합니다. 답은 기다리는 ask나 메시지로 Worker에게 적어도 한 번 닿고, Worker는 그 답에 한 번만 따릅니다.
  • 결과: 아직 해 보지 않았습니다.

4. 막 연 세션에게 인계 (계획)

섹션 제목: “4. 막 연 세션에게 인계 (계획)”

막 연 세션이 첫 턴을 마치기 전에 인계를 받는가?

  • 해 보는 법: Orchestrator 1, 새 세션 1 · Claude Code · macOS 한 대 · worker start --handoff
  • 통과 기준:
    • 받는 쪽이 60초 안에 명시적으로 ack함 (not_delivered가 아님).
    • 받는 쪽이 준 쪽의 자리와 역할을 받음
    • 보고는 받는 쪽만 들음
  • 결과: 아직 해 보지 않았습니다.

5. Worker 프로세스가 죽을 때 (계획)

섹션 제목: “5. Worker 프로세스가 죽을 때 (계획)”

Orchestrator가 사람에게 알리고, 사람의 말이 있을 때만 손을 쓰는가?

  • 해 보는 법: Orchestrator 1, Worker 2 · Claude Code · macOS 한 대 · 작업 중인 Worker 하나의 에이전트 프로세스를 Lyra 밖에서 종료
  • 통과 기준:
    • 원인과 다음 명령을 사람에게 알림
    • 사람의 말 전에는 취소도 다시 시도도 하지 않음
    • 그 뒤 취소 → 다시 시도 → 같은 Workspace에 새 Worker
  • 결과: 아직 해 보지 않았습니다.

6. 끝난 Orchestrator의 일 넘겨받기 (계획)

섹션 제목: “6. 끝난 Orchestrator의 일 넘겨받기 (계획)”

새 세션이 끝난 Orchestrator의 계획을 이어받는가?

  • 해 보는 법: 끝날 Orchestrator 1, 새 Orchestrator 1, Worker 2 · Claude Code · Codex · macOS 한 대 · 작업이 도는 중에 lyra-daemon을 멈춤
  • 통과 기준:
    • 끝난 세션을 찾고, 사람의 말에 넘겨받음
    • task list로 계획을 다시 세움
    • 죽은 Worker를 새 Worker로 바꿈
  • 결과: 아직 해 보지 않았습니다.

7. Worker가 적게 읽고 보고하는가 (계획)

섹션 제목: “7. Worker가 적게 읽고 보고하는가 (계획)”

Worker가 작업 글만으로 보고까지 가는가?

    • 스킬을 읽지 않음. 꼬리말 명령이 실패했을 때만 worker 참고를 읽음
  • 결과: 아직 해 보지 않았습니다.

10. 원격 컴퓨터와 연결이 끊길 때 (아이디어)

섹션 제목: “10. 원격 컴퓨터와 연결이 끊길 때 (아이디어)”

연결이 끊기면 연결 중에만 실행하는 작업은 멈추고, 기본 작업은 계속 가는가?

  • 해 보는 법: Orchestrator 1, Worker 2 · Claude Code · Codex · macOS (Orchestrator) · SSH로 원격 서버 (Worker 2) · 아직 정하지 않음: 어느 서버에서, 연결을 어떻게 끊을지

    • 연결 중에만 실행하는 작업이 stopped로 읽힘
    • 기본 작업은 연결이 돌아온 뒤 보고함
    • unknown은 다시 시도가 아니라 사람에게 감
  • 결과: 아직 해 보지 않았습니다.

11. 한 시간짜리 일 (아이디어)
