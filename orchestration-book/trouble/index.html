이럴 때는

증상을 찾으면 뜻과 할 일이 나옵니다. 사람이 할 일과 에이전트가 할 일을 나눠 적었습니다.

Worker가 10분 넘게 조용해요

섹션 제목: “Worker가 10분 넘게 조용해요”

No updates · worker-suspect

  • 보이는 것: 세션 줄에 No updates가 보이고, Orchestrator의 기다림은 worker-suspect로 깨어납니다.
  • 뜻: 10분간 진행 신호가 없다는 뜻입니다. 관측하지 못한 빌드나 테스트도 같아 보입니다. 실행 중인 도구의 표시는 얼마나 오래 돌았는지와 CPU 측정에서 본 것만 알려 줍니다. CPU 사용이 없다고 멈춘 것은 아니고, CPU를 쓴다고 정상인 것도 아닙니다.
  • 사람이 할 일: 바로 취소하지 않습니다. 걱정되면 그 Worker의 화면을 한 번 봅니다.
  • 에이전트가 할 일: 한 번 봅니다: status show의 turn, session read로 마지막에 한 일, git status의 변경. 다음 checkpoint에도 소식이 없으면 본 것을 사람에게 알립니다. 조용하다는 이유로 취소, 다시 시도, 다시 맡기기를 하지 않습니다.

보고 없이 턴이 끝났어요

섹션 제목: “보고 없이 턴이 끝났어요”

worker-stopped

  • 뜻: Worker가 보고하지 않고 턴을 끝냈습니다. 성공도 실패도 아닙니다.
  • 에이전트가 할 일: 방금 질문을 받았다면 그 질문이 멈춘 이유입니다: 아직 답하지 않았다면 답만 보내고 다른 것은 보내지 않습니다. 아니면 메시지 하나로 결과를 보고하거나 막힌 것을 말해 달라고 합니다. 또 멈추면 그 Worker가 마지막에 한 말을 사람에게 알립니다.

worker start가 중간에 멈췄어요

섹션 제목: “worker start가 중간에 멈췄어요”

failedStep · created · next

  • 뜻: 여러 단계 가운데 하나가 실패했습니다. 이미 만든 것(created)은 남고, 되돌리지 않습니다.
  • 에이전트가 할 일: error.detail의 failedStep과 next를 읽습니다. worker start를 다시 부르지 않고, 원인을 푼 뒤 next를 새 --request-id로 실행합니다.

명령이 exit 3으로 끝났어요

섹션 제목: “명령이 exit 3으로 끝났어요”

Unknown

  • 뜻: 실패가 아니라 ‘모름’입니다. 처음 것이 이미 됐을 수도 있습니다.
  • 에이전트가 할 일: 먼저 lyra request show <request-id> --operation <operation> --json으로 저장된 응답을 확인한 뒤 작업이나 갈림길을 읽으세요. message ask와 message reply는 이 조회 없이 바로 같은 요청을 다시 보냅니다. 응답 조회는 아무 작업도 적용하지 않습니다. 다시 요청할 때는 같은 요청 ID와 인자를 쓰세요. 응답이 없어도 처리 중일 수 있으니 새 ID로 우회하지 마세요.

깊이 한도로 거절됐어요

섹션 제목: “깊이 한도로 거절됐어요”
  • 뜻: 그 자리에서는 더 깊은 세션을 시작할 수 없습니다. 한도는 설정에서 정합니다 (기본 2). Worker는 깊이와 상관없이 세션을 시작하지 않습니다.
  • 사람이 할 일: 필요하면 설정 → 오케스트레이션에서 깊이 한도를 올립니다. 에이전트는 한도를 바꾸지 못합니다.
  • 에이전트가 할 일: 그 부분을 Worker에게 맡기거나 워크플로로 나누고, 아니면 작업 주인에게 메시지로 묻습니다.

인계가 거절됐어요

섹션 제목: “인계가 거절됐어요”
  • 뜻: 받는 쪽이 넘기는 가지 안에 있거나(고리), Worker가 자식을 받게 되거나, 옮겨 가는 가지가 깊이 한도를 넘습니다. 보내기 전과 받을 때 두 번 확인합니다.
  • 에이전트가 할 일: 나무에서 더 위의 받는 쪽, 또는 Lead나 Orchestrator를 고릅니다. 역할 바꾸기는 계획입니다.

메시지를 보냈는데 안 읽어요

섹션 제목: “메시지를 보냈는데 안 읽어요”

delivery.pointer

  • 뜻: accepted는 저장했다는 뜻이지 읽었다는 뜻이 아닙니다. 일반 메시지는 ‘메시지 모아 전달’ 시간(기본 5분)까지 기다렸다가 초인종이 울리고, --urgent 메시지는 바로 울립니다. 초인종이 잠깐 거절되면 Lyra가 스스로 다시 칩니다. 바쁜 세션은 다음 확인 때 읽습니다. 끝내 전할 수 없으면 보낸 쪽의 기다림이 message-held로 깨어납니다.
  • 에이전트가 할 일: message show로 배달과 초인종(delivery.pointer)을 봅니다. 기다림이 message-held로 깨어나면: 받는 쪽이 닫혔으면 그 일을 살아 있는 세션에 넘기고, 결과를 모르면 다시 보내지 말고 session show를 본 뒤 사람에게 묻습니다.

에이전트 화면에 대화 상자가 떴어요

섹션 제목: “에이전트 화면에 대화 상자가 떴어요”
  • 뜻: Worker의 에이전트가 대화 상자(업데이트, 폴더 신뢰, 폴더, 모델, 훅, 질문)를 띄웠거나 아직 준비되지 않았습니다. 작업은 쳐 넣지 않았습니다.
  • 사람이 할 일: 그 터미널에서 대화 상자에 답합니다.
  • 에이전트가 할 일: 사람에게 그 터미널에서 답해 달라고 하고, 답한 뒤 next를 새 --request-id로 실행합니다.

이전 lyra-daemon이 사람의 입력 때문에 작업을 보내지 않았어요

섹션 제목: “이전 lyra-daemon이 사람의 입력 때문에 작업을 보내지 않았어요”
  • 뜻: 그 Worker를 돌리는 lyra-daemon이 이전 버전이라, 사람이 그 화면의 입력을 잡고 있는 동안 작업을 쳐 넣지 않았습니다. 지금 버전은 막지 않습니다.
  • 사람이 할 일: 그 화면을 닫습니다.
  • 에이전트가 할 일: 사람에게 그 화면을 닫아 달라고 하고, 그 뒤 next를 새 --request-id로 실행합니다.

내 세션이 끝났어요

섹션 제목: “내 세션이 끝났어요”
  • 뜻: lyra-daemon이 멈추면 그 lyra-daemon이 돌리던 세션이 모두 끝납니다. 새 세션은 넘겨받기 전까지 아무것도 갖지 않습니다.
  • 사람이 할 일: 새 세션에게 끝난 세션의 일을 넘겨받으라고 말합니다.
  • 에이전트가 할 일: 사람의 말이 있으면 끝난 세션(failed나 closed)을 찾아 task adopt --from으로 넘겨받고, task list로 계획을 다시 봅니다. 그 세션이 아직 돌고 있으면 넘겨받기는 거절됩니다.

Worker가 보고를 못 해요

섹션 제목: “Worker가 보고를 못 해요”
  • 뜻: 에이전트가 Lyra의 세션 변수를 잃었습니다. ID를 짐작하거나 변수를 스스로 넣으면 안 됩니다.
  • 사람이 할 일: 그 Worker의 마지막 답에 남은 오류와 요약을 읽고 처리합니다.
  • 에이전트가 할 일: next를 따르지 않습니다. 정확한 오류와 요약을 마지막 답에 적고 멈춥니다.

취소했는데 멈추지 않아요

섹션 제목: “취소했는데 멈추지 않아요”
  • 뜻: 취소는 Ctrl-C 한 번을 친 요청입니다. Worker가 보고하거나 그 프로세스가 끝난 것이 확인되어야 stopped가 됩니다.
  • 사람이 할 일: 프로세스 종료를 확인하려면 session force-stop을 사용합니다. 확인되지 않은 배차가 계속 실행될 수 있는 --abandon-unproven은 여전히 사람만 정합니다.
  • 에이전트가 할 일: Worker에게 stopped를 보고해 달라고 요청합니다. Worker 위의 Orchestrator나 Lead는 명시적으로 강제 종료할 수 있고, 그 외에는 사람에게 요청합니다. 종료가 확인된 뒤에만 재시도하거나 다시 배정하며 중복 작업은 시작하지 않습니다.

같은 작업을 다른 Worker에게 또 줘도 되나요?

섹션 제목: “같은 작업을 다른 Worker에게 또 줘도 되나요?”
  • 뜻: 안 됩니다. 처음 맡긴 일이 아직 돌 수 있습니다 (배차가 unknown이거나 turn이 not-started).
  • 에이전트가 할 일: 먼저 봅니다. 시도가 returned면 새 요청 ID로 다시 배차하고, dispatching이면 멈추고 사람에게 알립니다.

terminal release가 안 돼요

섹션 제목: “terminal release가 안 돼요”
  • 뜻: 놓기 전에 대화와 결과가 보존됐는지 확인합니다. 결과가 아직 없거나 checking, closing이면 끝나지 않은 것이고, 결과를 모른다는 답이면 놓였는지 알 수 없는 것입니다.
  • 에이전트가 할 일: 결과가 없으면 기다립니다. 결과를 모르면 사람에게 알립니다. 놓기가 실패했다고 세션을 대신 닫지 않습니다.

Worker를 더 시작할 수 없어요

섹션 제목: “Worker를 더 시작할 수 없어요”
  • 뜻: 사람이 설정 → 오케스트레이션에서 ‘동시에 도는 Worker 수 제한’을 켰고, Working인 Worker가 그 수에 닿았습니다.
  • 사람이 할 일: 제한을 올리거나 끕니다.
  • 에이전트가 할 일: Worker 하나가 끝나기를 기다렸다가 다시 시작합니다. 제한은 사람만 바꿉니다.

작업 글이 16 KiB를 넘어요

섹션 제목: “작업 글이 16 KiB를 넘어요”
  • 뜻: 꼬리말을 붙인 작업 글이 16 KiB를 넘으면 쳐 넣지 않습니다. 아무것도 시작하지 않았고, 작업은 아직 준비 상태입니다.
  • 에이전트가 할 일: 작업 글을 줄이고, 붙여 넣는 대신 파일을 가리킵니다. 그다음 next를 새 --request-id로 한 번 실행합니다. 같은 코드가 또 나오면 멈추고 알립니다.

이 컴퓨터의 lyra-daemon이 돌지 않아요

섹션 제목: “이 컴퓨터의 lyra-daemon이 돌지 않아요”
  • 뜻: 이 컴퓨터의 lyra-daemon이 돌지 않아 명령이 닿지 않습니다.
  • 사람이 할 일: Lyra 앱을 열거나 lyra daemon start로 시작합니다.
  • 에이전트가 할 일: 사람에게 알리고, 사람의 말이 있을 때만 lyra daemon start --json으로 시작합니다.

turn이 not-started인 채 소식이 없어요

섹션 제목: “turn이 not-started인 채 소식이 없어요”

not-started

  • 뜻: 글이 입력 칸에 남아 있거나, 에이전트가 턴 신호를 보내지 않습니다.
