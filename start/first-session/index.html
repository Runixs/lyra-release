첫 Session

이 페이지는 설치를 마친 사람을 위한 것입니다. 순서는 다음과 같습니다.

  1. 프로젝트를 추가합니다.
  2. 작업 자리(Worktree 또는 Workspace)를 만듭니다.
  3. 에이전트 Session을 엽니다.

1. 프로젝트 추가

섹션 제목: “1. 프로젝트 추가”

Project는 Lyra에 등록한 저장소 또는 폴더입니다.

  1. 왼쪽 막대에서 프로젝트를 엽니다.

  2. 탐색기 위쪽의 폴더 모양 프로젝트 추가 버튼을 누릅니다. 프로젝트가 하나도 없으면 목록 안에도 같은 버튼이 있습니다. 폴더를 탐색기로 끌어다 놓아도 추가됩니다.

    예시 데이터로 찍은 화면입니다.

  3. Add Project 창에서 방법을 고릅니다: 폴더 열기, URL에서 복제, 새로 만들기.

  4. Path에 폴더 경로를 적거나, 폴더 모양 버튼(폴더 찾아보기)으로 고릅니다.

  5. 추가를 누릅니다.

연결해 둔 서버가 있으면 Host에서 어디에 추가할지 고릅니다. 이 컴퓨터는 localhost로 표시됩니다. 서버가 아직 연결 전이면 “연결한 후 폴더를 선택하세요”라고 나오고 연결 버튼이 있습니다.

Git 저장소가 아닌 폴더는 한 번 더 확인 창이 뜹니다. 폴더로 추가를 누르면 폴더 그대로 추가됩니다. 폴더를 여러 개 한꺼번에 고르면 Git 저장소가 아닌 폴더는 건너뛰고 몇 개를 건너뛰었는지 알려 줍니다. 건너뛴 폴더는 하나씩 추가하세요.

추가가 끝나면 새 프로젝트가 펼쳐지고, 그 프로젝트 폴더의 작업 자리가 열립니다.

2. 작업 자리 만들기

섹션 제목: “2. 작업 자리 만들기”

Git 저장소는 Worktree(같은 저장소에서 브랜치별로 따로 쓰는 작업 폴더)를 만들고, Git이 아닌 폴더는 Workspace(작업 폴더 하나)를 만듭니다. 에이전트는 이 자리 안에서 일합니다.

  1. 프로젝트 줄의 + 버튼을 누릅니다. 줄의 메뉴에서 Worktree 추가(Git이 아니면 Workspace 추가)를 골라도 됩니다.
  2. Create Worktree 창(Git이 아니면 Create Workspace)이 열립니다.
  3. Git 저장소라면 이름을 적고 시작 브랜치를 고릅니다. Host 칸은 선택지가 둘 이상이거나 Windows에서 WSL 배포판을 추가했을 때만 나옵니다.
  4. 에이전트 칸에서 만들자마자 열 에이전트를 고릅니다. 열지 않으려면 세션 없이를 고릅니다.
  5. 생성을 누릅니다.

에이전트를 골랐는데 Setup Script가 아직 돌고 있으면 화면에 “준비 명령이 끝나면 세션을 시작합니다”라고 나옵니다.

각 Worktree에는 겹치지 않게 색이 하나씩 붙고, 탐색기 줄과 카드 띠에 같은 색이 보입니다.

Setup Script와 신뢰 확인

섹션 제목: “Setup Script와 신뢰 확인”

Setup Script는 작업 자리를 만들 때 먼저 돌리는 준비 명령입니다(프로젝트의 .lyra/config.yaml에 있습니다). 편집은 프로젝트 설정의 Setup Script에서 합니다. Create Worktree 창에는 입력칸이 없습니다.

  • 명령이 새로 생겼거나 바뀌었으면 Setup Script 실행 창이 명령 목록을 보여 줍니다. 읽어 본 뒤 실행 또는 실행하지 않기를 고릅니다. 이 프로젝트 항상 신뢰를 켜면 이 프로젝트는 다음부터 묻지 않습니다.
  • 명령이 없으면 묻지 않고 넘어갑니다.
  • 파일이 잘못되었거나 읽을 수 없으면 만들 수 없습니다. 이때는 이번에는 Setup Script 실행 안 함을 켜면 그것 없이 만들 수 있습니다.

모르는 프로젝트의 명령은 내용을 읽은 뒤에 실행을 누르세요.

작업 자리 삭제

섹션 제목: “작업 자리 삭제”

작업 자리 줄의 메뉴에서 **Worktree 삭제…**를 고르면 작업 자리 삭제 창이 열립니다.

  • 돌고 있는 Session과 터미널을 정해진 순서로 멈추고, 하나라도 멈춘 것을 확인하지 못하면 거기서 그치고 폴더를 그대로 둡니다.
  • 만든 브랜치에 합치지 않은 커밋이 있으면 브랜치는 남기고 삭제와 브랜치도 삭제 중에서 고릅니다.
  • 프로젝트 폴더 자체의 작업 자리에는 삭제 항목이 없습니다.

3. Session 열기

섹션 제목: “3. Session 열기”

Session은 에이전트 한 명과 하는 하나의 작업입니다. 프로젝트 화면에서 작업 자리를 고르면 시작 화면이 나옵니다.

시작 화면에서 열기

섹션 제목: “시작 화면에서 열기”

빈 작업 자리에는 입력 상자가 있는 시작 화면이 나옵니다.

  1. 입력 상자에 할 일을 적습니다. (“<이름>에서 할 일을 적으세요”라고 안내합니다.)
  2. 에이전트를 고릅니다. 모델 칩이 보이면 모델도 고릅니다.
  3. 보내기 버튼(새 세션으로 보내기)을 누릅니다.

에이전트 목록에는 이 컴퓨터(또는 고른 서버)에서 켜 둔 프로필(에이전트를 어떻게 실행할지 적어 둔 설정)이 이름으로 나옵니다. 시작할 수 있는 것은 Claude Code, Codex, OpenCode입니다. OpenCode는 2.0.0 이상만 시작됩니다. 더 낮으면 목록에는 나오지만, 시작할 때 「…OpenCode … 버전이 Lyra에 필요한 버전(2.0.0 이상)보다 낮아 세션을 열지 않았습니다. 그 컴퓨터에서 opencode upgrade를 실행한 뒤 다시 시작하세요.」가 나옵니다.

첫 메시지를 받을 수 없는 에이전트는 “아래에서 메시지 없이 열어 주세요”라고 나옵니다. 아래 메뉴로 여세요.

그 컴퓨터에서 Claude Code, Codex, OpenCode를 하나도 찾지 못했으면 「…에서 설치된 에이전트(Claude Code, Codex, OpenCode)를 찾지 못했습니다. 에이전트를 설치한 뒤 시작하세요.」와 설정 › 에이전트에서 보기가 나옵니다. 누르면 그 컴퓨터가 골라진 채 에이전트 설정이 열립니다. 아직 찾는 중이면 이 문장은 나오지 않습니다.

메뉴에서 열기

섹션 제목: “메뉴에서 열기”

시작 화면의 버튼이나 탭의 + 메뉴에서도 열 수 있습니다. 메뉴는 이 순서입니다.

  1. 켜 둔 프로필 목록
  2. 에이전트 관리…
  3. 터미널: New Terminal, New PowerShell, New Git Bash

Claude Code와 Codex는 프로필 옆 화살표에서 모델을 고를 수 있습니다. 맨 위의 Default를 고르면 모델을 지정하지 않고 엽니다. 모델 목록을 읽지 못해도 “기본 모델로 엽니다”라고 알리고 열 수 있습니다.

프로필이 하나도 켜져 있지 않으면 “이 호스트에 켠 프로필이 없습니다”라고 나옵니다. 아래 “프로필 추가”를 보세요.

터미널만 필요하면 New Terminal(cmd), New PowerShell, New Git Bash를 고릅니다.

열리는 동안, 그리고 열리지 않을 때

섹션 제목: “열리는 동안, 그리고 열리지 않을 때”

여는 동안 보내기 버튼에 돌아가는 표시가 나옵니다. 실패하면 Session 화면이나 알림에 이유가 나옵니다.

  • “새 세션을 열지 못했습니다” — 적어 둔 내용은 남겨 둡니다.
  • “세션은 열렸지만 첫 메시지를 보내지 못했습니다”
  • “시작 또는 전송 여부를 확인하지 못했습니다” — 세션 열어 확인으로 확인합니다.

상태 낱말

섹션 제목: “상태 낱말”

Session 상태는 영어 낱말 그대로 나옵니다.

  • 작업 상태: Working, Waiting, Done, Idle, Interrupted
  • 열림과 닫힘: Opening, Active, Closing, Closed
  • 실패: Failed, Failed · Unverified

Failed · Unverified는 시작 실패는 알지만 처음 시작한 프로세스가 멈췄는지 확인하지 못했다는 뜻입니다. 문제 해결에서 다룹니다.

에이전트 프로그램이 설치되어 있지 않을 때

섹션 제목: “에이전트 프로그램이 설치되어 있지 않을 때”

Session을 열다 이 컴퓨터(또는 서버)에서 에이전트 프로그램을 찾지 못하면, 실패 안내 옆에 설정 › 에이전트에서 보기 링크가 나옵니다. 이 링크는 설정의 에이전트 화면으로 데려다 줍니다(왼쪽 목록의 연결 아래). 설치 창은 자동으로 열리지 않으니 직접 여세요.

  1. 설정 → 에이전트를 엽니다.
  2. 왼쪽 기계 목록에서 설치하려는 컴퓨터를 고르고, 오른쪽 칸 머리의 에이전트/프로필 추가를 누릅니다.
  3. **에이전트 설치…**를 고릅니다. 지원 가능 아래 그 에이전트 줄의 설치 방법을 눌러도 됩니다.
  4. 설치할 에이전트의 설치 방법을 펼칩니다. 앱이 그 컴퓨터의 운영체제에 맞는 명령을 보여 주고, 복사 버튼이 있습니다.
  5. 명령을 그 컴퓨터의 터미널에서 직접 실행합니다. Lyra는 이 명령을 대신 실행하지 않습니다.
  6. 설치가 끝나면 지금 확인을 누릅니다.

설치되지 않은 에이전트는 지원 가능 아래에 설치 안 됨으로 나옵니다.

프로필 추가

섹션 제목: “프로필 추가”

프로필은 에이전트를 어떻게 실행할지 적어 둔 설정입니다. 컴퓨터(호스트)마다 따로 둡니다.

  1. 설정 → 에이전트를 엽니다.
  2. 왼쪽 기계 목록에서 컴퓨터를 고르고, 에이전트/프로필 추가를 누른 뒤 **프로필 추가…**를 고릅니다. 그 컴퓨터에서 에이전트가 확인된 뒤에만 켜집니다. 에이전트 줄의 **⋯**에서 **프로필 복사…**를 골라도 됩니다.
  3. 프로필 이름과 에이전트를 정하고, 필요하면 실행 파일 (절대 경로), 기본 인수, **모델 이름 (선택)**을 채웁니다.
  4. 테스트 탭에서 확인합니다. 테스트 없이 저장해도 됩니다.
  5. 저장합니다. 프로필 줄의 스위치로 켜고 끕니다.

실행 파일은 절대 경로로 적어야 합니다. 별칭(alias)이나 함수 이름은 쓸 수 없습니다. 실행 전 명령은 Windows에서는 잠겨 있어 쓸 수 없습니다. 에이전트 버전 확인은 처음 5초, 다시 시도에서 8초를 기다립니다. 끝나지 않으면 문제 해결을 보세요.
