편집

편집 화면에서 워크플로를 만들고 고칩니다. 가운데에 노드가 이어진 그래프가 있고, 오른쪽 옆판에서 고른 노드의 설정이나 워크플로 자체의 설정을 정합니다. 그래프 대신 워크플로 파일의 글을 직접 고칠 수도 있습니다.

편집은 두 길로 엽니다. 목록에서 새 워크플로를 누르면 새 워크플로가, 줄의 편집이나 저장된 워크플로 화면의 편집을 누르면 그 워크플로가 열립니다.

예시 데이터로 찍은 화면입니다.

화면의 위쪽

섹션 제목: “화면의 위쪽”
  • 목록: 목록으로 돌아갑니다. 저장하지 않은 변경이 있으면 먼저 묻습니다.
  • 제목: 워크플로 이름입니다. 이름이 비어 있으면 「새 워크플로」입니다.
  • v3: 저장된 버전입니다. 새 워크플로는 첫 저장 뒤에 나타납니다.
  • 「저장하지 않은 변경 있음」: 고친 것이 남아 있다는 표시입니다.
  • 저장: 지금 글을 저장합니다. 저장하는 동안과 쓰기가 막힌 상태에서는 눌리지 않고, 화면 전체가 읽기만 됩니다.
  • 그래프 · 텍스트: 그림으로 고칠지 글로 고칠지 고릅니다. 이름은 「보기」 묶음입니다.

새 워크플로는 바탕 글로 열립니다. 이름은 issue-to-comment이고, Jira 시작 조건의 Trigger 노드 assigned 하나와 Claude Code가 일하는 Agent 노드 work 하나가 이어져 있으며, 실행 시간 한도는 2시간입니다. 연결과 프로젝트 이름은 예시이니 내 것으로 고릅니다. 연결이 설정에 없으면 옆판에 「연결 … 이(가) 없습니다.」가 나옵니다.

노드를 더하려면

섹션 제목: “노드를 더하려면”
  1. 그래프 왼쪽 위의 + 단추(이름은 「노드 추가 열기」, 열려 있으면 「노드 추가 닫기」)를 누릅니다. 새 워크플로에서는 처음부터 열려 있습니다.
  2. 목록에서 더할 노드를 고릅니다.
  3. 그래프 위로 끌어다 놓거나, 눌러서(Enter나 Space도 됩니다) 보이는 자리의 빈 곳에 놓습니다.
묶음 줄
Trigger 직접 실행 · Jira · GitHub
Agent Claude Code · Codex · OpenCode
  • Trigger는 워크플로에 하나만 둘 수 있습니다. 이미 있으면 Trigger 줄이 흐려지고, 마우스를 올리면 「트리거는 워크플로에 하나만 둘 수 있어 추가하지 않았습니다. 이미 있는 트리거 … 을(를) 고치거나 삭제한 뒤 추가하세요.」라고 나옵니다.
  • Jira나 GitHub 줄로 더한 Trigger는 「나에게 배정됨」 이벤트로 시작합니다. 설정에 그 종류의 연결이 하나뿐이면 그 연결이 저절로 들어가고, 없거나 여럿이면 옆판에서 고릅니다.
  • OpenCode 줄로 더한 Agent는 터미널에서 명령으로 일하는 모양으로 시작합니다. 명령 칸이 프롬프트 칸을 대신합니다.
  • 노드가 하나도 없으면 「왼쪽 위 노드 추가 버튼을 눌러 노드를 끌어 놓거나 눌러서 더하세요.」가 나옵니다.

노드를 더하거나 지우면 「… 노드를 더했습니다.」 · 「… 노드를 삭제했습니다.」처럼 화면 낭독기에 알려 줍니다.

노드를 잇고 끊고 지우려면

섹션 제목: “노드를 잇고 끊고 지우려면”

워크플로는 앞에서 뒤로만 흐릅니다. 선은 “이 노드가 끝나면 저 노드가 시작한다”는 뜻입니다.

  1. 노드 카드 가장자리의 연결점(카드마다 여러 개 있습니다)을 끌어 다른 노드의 연결점에 놓습니다.
  2. 끊으려면 노드 메뉴(카드의 ⋯, 마우스 오른쪽 단추, 또는 노드에서 Shift+F10)를 엽니다. 연결 끊기에서 끊을 선(from → to)을 고릅니다.
  3. 메뉴에서 다음 노드로 잇기를 고르고 이을 노드 이름을 눌러도 이어집니다.
  4. 지우려면 메뉴의 노드 삭제를 고르거나, 노드를 고른 채 Delete나 Backspace를 누릅니다.

이을 수 없는 경우에는 이유가 그래프 위에 나옵니다. 이유 닫기로 닫습니다.

이유 뜻
자기 자신에게 잇기 다른 노드에 이어 달라고 안내합니다
Trigger로 들어오는 선 Trigger는 앞 노드를 기다리지 않으므로 받지 않습니다
순환 이미 반대 방향으로 이어져 있어, 이으면 맴돌게 됩니다
이미 있는 선 같은 연결이 이미 있습니다

메뉴 항목은 이을 노드가 없으면 「이을 다른 노드가 없습니다.」, 끊을 선이 없으면 「이 노드에 이어진 연결이 없습니다.」라는 이유와 함께 흐려집니다.

카드 아래에 저장할 때 걸린 문제가 한 줄 보이고 외 2개처럼 개수가 붙습니다. 자세한 것은 저장하려면에 있습니다.

끝 표시는 Lyra가 마지막 노드들 뒤에 알아서 그립니다. 고르거나 옮기거나 잇거나 지울 수 없습니다.

그래프를 정리하려면

섹션 제목: “그래프를 정리하려면”
  • 노드는 끌어서, 또는 노드를 고르고 Alt+화살표로 옮깁니다. 노드에서 화살표 키는 다음 노드로 가고, Enter는 노드를 고릅니다.
  • 그래프 왼쪽 아래의 도구로 축소, 확대, 그래프 전체 보기를 하고, 왼쪽 → 오른쪽 · 위 → 아래로 방향을 바꿉니다. 방향은 워크플로마다 이 컴퓨터가 기억합니다.
  • 같은 도구 줄 끝의 자동 배치(다이어그램 모양 단추)를 누르면 지금 방향에 맞춰 노드를 다시 늘어놓습니다. 노드가 없으면 눌리지 않습니다.
  • 노드 위치와 연결선 위치는 저장할 때 파일에 함께 들어갑니다.

워크플로 자체를 설정하려면

섹션 제목: “워크플로 자체를 설정하려면”

노드를 고르지 않으면 옆판이 워크플로 자체의 설정을 보여 줍니다. 머리에 이름과 「워크플로 · 노드 3개 · Lyra 엔진이 이끎」이 나옵니다.

  1. 이름: 목록과 lyra workflow 명령이 쓰는 이름입니다.
  2. 설명: 적고 싶은 설명입니다.
  3. 실행 시간 한도: 숫자를 적고 단위(초 · 분 · 시간)를 고릅니다. 이 시간을 넘기면 실행을 멈춥니다. 비워 두면 「한도 없음」입니다. 파일에 1h30m처럼 이어 쓴 값이 있으면 글 칸으로 보입니다.
  4. 노드를 펼치면 노드 이름이 한 줄씩 나옵니다. 누르면 그 노드가 골라지므로, 마우스 없이 노드를 고를 때 씁니다.

「실행을 이끄는 쪽」은 파일에 lyra가 아닌 값이 적혀 있을 때만 읽기로 보입니다.

Trigger 노드를 설정하려면

섹션 제목: “Trigger 노드를 설정하려면”

그래프에서 Trigger 노드를 고릅니다. 머리에 「트리거 · 실행이 시작되는 곳」이 나옵니다.

  1. 시작 방법에서 직접 실행, Jira, GitHub 중 하나를 고릅니다.
  2. Jira나 GitHub이면 연결에서 설정에 만들어 둔 연결을 고릅니다. 연결 이름 옆에 서비스 주소의 호스트가 붙습니다.
    • 그 종류의 연결이 아직 없으면 「… 연결이 아직 없습니다. 설정 → 이슈 연결에서 추가하세요.」가 나옵니다.
    • 파일에 적힌 연결이 설정에 없으면 「(설정에 없음)」으로 보이고 「연결 … 이(가) 없습니다.」가 나옵니다.
  3. 이벤트는 「나에게 배정됨」입니다. 지금은 이것 하나입니다.
  4. 시작 방법이 Jira이면 Jira 프로젝트 키, GitHub이면 **저장소 (owner/name)**를 적습니다. 그 프로젝트나 저장소의 이슈만 실행을 시작합니다.
  5. Lyra 프로젝트에서 실행의 작업 자리가 만들어질 프로젝트를 고릅니다. 목록을 읽지 못하면 「Lyra 프로젝트 목록을 읽지 못했습니다.」와 프로젝트 목록 다시 읽기가 나옵니다. 파일에 적힌 프로젝트가 Lyra에 없으면 「프로젝트 … 이(가) Lyra에 없습니다. Projects 에서 추가하거나 다른 프로젝트를 고르세요.」가 나옵니다.
  6. 다음 노드에 넘기는 이름을 펼치면 뒤 노드의 프롬프트에 넣을 수 있는 이름(key, title, body, url 같은 것)이 나옵니다.

연결 목록을 읽지 못하면 편집 화면 위쪽에 이유가 나오고 연결 목록 다시 읽기가 있습니다.

Agent 노드를 설정하려면

섹션 제목: “Agent 노드를 설정하려면”

그래프에서 Agent 노드를 고릅니다. 머리에 「에이전트 · 앞 노드 다음」이 나옵니다.

  1. 노드 이름: 다른 노드가 이 노드의 결과를 가리킬 때 씁니다. 영문자로 시작하고 영문자, 숫자, _, -만 쓸 수 있습니다. 쓸 수 없거나 다른 노드가 이미 쓰는 이름이면 이유가 나오고 바뀌지 않습니다. 이름 옆 **⋯**의 이름 바꾸기는 이 칸으로 가고, 노드 삭제는 노드를 지웁니다.
  2. 에이전트에서 Claude Code, Codex, OpenCode 중 하나를 고릅니다.
  3. 프롬프트에 에이전트에게 시킬 일을 적습니다. ${를 치면 앞 노드가 넘기는 이름이 목록으로 나오고, 위아래 화살표로 고르고 Enter로 넣습니다. 앞 노드와 이어져 있지 않으면 「앞 노드와 연결하면 그 노드가 넘기는 이름을 ${ 로 넣을 수 있습니다」라고 나옵니다.
    • 터미널로 일하는 단계(OpenCode)는 프롬프트 대신 명령이 나옵니다. 실행할 프로그램과 인자 1, 인자 2 …를 적고, 인자 추가와 인자별 삭제 단추를 씁니다. 이 명령은 작업 자리의 터미널에서 실행되고, 0으로 끝나면 통과합니다.
    • 명령이 opencode run <메시지> 모양이 아니면 다른 에이전트로 바꿀 수 없다는 안내가 나옵니다.
  4. 산출물은 단계가 남기는 결과물입니다. 산출물 추가를 누르고 이름과 종류(텍스트 또는 파일)를 정합니다. 파일이면 파일 경로도 적습니다. 줄 끝의 단추로 지웁니다.
  5. 모델 · 추론을 펼치면 모델과 추론을 고릅니다. 비워 두면 「에이전트 기본값」입니다. 목록은 그 에이전트에서 읽어 오고, 읽는 동안 「목록을 읽는 중…」이 보입니다. 읽지 못하거나 읽을 수 없는 이유(트리거에 프로젝트가 없음, 프로젝트에 작업 자리가 없음, 에이전트 프로필이 없음·여럿임·쓸 수 없음)가 있으면 이유가 나오고 다시 읽기와 직접 적는 칸이 남습니다.
  6. 작업 자리를 펼치면 새로 만들기(이 이름의 작업 자리와 브랜치를 만듭니다. 이름에도 ${ 이름을 쓸 수 있습니다)와 앞 노드의 작업 자리(앞 노드가 만든 자리에서 이어서 일합니다) 중에서 고릅니다. 앞에 에이전트 노드가 없으면 뒤쪽은 고를 수 없습니다.
  7. 통과 · 승인 · 실패하면을 펼쳐 단계의 규칙을 정합니다.
칸 고르는 것
통과 조건 「이슈에 댓글을 남겨야 통과」. 켜면 댓글이 없는 시도는 실패합니다
승인 「시작하기 전에 사람이 승인」. 켜면 단계가 시작되기 전에 받은 요청에 승인 요청이 옵니다
거절하면 승인을 켰을 때만 보입니다. 실행을 멈춤, 이 단계를 다시, 앞 노드로 돌려보내기. 돌려보내는 횟수에는 한도가 없습니다
실패하면 멈춤(실행도 실패), 다시 시도(같은 세션이 열려 있으면 거기에 새 작업으로), 돌려보내기(앞 노드가 실패 내용을 넘겨받아 다시 시작)
다시 시도 횟수 최대 4번까지
돌려보낼 노드, 최대 횟수 앞 에이전트 노드 중에서 고르고, 최대 10번까지

접힌 줄의 오른쪽에는 지금 정한 것이 한 줄로 보입니다. 예를 들면 「이슈 댓글 필요 · 승인 필요 · 거절하면 멈춤 · 실패하면 2번 다시 시도」입니다. 저장할 때 문제가 걸린 칸은 접힌 줄이 저절로 펼쳐집니다.

칸 이름 옆의 **?**에 마우스를 올리거나 키보드로 가면 설명이 나옵니다. Esc로 닫습니다.

Trigger와 Agent가 아닌 노드가 파일에 있으면 「… 노드의 설정은 텍스트 편집기로 전환해 고칩니다.」라고 나옵니다. 그래프에서 새로 더할 수 있는 노드는 둘뿐입니다.

글로 고치려면

섹션 제목: “글로 고치려면”
  1. 위쪽의 텍스트를 누릅니다.
  2. 「저장할 워크플로 파일」 칸에서 글을 고칩니다. 「저장하면 이 글이 저장됩니다. 그래프로 돌아가면 이 글을 다시 읽어 그립니다.」라고 안내합니다.
  3. 그림으로 돌아가려면 그래프를 누릅니다. 글을 다시 읽어 그립니다.

글을 그림으로 읽지 못하면 텍스트 보기에 남고 그 이유와 줄 번호가 나옵니다. 읽지 못하는 경우는 YAML 모양이 맞지 않을 때, & · * · ! 같은 앵커·별칭·태그를 쓸 때, nodes가 목록이 아닐 때, 노드에 id가 없거나 겹칠 때입니다. 고친 뒤 그래프를 다시 누릅니다. 이때 옆판에는 「파일을 그래프로 읽지 못해 노드 설정을 보여 줄 수 없습니다. …」가 나옵니다. 처음 열 때부터 그림으로 읽을 수 없는 파일은 텍스트 보기로 열립니다.

저장하려면

섹션 제목: “저장하려면”
  1. 저장을 누릅니다.
  2. 성공하면 위쪽에 「저장했습니다.」가 나오고 버전이 오릅니다. 저장할 때 걸린 경고는 위쪽 목록에 남습니다.

저장하지 못하면 「저장하지 못했습니다 · 문제 3개」처럼 개수가 나옵니다. 노드에 해당하는 문제는 그 노드 카드 아래와 옆판 맨 위에 보이고, 노드에 속하지 않는 문제는 화면 위쪽 목록에 모입니다. 고치고 다시 저장합니다. 저장하지 못해도 고친 내용은 그대로 남습니다.

실행은 시작할 때의 버전으로 돕니다. 나중에 저장한 버전은 앞서 시작한 실행에 영향을 주지 않습니다.

저장하지 않고 나가려면

섹션 제목: “저장하지 않고 나가려면”

저장하지 않은 변경이 있을 때 목록을 누르거나 다른 곳(예: 받은 요청 카드의 실행 열기)으로 가려 하면 「저장하지 않은 변경이 있습니다」 창이 먼저 열립니다. 무엇이 바뀌었는지가 줄로 나옵니다. 「추가한 노드: …」, 「삭제한 노드: …」, 「설정을 바꾼 노드: …」, 「워크플로 이름 · 설명 · 한도」, 「노드 배치와 연결선 위치」, 「워크플로 파일의 글」입니다.

  1. 저장하고 나가기: 저장한 뒤 나갑니다. 저장하지 못하면 「저장하지 못해 나가지 않았습니다. 이 화면에 표시된 문제를 고친 뒤 다시 저장하세요.」가 나오고 창과 고친 내용이 그대로 남습니다.
  2. 버리고 나가기: 고친 것을 버립니다.
  3. 남기: 창을 닫고 계속 고칩니다.

이 화면의 말

섹션 제목: “이 화면의 말”

용어에서 각 말의 뜻을 봅니다.

말 이 화면에서
노드 그래프 속 상자 하나, 곧 한 단계
Trigger · Agent 노드의 두 종류
산출물 Agent 노드가 남기는 결과물
작업 자리 노드가 일하는 폴더. 새로 만들기 또는 앞 노드의 작업 자리
돌려보내기 실패나 거절 때 앞 노드를 다시 시작하게 함
그래프 · 텍스트 같은 파일을 보는 두 가지 모양

잘 안 될 때

섹션 제목: “잘 안 될 때”
보이는 것 할 일
저장이 눌리지 않음 저장하는 중이거나 쓰기가 막힌 상태입니다. 잠시 기다립니다
「저장하지 못했습니다 · 문제 N개」 문제가 걸린 노드를 골라 접힌 줄을 펼치고 고칩니다
노드를 이을 수 없음 그래프 위에 나온 이유를 읽습니다. 순환이나 Trigger로 들어오는 선은 만들 수 없습니다
그래프를 눌러도 텍스트 보기에 남음 텍스트 위에 나온 줄 번호의 글을 고칩니다
모델 목록이 비어 있음 이유 문장을 읽고 다시 읽기를 누르거나 모델을 직접 적습니다
「연결 … 이(가) 없습니다.」 설정에서 연결을 만들거나 다른 연결을 고릅니다
