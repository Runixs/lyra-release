원격

원격은 SSH로 연결하는 서버(에이전트와 터미널을 돌리는 다른 컴퓨터)의 목록입니다. 서버를 더하고, 연결하고, 상태를 읽고, 고치고, 지웁니다. 서버가 무엇이고 어디서 무엇이 도는지는 서버와 Host에 있습니다.

이 컴퓨터는 이 목록에 나오지 않습니다. 이 컴퓨터의 에이전트는 에이전트에서 봅니다.

이 페이지의 그림은 예시 데이터로 찍었습니다.

서버를 추가하려면

섹션 제목: “서버를 추가하려면”
  1. 설정 왼쪽 목차의 연결 묶음에서 원격을 엽니다.
  2. 맨 위의 서버 추가를 누릅니다. 서버 추가 창이 열립니다.
  3. 등록 방법을 고릅니다. 직접 입력은 주소를 직접 적고, SSH 설정에서는 이 컴퓨터의 ~/.ssh/config에 있는 Host 별칭을 고릅니다.
  4. 직접 입력이면 이름, 주소, 포트, 사용자를 적습니다. 포트는 비워 둘 수 있고, 적으면 숫자만 넣을 수 있습니다.
  5. 저장을 누릅니다. 그만두려면 취소를 누릅니다.
  • 창에는 「로그인은 연결할 때 서버가 받는 방법을 따릅니다. 키가 있으면 키로 들어가고, 서버가 비밀번호를 물으면 그때 한 번 묻습니다.」라고 적혀 있습니다. 추가할 때는 비밀번호 칸이 없습니다.
  • SSH 설정에서를 고르면 별칭이 라디오 목록으로 나오고, 하나를 고르면 이름 칸이 비어 있거나 직전에 고른 별칭 이름일 때 그 별칭으로 채워집니다. 칸에는 이름만 남습니다. 별칭을 고르기 전에는 저장이 눌리지 않습니다.
  • 별칭을 읽는 중이면 「이 컴퓨터의 SSH 설정에서 Host 별칭을 읽고 있습니다.」가 나옵니다. 하나도 없으면 「SSH 설정 파일에서 Host 별칭을 찾지 못했습니다. 직접 입력으로 서버 주소를 입력하세요.」, 읽지 못했으면 읽지 못했다는 안내가 나오고, 두 경우 모두 직접 입력 단추로 돌아갈 수 있습니다. 일부만 읽었으면 목록이 불완전하다는 안내가 나옵니다.
  • 칸이 비어 있으면 「비워 둘 수 없습니다.」, 너무 길면 「너무 깁니다.」, 포트에 숫자가 아닌 것이 있으면 「숫자만 넣을 수 있습니다.」가 칸 아래에 나옵니다. 주소 형식이나 이름이 겹치는 것은 저장할 때 알려 줍니다.

처음 추가하는 순서는 설치에도 있습니다.

연결 상태를 읽으려면

섹션 제목: “연결 상태를 읽으려면”

서버 줄 오른쪽의 작은 표시가 지금 상태입니다.

표시 뜻 할 일
연결됨 지금 이어져 있습니다 없음
연결 끊김 연결이 끊겼거나 연결에 실패했습니다 연결을 누르거나 아래 연결이 안 될 때를 봅니다
확인 전 아직 연결 상태를 확인하지 못했습니다 연결을 누릅니다. 표시를 누르면 「서버 “이름”의 연결 상태를 확인하지 못했습니다. [연결]을 눌러 다시 연결하세요.」가 나옵니다
연결 중 연결을 누르고 답을 기다리는 중입니다 기다립니다

확인 전은 실패가 아닙니다. 아직 모른다는 뜻입니다. 시각을 알면 「확인 전 · 14:05부터」처럼 언제부터인지 함께 나옵니다.

서버 줄에는 이름 옆에 SSH 표시가 있고, 이름 아래에 서버의 사실이 나옵니다.

항목 뜻
SSH 호스트 · 포트 · 사용자 등록한 값
OS 서버의 운영체제. 연결되어 있을 때만 알려 줍니다
lyra-daemon · 프로토콜 서버에서 도는 lyra-daemon(Lyra의 실행 엔진)의 버전과 프로토콜. 연결되어 있을 때만 알려 줍니다
마지막 확인 위 값을 마지막으로 확인한 시각
앱 버전(…)과 다름 서버의 lyra-daemon 버전이 이 앱의 버전과 다르거나 버전이 거부되었습니다
설치된 에이전트 연결되어 있을 때 서버에서 찾은 에이전트와 버전

모르는 값은 확인 전으로 적힙니다.

연결하고 끊으려면

섹션 제목: “연결하고 끊으려면”
  1. 연결이 안 된 서버 줄 오른쪽의 연결을 누릅니다.
  2. 연결을 끊으려면 서버 줄의 이름을 눌러 줄을 펼치고 연결 끊기를 누릅니다.
  3. 서버의 에이전트를 다시 찾으려면 연결된 서버 줄의 지금 확인을 누릅니다. 결과가 설치된 에이전트에 나옵니다.

연결에 실패하면 줄이 저절로 펼쳐지고 이유가 줄 아래에 나옵니다. 서버를 잘못 눌렀다면 이름을 다시 눌러 줄을 접습니다.

연결하는 동안 보이는 단계

섹션 제목: “연결하는 동안 보이는 단계”

연결을 시작하면 서버 줄 아래에 지금 하는 단계가 한 줄로 나옵니다. 「SSH 로그인 · 진행 중」처럼 단계 이름과 상태가 함께 보입니다. 단계는 Lyra가 알려 준 것만 나오고, 시간이 지났다고 저절로 넘어가지 않습니다.

단계 하는 일
SSH 로그인 서버에 닿아 로그인합니다. 비밀번호나 일회용 코드를 물으면 이 단계에서 멈춰 기다립니다
배포판 시작 WSL 서버의 배포판을 켭니다
버전 확인 서버의 운영체제와 서버에 있는 lyra-daemon을 읽습니다. 서버에 이 버전이 없고 이 컴퓨터에도 그 서버용 패키지가 없으면, 이 단계에서 서버 패키지를 내려받습니다(최대 2분 기다림)
SSH로 보내기 lyra-daemon 파일을 서버로 보냅니다
설치 보낸 파일을 제자리에 놓습니다
이전 버전 lyra-daemon 멈춤 이 버전이 자리를 이으려고 서버의 이전 버전 lyra-daemon을 멈춥니다. 멈출 것이 없었으면 이 단계는 나오지 않습니다
lyra-daemon 시작 서버에서 lyra-daemon을 켜고 준비될 때까지 기다립니다
연결 열기 서버의 lyra-daemon과 명령 길을 엽니다

실제로 거친 단계만 나옵니다. 이미 설치되어 있어 건너뛴 단계는 완료로 적히지 않습니다. 연결되면 줄은 사라집니다.

  • 멈추면 「SSH 로그인 단계에서 멈췄습니다.」처럼 멈춘 단계가 나오고, 그 아래에 멈춘 이유와 다음 할 일이 나옵니다. 연결을 눌러 실패한 줄 아래에 이미 이유가 있으면 같은 이유를 두 번 적지 않습니다.
  • 연결하는 도중에 연결을 닫으면 「… 단계에서 연결을 닫았습니다.」가 나옵니다.
  • 이전 버전 lyra-daemon을 멈췄는지 확인하지 못했으면 「…: 결과를 확인하지 못했습니다. 이전 버전 lyra-daemon이 아직 실행 중일 수 있습니다.」가 나옵니다. 이 단계는 끝난 것으로 치지 않습니다.
  • 버전 확인에서 서버에 이전 버전 lyra-daemon이 돌고 있으면 「이전 버전 lyra-daemon 실행 중 → … 버전으로 바꿉니다. 그 세션은 …에서 이어집니다.」가, 필요한 버전이 서버에 없으면 「이 서버에 lyra-daemon … 버전이 없어 설치합니다.」가 나옵니다. 묻지 않고 알려 주기만 합니다.
  • 지난 단계 보기를 누르면 이미 지난 단계가 「버전 확인 · 완료」처럼 한 줄씩 나옵니다. 상태는 완료, 진행 중, 멈춤, 닫음, 확인 못 함 가운데 하나입니다. 연결된 뒤에도 이 목록은 남고, 다시 연결을 시작하면 닫힌 채 새 단계로 바뀝니다.
  • 화면 낭독기에는 서버 이름과 함께 단계가 바뀔 때, 멈출 때, 연결되었을 때 한 번씩 읽어 줍니다.

명령줄에서는 lyra server connect가 상태 줄마다 지금 단계를 적습니다. 자세한 것은 서버: server에 있습니다.

펼친 줄에서 보는 것

섹션 제목: “펼친 줄에서 보는 것”

서버 이름을 누르면 줄이 펼쳐집니다.

항목 뜻
주소 주소:포트
사용자 로그인 사용자
인증 로그인 방식. 아래 로그인 방식을 봅니다
연결 연결 상태

펼친 줄 위쪽에는 서버의 lyra-daemon 기록이 있습니다.

보이는 것 뜻
적어 둔 지금 버전 · 이전 버전 서버에 기록해 둔 버전. 없으면 적어 둔 버전 없음, 이전 버전 없음
마지막 확인 기록을 마지막으로 확인한 시각. 모르면 마지막 확인 모름
새 버전에 맞춤 서버를 새 버전에 맞췄습니다
맞추는 중 — 아직 맞춘 것이 아닙니다 진행 중입니다. 단계: 서버 확인처럼 지금 단계가 함께 나옵니다
업데이트 때 이어져 있지 않았습니다 — 맞췄다는 뜻이 아닙니다 업데이트 때 서버가 연결되어 있지 않았습니다
맞추지 못함 — 확인되지 않았습니다 맞추지 못했습니다. 이유가 함께 나옵니다
버전 거부 · 앱 프로토콜 … · lyra-daemon 프로토콜 … 앱과 서버의 프로토콜이 맞지 않습니다
다른 lyra-daemon 버전 서버에 있는 다른 버전. 줄마다 버전, 일이 남음·일은 없고 연결이 남음·비어 있음·끝남·확인하지 못함 가운데 하나, 일과 연결의 수가 나옵니다

앱이 새 버전이 되면 서버의 lyra-daemon이 앱보다 낮은 버전일 때 Lyra가 새 버전으로 바꿉니다. 그 서버에 살아 있는 일이 있으면 일이 없어질 때까지 옛 버전을 둡니다. 직접 올릴 필요는 없습니다.

맞추지 못했거나 버전 거부가 나오면 서버를 연결한 채로 지금 확인을 누르고, 그래도 같으면 문제 해결을 봅니다.

로그인 방식

섹션 제목: “로그인 방식”

인증 칸에서 이 서버가 어떻게 로그인하는지 알 수 있습니다.

보이는 것 뜻
SSH 키 키 파일로 로그인합니다
SSH 키 (암호) 암호가 걸린 키로 로그인합니다
인증 에이전트 이 컴퓨터의 SSH 인증 에이전트를 씁니다

비밀번호로 연결할 때

섹션 제목: “비밀번호로 연결할 때”

서버가 비밀번호를 물으면 연결할 비밀번호 입력 창이 뜹니다. 입력하고 연결을 누릅니다.

  • 창에는 「이 컴퓨터의 lyra-daemon 메모리에만 두고 디스크에 쓰지 않습니다. lyra-daemon이 종료되면 지웁니다.」라고 적혀 있습니다.
  • 비밀번호는 64 KiB 이하여야 합니다. 비어 있거나 넘으면 「비밀번호를 입력해 주세요. 입력은 64 KiB 이하여야 합니다.」가 나옵니다.
  • 일회용 코드(OTP)를 묻는 서버는 일회용 코드(OTP) 입력 창이 뜹니다. 코드는 저장하지 않으며 256바이트 이하여야 합니다.
  • 비밀번호가 틀려서 실패하면 펼친 줄에 비밀번호 고치기가 나옵니다. 누르면 수정 창이 열리고 비밀번호 칸에 커서가 갑니다.
  • 같은 비밀번호로 다시 해 보려면 현재 비밀번호로 다시 확인을 누릅니다.

비밀번호 없이 로그인하려면

섹션 제목: “비밀번호 없이 로그인하려면”

비밀번호로 연결한 서버는 내 SSH 키를 서버에 올려 두면 다음부터 비밀번호를 묻지 않습니다.

  1. 서버에 처음 비밀번호로 연결하면 「비밀번호 없이 …에 로그인할까요?」 창이 한 번 뜹니다. 이 서버에 등록을 누릅니다.
  2. 나중에 하려면 나중에를 누릅니다. 창을 닫아도 나중에와 같습니다. 이 서버에는 다시 묻지 않습니다.
  3. 나중에 등록하려면 연결된 서버의 펼친 줄에서 SSH 키 등록을 누릅니다.

창에는 이렇게 적혀 있습니다.

  • Lyra가 서버의 ~/.ssh/authorized_keys에 내 SSH 키의 공개 줄을 추가합니다. 회사 게이트웨이 서버는 포함되지 않습니다.
  • SSH 키가 없으면 먼저 이 컴퓨터에 ~/.ssh/id_ed25519를 암호 문구 없이 만듭니다.
  • 암호 문구가 없는 키 파일은 만료되지 않는 비밀번호와 같습니다. 그 파일을 읽을 수 있는 사람이나 그 파일이 든 백업은 이 키를 믿는 모든 서버에 로그인할 수 있습니다.
  • Lyra는 추가만 합니다. 서버를 Lyra에서 지우거나 키를 바꿔도 서버의 줄은 남습니다. 접근을 막으려면 서버에서 그 줄을 지웁니다.

등록 결과는 알림으로 잠깐 나옵니다. 등록했으면 「SSH 키(…)를 이 서버에 추가했습니다 — 다음부터는 비밀번호가 필요 없습니다.」, 이미 있으면 「SSH 키(…)가 이미 이 서버에 있습니다 — 다음부터는 비밀번호가 필요 없습니다.」, 하지 않았으면 「SSH 키를 등록하지 않았습니다: 이유」입니다. 키에 암호 문구가 있으면 이유가 「키에 암호 문구가 있습니다. ssh-add 로 올린 뒤 다시 등록하세요」이니, 안내대로 ssh-add로 키를 올린 뒤 다시 등록합니다.

서버가 키를 받아들이지 않았거나 키를 추가하는 중에 연결이 끊겼을 때는 알림이 아니라 서버 줄에 경고가 남고 다시 연결 단추가 붙습니다. 이때 Lyra는 서버의 줄을 지우지 않습니다.

별칭으로 추가한 서버

섹션 제목: “별칭으로 추가한 서버”

~/.ssh/config의 별칭으로 추가한 서버 중에는 이 컴퓨터의 ssh 프로그램으로 연결하는 것이 있습니다(ProxyJump, ProxyCommand, 보안 키 등을 쓰는 경우). 이 서버는 키로 로그인하고, 수정 창의 비밀번호 칸이 잠기며 「…서버는 이 컴퓨터의 ssh 프로그램으로 연결합니다…」라는 안내가 나옵니다. 터미널에서 ssh-copy-id <별칭> 명령으로 키를 서버에 등록합니다.

사용자 이름이 회사 게이트웨이 로그인 모양인 별칭은 다릅니다. 이 컴퓨터의 ssh 프로그램이 필요하지 않고(ProxyJump 같은 설정과 보안 키를 쓰지 않을 때) 로그인 방식을 따로 고르지 않으면 비밀번호로 등록됩니다. 연결을 누르면 주소로 추가한 서버처럼 사내 ID 비밀번호와 일회용 코드를 묻는 창이 뜹니다. 로그인 방식을 직접 고르면 그대로 따릅니다. 앱을 열 때의 자동 연결은 창을 열지 않고 멈추고, 아래 알림의 연결 단추로 다시 이을 수 있습니다.

연결이 안 될 때

섹션 제목: “연결이 안 될 때”

서버 줄이 연결 끊김이면 다음을 합니다.

  1. 서버 이름을 눌러 줄을 펼치고 줄 아래에 나온 이유를 읽습니다.
  2. 연결을 눌러 다시 연결합니다.
  3. 계속 안 되면 서버 로그인이 안 되거나 시간이 초과될 때를 봅니다.

앱을 열 때 Lyra가 서버에 저절로 다시 연결하려다 멈추면 알림이 올라옵니다.

알림 제목 알림 내용 단추
자동 연결 중단 암호 또는 키 암호 필요, 저장한 설정 바뀜, 저장한 인증 정보 접근 필요 가운데 하나, 또는 실패 이유 연결
서버 신원 확인 필요 서버 신원 확인 필요 서버 설정 열기

서버 설정 열기를 누르면 이 원격 화면이 열립니다. 서버를 바꾸거나 다시 설치한 일이 없는데 서버 신원 확인 필요가 나왔다면 연결하지 마세요.

연결이 끊겨 있는 동안 서버의 터미널이 어떻게 보이는지는 서버와 Host에 있습니다.

서버를 고치려면

섹션 제목: “서버를 고치려면”
  1. 서버 이름을 눌러 줄을 펼칩니다.
  2. 수정을 누릅니다. 서버 고치기 창이 열립니다.
  3. 이름, 주소, 포트, 사용자, 비밀번호를 고치고 저장을 누릅니다.
  • 비밀번호 칸을 비워 두면 지금 비밀을 그대로 둡니다.
  • 별칭으로 추가한 서버는 이름과 비밀번호만 고칠 수 있습니다.
  • 비밀번호를 적어 저장하면 이 컴퓨터의 lyra-daemon 메모리에만 둡니다.

서버를 삭제하려면

섹션 제목: “서버를 삭제하려면”
  1. 서버 줄을 펼치고 삭제를 누릅니다.
  2. 서버 삭제 창의 「서버 “이름”을(를) 목록에서 삭제할까요?」를 읽고 삭제를 누릅니다. 그만두려면 취소를 누릅니다.

서버를 목록에서 지우고, 이 컴퓨터에 저장된 그 서버의 로그인 정보도 지웁니다. 사내 ID 비밀번호로 로그인하는 서버라면 그 사내 ID 의 저장된 비밀번호를 지우므로, 같은 사내 ID 를 쓰는 다른 서버도 다음 연결 때 비밀번호를 다시 묻습니다. 서버의 세션과 파일은 그대로 둡니다. 서버에 올린 SSH 키 줄도 그대로이니, 접근을 막으려면 서버에서 직접 지웁니다.
