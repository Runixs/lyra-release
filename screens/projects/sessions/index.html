Session 열기

Session은 에이전트와 하는 한 번의 작업입니다. 이 페이지는 프로젝트 화면에서 Session을 여는 길을 다룹니다. Session은 작업 자리(Worktree 또는 Workspace) 안에서 돕니다. 먼저 작업 자리를 고르거나 만들어 둡니다.

이 페이지의 그림은 예시 데이터로 찍었습니다.

새 Session 시작하기

섹션 제목: “새 Session 시작하기”

세 곳에서 같은 목록으로 시작합니다.

방법 1. Worktree 줄 메뉴

  1. 탐색기에서 작업 자리 줄의 … 버튼을 누르거나 줄을 오른쪽 클릭합니다.
  2. 메뉴 위쪽의 에이전트 이름을 누릅니다. 목록은 그 호스트에서 켜 둔 프로필입니다. 에이전트 이름은 Claude Code, Codex, OpenCode처럼 영어로 보입니다.
  3. 가운데 무대에 새 Session 탭이 열리고, 탐색기의 그 작업 자리 아래에 Session 줄이 생깁니다.

방법 2. 탭 줄의 새 탭 버튼

  1. 가운데 무대의 탭 줄 끝에 있는 +(새 탭)를 누릅니다.
  2. 같은 목록에서 에이전트를 고릅니다.

방법 3. 아직 아무 탭이 없는 작업 자리

  1. 탐색기에서 작업 자리를 고릅니다.
  2. 무대에 작업 자리 이름과 브랜치, 터미널 버튼, 프로필이름 열기 버튼이 나옵니다. 에이전트 버튼을 누릅니다.

목록에 에이전트가 하나도 없으면 “이 호스트에 켠 프로필이 없습니다”라고 나옵니다. **에이전트 관리…**를 누르면 설정으로 갑니다. 프로필 만드는 방법은 설정 페이지에 있습니다.

모델을 고르고 시작하려면 에이전트 이름 오른쪽의 하위 메뉴를 엽니다. Default는 모델을 지정하지 않고 시작합니다. 하위 메뉴는 Claude Code와 Codex 같이 모델을 고를 수 있는 에이전트에만 있습니다. 에이전트 이름 옆에 “OpenCode 버전을 읽지 못했습니다. 시작할 때 다시 확인합니다”가 보일 수 있습니다. 시작은 되고, 그때 버전을 읽어 2.0.0보다 낮으면 세션을 열지 않습니다. OpenCode가 2.0.0보다 낮으면 「…OpenCode … 버전이 Lyra에 필요한 버전(2.0.0 이상)보다 낮아 세션을 열지 않았습니다. 그 컴퓨터에서 opencode upgrade를 실행한 뒤 다시 시작하세요.」가 탭 줄 위에 나옵니다. 그 컴퓨터의 터미널에서 opencode upgrade를 실행한 뒤 다시 시작합니다.

Session을 열 수 없으면 실패 이유가 탭 줄 위에 나오고, 에이전트에 로그인해야 하는 경우에는 터미널 열기 버튼이 함께 나옵니다.

열어 둔 Session 다시 열기

섹션 제목: “열어 둔 Session 다시 열기”
  1. 탐색기에서 Session 줄을 누르거나, 줄 메뉴의 열기를 고릅니다. 줄을 고르고 Enter를 눌러도 됩니다.
  2. 그 Session의 탭이 무대에서 앞으로 옵니다. 닫은 탭이면 새로 열립니다.

Worktree 줄 아래에 Session이 많으면 줄을 접을 수 있습니다. 탐색기의 세션 줄을 요약으로 바꾸면 줄 대신 “세션 3개”처럼 개수와 “확인 필요 1”이 보입니다. 탐색기를 보세요.

줄과 탭의 상태 읽기

섹션 제목: “줄과 탭의 상태 읽기”

Session 줄과 탭에 상태가 점이나 이름으로 보입니다. 이름은 화면 그대로 영어입니다. 열림 상태와 작업 상태의 뜻은 오케스트레이션에, 모든 말의 뜻은 용어에 있습니다.

상태 뜻
Idle 에이전트를 띄웠지만 아직 첫 턴(에이전트가 한 번 일하는 단위)이 없습니다
Working 일하는 중입니다
Waiting 사람의 답을 기다립니다
Done 한 턴을 끝냈습니다
Failed 오류가 났습니다
Interrupted 사람이 멈춘 턴입니다. 실패가 아닙니다

Waiting이나 Failed인 Session 줄은 줄 전체에 색이 입혀집니다. Claude Code의 Session 줄 끝에는 프롬프트 캐시 남은 시간이 작게 나옵니다. 줄에 마우스를 올리면 설명이 나옵니다. 끝나면 다음 메시지는 전체 맥락을 캐시 없이 다시 보냅니다. Claude Code가 캐시를 기록한 뒤에만 나오고, 그 프로필의 캐시 타이머를 에이전트에서 끄면 이미 열린 Session 줄에서도 사라집니다. Codex와 OpenCode의 줄에는 타이머가 없습니다.

정보 보기

섹션 제목: “정보 보기”
  1. Session 줄 메뉴에서 세션 정보를 고르거나, 탭 메뉴에서 세션 정보를 고릅니다. 작은 창이 열립니다.
  2. 오른쪽 옆판의 세션 정보 탭에서도 지금 앞에 있는 Session의 정보를 볼 수 있습니다. 오른쪽 옆판을 보세요.

이름 바꾸기와 ID 복사

섹션 제목: “이름 바꾸기와 ID 복사”
  • 이름 바꾸기: Session 줄 메뉴나 탭 메뉴의 이름 바꾸기를 고릅니다. macOS는 Enter, Windows는 F2로도 됩니다. 탭 이름 입력 창에서 저장을 누릅니다.
  • ID 복사: Session 줄 메뉴의 세션 ID 복사를 고릅니다.

에이전트가 끝나면

섹션 제목: “에이전트가 끝나면”

에이전트가 끝나면 같은 탭이 그 Session의 작업 폴더에서 연 셸로 바뀝니다. 에이전트가 마지막에 찍은 내용은 셸의 첫 화면 바로 위 스크롤 기록에 그대로 남아, 위로 올려 읽을 수 있습니다. 셸은 첫 화면이 나온 뒤부터 글자를 받습니다. 그 전에 친 글자는 셸에 닿지 않습니다.

  • 셸을 여는 길이 엔진을 다시 시작하는 때나 서버와의 연결이 끊긴 틈에 막히면 Lyra가 몇 번 다시 시도합니다. 그래도 열지 못하면 탭이 끝난 채로 남고 「에이전트가 끝난 뒤 이 탭에서 셸을 열지 못했습니다. 아래 원인을 확인한 뒤 탭을 닫고 새 터미널을 여세요. 탭이 닫히지 않으면 문제 기록을 남겨 주세요.」와 원인이 나옵니다.
  • **세션 닫기…**로 Session을 끝내면 이렇게 열린 셸도 함께 닫힙니다.
  • 메모리가 모자라 끝난 경우와, 다른 Session이 시작한 Worker의 Session은 셸로 바뀌지 않고 끝난 채로 남습니다.

Session 닫기

섹션 제목: “Session 닫기”

탭을 닫는 것과 Session을 끝내는 것은 다릅니다.

  1. 탭의 닫기 버튼이나 탭 메뉴의 보기 닫기는 화면만 닫습니다. 에이전트는 계속 돕니다.
  2. Session을 끝내려면 Session 줄 메뉴나 탭 메뉴에서 **세션 닫기…**를 고릅니다.
  3. “이 세션을 멈출까요?” 창이 “에이전트가 하던 일을 멈춥니다. 탭을 닫는 것으로는 멈추지 않고, 이것으로만 멈춥니다.“라고 알려 줍니다. 멈추기를 누릅니다. 취소로 돌아갈 수 있습니다.
  4. 이 질문을 다시 보지 않으려면 다시 묻지 않기를 켭니다.

같은 탭 그룹의 다른 탭을 한꺼번에 닫는 다른 탭 닫기에서도 Session이 들어 있으면 “그중 세션 N개는 실행을 끝냅니다. 계속할까요?“라고 묻습니다. 서버에 연결할 수 없는 Session은 **세션 닫기…**가 이유와 함께 막힙니다. 터미널에 묶여 있는 Session의 줄 메뉴에는 **세션 닫기…**가 없습니다. 그 터미널의 셸을 끝내야 합니다.

이 화면의 말

섹션 제목: “이 화면의 말”

용어 페이지에서 Session, Idle, Working, Waiting, Done, Failed, Interrupted, 프롬프트 캐시를 설명합니다.

잘 안 될 때

섹션 제목: “잘 안 될 때”
보이는 것 하면 되는 것
“세션은 열렸지만 첫 메시지를 보내지 못했습니다” 탭 줄 위의 알림을 읽고 Session을 열어 확인합니다
“시작 또는 전송 여부를 확인하지 못했습니다” 같은 일을 두 번 하지 않도록 다시 보내지 않았습니다. Session 탭을 열어 확인합니다
“이 세션의 터미널과 대화 보기는 아직 이어지지 않았습니다” Session과 작업은 그대로 돌고 있습니다. 잠시 뒤 다시 엽니다
“에이전트의 터미널을 열 수 없습니다. 그 터미널은 이미 닫혔습니다.” 세션 목록에서 다시 열거나 새 터미널을 엽니다
「에이전트가 끝난 뒤 이 탭에서 셸을 열지 못했습니다…」 나온 원인을 읽고 탭을 닫은 뒤 새 터미널을 엽니다. 탭이 안 닫히면 문제 기록을 남깁니다
Session 목록이 읽는 중에서 멈춥니다 목록 아래 다시 읽기를 누릅니다
