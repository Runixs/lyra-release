Worktree와 Workspace

Project 안에서 일을 나누는 자리를 작업 자리라고 부릅니다. Git 프로젝트의 작업 자리는 Worktree(같은 저장소에서 브랜치마다 따로 쓰는 작업 폴더), Git이 아닌 프로젝트의 작업 자리는 Workspace입니다. Worktree는 서로의 파일을 덮어쓰지 않으므로 에이전트 둘이 각자의 브랜치에서 일할 수 있습니다. Workspace는 폴더 하나를 여럿이 함께 씁니다.

이 페이지의 그림은 예시 데이터로 찍었습니다.

Worktree 만들기

섹션 제목: “Worktree 만들기”

Git 프로젝트에서 새 브랜치와 새 작업 폴더를 함께 만듭니다.

  1. Project 줄의 + 버튼을 누릅니다. 줄 메뉴의 Worktree 추가를 골라도 되고, 단축키 ⌘N(Windows는 Ctrl+N)도 됩니다. 단축키로 열면 창 맨 위에 Project 칸이 있어 어느 프로젝트에 만들지 고릅니다.
  2. Create Worktree 창이 열립니다. 프로젝트가 여러 컴퓨터에 있으면 호스트 칸에서 어느 위치에 만들지 고릅니다. 한 곳뿐이면 이 칸은 나오지 않습니다.
  3. 이름을 적습니다. 이 이름이 새 브랜치 이름이 되고, 폴더 이름은 거기서 정해집니다. 폴더 이름이 다르면 예상 폴더: 이름 줄에 미리 보입니다.
  4. 시작 브랜치에서 어느 브랜치에서 갈라질지 고릅니다. 처음에는 원격의 기본 브랜치(origin/main, origin/master, main, master 순)가 골라지고, 목록에서 기본, 지금 브랜치, 원격 브랜치가 표시됩니다. 브랜치 찾기 칸으로 찾을 수 있습니다.
  5. 에이전트에서 만든 뒤 바로 열 Session의 프로필을 고르거나 세션 없이를 고릅니다. 목록에 없으면 **에이전트 관리…**로 설정에 갑니다. 켠 프로필이 없으면 「이 호스트에 켠 프로필이 없습니다. 세션 없이 만들 수 있습니다.」가, 그 컴퓨터에서 에이전트를 하나도 찾지 못했으면 「…에서 설치된 에이전트(Claude Code, Codex, OpenCode)를 찾지 못했습니다. 세션 없이 만들 수 있습니다.」와 설정 › 에이전트에서 보기가 나옵니다.
  6. 생성을 누릅니다.

만드는 동안 Worktree 줄 아래에 진행이 나옵니다. 끝나면 줄이 보통 모습이 되고, 에이전트를 골랐다면 그 Session이 열립니다.

이름이 막히는 경우는 다음과 같습니다.

보이는 것 뜻
“이름을 입력하세요.” 이름이 비었습니다
“이미 있는 브랜치입니다.” 같은 이름의 로컬 브랜치가 있습니다
“Git 브랜치 이름으로 쓸 수 없습니다.” 공백, .., ~^:?*[ 같은 문자나 앞뒤의 /, . 등이 들어 있습니다
“폴더 이름은 64자 이하여야 하며 CON, NUL 같은 Windows 예약 이름은 쓸 수 없습니다. 이름을 바꾸세요.” 이름에서 만든 폴더 이름을 쓸 수 없습니다

같은 이름의 작업 자리가 이미 있으면 이름 아래에 “이 이름의 작업 자리가 이미 있습니다.” 같은 안내와 열기 버튼이 나옵니다. 준비에 실패한 채 남은 것이면 다시 준비도 있습니다. 다른 브랜치로 있는 이름이면 다른 이름을 적어야 합니다.

Setup Script

섹션 제목: “Setup Script”

프로젝트 폴더의 .lyra/config.yaml에 Setup Script(작업 자리를 만든 뒤 돌릴 준비 명령)가 있으면 Lyra가 만들기 전에 읽습니다.

  1. 처음 보는 명령이거나 전에 허락한 명령과 달라졌으면 Setup Script 실행 창이 열립니다. 명령 목록이 번호와 함께 보입니다.
  2. 실행을 누르면 준비 명령을 돌리고 작업 자리를 만듭니다. 실행하지 않기를 누르면 명령 없이 만듭니다. 창을 닫으면 아무것도 하지 않습니다.
  3. 이 프로젝트 항상 신뢰를 켜고 실행을 누르면, 이 프로젝트의 모든 호스트에서 이후 바뀌는 명령도 다시 묻지 않습니다. 끄는 방법은 프로젝트 설정에 있습니다.

파일을 읽을 수 없거나 형식이 틀리면 “Setup Script가 올바르지 않습니다” 또는 “읽지 못했습니다”라고 나오고 다시 읽기와 이번에는 Setup Script 실행 안 함이 있습니다. 후자를 켜면 명령 없이 만들 수 있습니다.

준비가 실패했을 때

섹션 제목: “준비가 실패했을 때”
  • 만들다 실패하면 줄 아래에 “이름 만들지 못함” 또는 “이름 준비를 다 마치지 못함”과 이유가 나옵니다. “만들다 만 자리는 그대로 남습니다.“라고 알려 줍니다.
  • 다시 시도는 이어서 합니다. 닫기는 알림만 닫습니다.
  • 준비 명령만 실패했다면 “작업 자리 준비 명령이 실패했습니다” 알림에 다시 실행과 로그 보기가 있습니다. 작업 자리는 그대로 남아 있습니다.
  • 줄 오른쪽에 준비 실패, 준비 일부만 됨 표시가 붙습니다. 이미 있던 작업 자리를 등록해 Lyra가 준비 명령을 돌리지 않은 것은 정보 카드에 준비 명령 안 돌림이라고 나옵니다.

Workspace 만들기

섹션 제목: “Workspace 만들기”

Git이 아닌 프로젝트에서 작업 자리를 하나 더 만듭니다.

  1. Project 줄의 + 버튼을 누릅니다. 메뉴 이름은 Workspace 추가이고 창 제목은 Create Workspace입니다.
  2. 이름을 적습니다. 64글자 이하여야 하고 보이지 않는 제어 문자는 쓸 수 없습니다.
  3. 창은 “이 Workspace들은 같은 폴더를 공유하므로 에이전트들이 같은 파일을 수정할 수 있습니다.“라고 알려 줍니다. 새 폴더는 만들지 않습니다.
  4. 에이전트를 고르고 생성을 누릅니다.

이름 바꾸기

섹션 제목: “이름 바꾸기”
  1. 작업 자리 줄 메뉴에서 이름 바꾸기를 고릅니다. macOS는 줄을 고르고 Enter, Windows는 F2로도 됩니다.
  2. 줄 아래에 표시 이름 입력이 열립니다. 이름을 적고 저장을 누릅니다. Esc나 취소는 그대로 둡니다.

다른 곳에서 먼저 바뀌었으면 저장이 거절되고 이유가 나옵니다. 다시 읽기를 누른 뒤 다시 저장합니다. 표시 이름은 Lyra 안의 이름입니다. 폴더 이름과 브랜치 이름은 바뀌지 않습니다.

삭제하기

섹션 제목: “삭제하기”
  1. 작업 자리 줄 메뉴에서 Worktree 삭제…(Git이 아니면 Workspace 삭제…)를 고릅니다.
  2. 작업 자리 삭제 창에 이름, 종류, 호스트, 경로가 보입니다.
    • Lyra가 만든 Worktree이면 “이 경로의 워크트리를 삭제하고 브랜치 이름의 안전 삭제를 시도합니다. 수정된 파일이 있으면 아무것도 멈추지 않고 거절합니다.“라고 나옵니다.
    • 그 밖의 작업 자리(원래 폴더, Git이 아닌 폴더, 이미 있던 워크트리)는 “Lyra 목록에서만 삭제합니다. 디스크의 폴더와 브랜치는 그대로입니다.“라고 나옵니다.
  3. 도는 Session과 터미널이 있으면 “삭제하기 전에 아래 세션과 터미널을 이 순서로 멈춥니다. 하나라도 멈춘 것을 확인하지 못하면 거기서 그치고 폴더를 그대로 둡니다.“라는 목록이 나옵니다.
  4. 매번 묻지 않으려면 다시 묻지 않기를 켭니다. 켜 두면 다음부터 이 창이 열리지 않고 바로 삭제합니다. 서버 연결이 끊겼거나 서버가 목록에서 빠진 경우와 병합하지 않은 커밋이 있는 브랜치는 그래도 묻습니다.
  5. 작업 자리 삭제를 누릅니다.

병합하지 않은 커밋이 있을 때

섹션 제목: “병합하지 않은 커밋이 있을 때”

브랜치에 아직 병합하지 않은 커밋이 있으면 창에 “브랜치 이름에는 기준 브랜치에 없는 커밋이 N개 있습니다.“가 나오고 버튼이 둘로 바뀝니다.

버튼 하는 일
브랜치는 남기고 삭제 폴더만 지우고 브랜치와 커밋을 남깁니다
브랜치도 삭제 브랜치도 지웁니다. 그 커밋을 잃을 수 있습니다

남긴 브랜치는 프로젝트 설정의 남긴 브랜치에 모입니다. 병합했는지 읽지 못했다면 “삭제하면 브랜치는 안전 삭제만 시도하고, 커밋이 있으면 남깁니다.“라고 알려 줍니다.

강제 삭제

섹션 제목: “강제 삭제”

Lyra가 만든 Worktree에 저장하지 않은 변경이 있으면 보통 삭제는 거절됩니다. 이때 강제 삭제 창이 열립니다.

  1. “일반 삭제를 거절했습니다: 이유”를 읽습니다.
  2. “커밋하지 않은 변경과 새 파일을 버리고 호스트의 폴더(경로)를 삭제할까요?“를 읽고 강제 삭제를 누릅니다. 취소하려면 닫습니다.

변경을 버리므로 되돌릴 수 없습니다. 변경이 있는지 확인하지 못한 경우와 Lyra가 만들지 않은 작업 자리에는 강제 삭제가 나오지 않습니다.

삭제가 끝나지 않았을 때

섹션 제목: “삭제가 끝나지 않았을 때”

삭제하다 멈추면 줄 끝에 경고 표시가 남습니다. 예를 들면 “삭제 미완료 · 일부 파일이 남음”, “삭제하지 못함 · 이름 사용 중”입니다. 표시를 누르면 설명과 버튼이 든 작은 창이 열리고, 줄 메뉴 맨 아래에도 같은 항목이 있습니다.

메뉴 하는 일
다시 삭제 같은 삭제를 다시 시도합니다
목록에서만 삭제 폴더는 두고 Lyra 기록만 지웁니다
결과를 모르는 기록만 삭제 결과를 알 수 없는 기록만 지웁니다. 한 번 더 확인을 묻고, 서버의 폴더와 브랜치는 건드리지 않습니다

서버 연결이 끊겨서 막힌 경우에는 설정의 원격에서 서버를 다시 연결하거나 다시 추가한 뒤 삭제하라고 안내합니다.

이 화면의 말

섹션 제목: “이 화면의 말”

용어 페이지에서 Worktree, Workspace, primary, Setup Script, 준비 상태(만드는 중, 준비 중, 준비됨, 준비 실패, 준비 일부만 됨)를 설명합니다.

잘 안 될 때

섹션 제목: “잘 안 될 때”
보이는 것 하면 되는 것
생성이 눌리지 않습니다 이름 아래 안내를 읽고 고칩니다. 시작 브랜치를 고르지 않았거나 호스트를 고르지 않았을 수도 있습니다
“브랜치 목록을 읽지 못함” 호스트에 연결되어 있는지 봅니다. 창을 닫고 다시 엽니다
“호스트 목록을 읽지 못했습니다” 같은 줄의 다시 읽기를 누릅니다
