Bundled skills

번들 스킬은 에이전트가 lyra 명령줄을 알맞게 쓰도록 Lyra가 설치해 주는 설명서 묶음입니다. 스킬의 글은 lyra 실행 파일 안에 컴파일되어 들어 있어 네트워크도 lyra-daemon도 필요 없습니다. 화면에서 하는 일은 에이전트 스킬에 있고, 이 쪽은 설치되는 길과 한계를 설명합니다. 스킬 글을 고치는 규칙은 코드가 아닌 팀 규칙이므로 여기서 다루지 않습니다.

무엇이 설치되나

섹션 제목: “무엇이 설치되나”

세 스킬이 skills/bundled/ 아래에 있고, 컴파일할 때 include_str!로 실행 파일에 들어갑니다.

스킬 다루는 것
lyra-cli Projects, Workspaces, Session, 터미널, 파일과 Git, Inbox, Hosts, 서버와 자격증명, Profile, 연결과 이슈, 워크플로, 시리얼
lyra-orchestration Worker 시작, Lead에게 맡기기, Task, 메시지, 갈림길, 기다림과 복구
lyra-workflow 워크플로 실행의 한 단계로 일하기, 실행을 지켜보기, 워크플로 쓰기

스킬 하나는 폴더 하나입니다. SKILL.md(에이전트가 처음 읽는 짧은 안내), guide.md(전체 안내), references/ 아래의 참고 글들입니다. 에이전트에게 설치되는 것은 SKILL.md뿐입니다. 전체 안내와 참고 글은 설치되지 않고, 에이전트가 lyra skills get <name>으로 실행 파일에게서 직접 읽습니다. 그래서 안내를 읽는 쪽은 늘 그 명령을 돌릴 실행 파일과 같은 버전입니다.

어디에 꽂히나

섹션 제목: “어디에 꽂히나”
입구 하는 일
lyra skills list 번들된 스킬을 한 줄 설명과 함께 보입니다. --installed를 주면 설치된 상태를 보입니다.
lyra skills status list --installed의 다른 이름입니다.
lyra skills get <name> 안내를 인쇄합니다. --references는 참고 글 목록, --reference <name>은 하나, --full은 전체입니다.
lyra skills install [<name>] 스킬 하나를 설치합니다. --from <zip>은 검증된 로컬 릴리스 묶음(zip)을 설치합니다.
lyra skills update 공유 폴더를 한 번 맞춥니다. --repair-links는 빠진 스킬을 설치하고 감지된 에이전트의 링크를 고칩니다. --skill <name>으로 하나만 고릅니다.
앱의 app.skills.list · install · update · reveal main이 작업 스레드에서 위 명령을 돌려 답을 화면에 줍니다. 닫을 때는 일하는 중인 스레드에 취소를 보내고 끝나기를 기다립니다.
엔진의 skills.inventory · skills.apply 연결된 서버의 같은 일. 이미 연결된 서버에만 보냅니다.

--agent는 claude, codex, opencode 중 하나입니다. 주지 않으면 <account home> 아래에서 에이전트 설정 폴더가 있는 것을 찾아 하나일 때만 고릅니다. 없거나 여럿이면 찾은 이름을 말하며 skill-agent-required로 멈추고, 설정 폴더를 읽지 못하면 skill-agent-unreadable입니다. 목록에 없는 이름은 skill-agent-unsupported입니다.

설치가 하는 일

섹션 제목: “설치가 하는 일”
  1. 미리 확인. 에이전트 쪽 자리의 상태를 읽어 충돌을 먼저 가려냅니다. 읽기만 하고 아무것도 바꾸지 않습니다.
  2. 공유 폴더에 쓰기. <account home>/.agents/skills/<name>/SKILL.md를 씁니다. 새 폴더를 만들고, 임시 파일에 쓴 뒤 이름을 바꾸어 넣습니다. 쓰다 실패하면 이번 설치가 만든 것만 치우고, 치우지 못하면 남은 폴더를 leftover로 알립니다. 이미 같은 내용이 있으면 아무것도 쓰지 않고 “already installed”로 답합니다.
  3. 에이전트에 잇기. Claude는 <claude config>/skills/<name>(기본은 <account home>/.claude/skills, 환경에서 지정된 설정 폴더가 있으면 그 아래)을 공유 폴더의 같은 이름 폴더로 가는 링크로 만듭니다. Codex와 OpenCode는 공유 폴더를 직접 읽으므로 링크를 만들지 않습니다. Claude 쪽에 Lyra가 표시한 옛 복사본이 있으면 --replace-old-copy가 있을 때만 휴지통으로 옮기고 링크로 바꿉니다. 서버에서는 --host-trash로 그 서버 안의 휴지통을 씁니다.

SKILL.md에는 스킬 이름과 두 표시가 들어갑니다. <!-- lyra-skill: <name> <제품 버전> -->은 설치한 lyra의 버전이고 새로 설치할지 가리는 기준입니다. <!-- lyra-skills-version: <스킬 글 버전> -->은 스킬 글의 버전이라, 앱 버전이 같아도 글만 바뀐 것을 따로 알아냅니다. 스킬 글 버전은 skills/bundled/VERSION의 값입니다. 파일 하나는 1 MiB까지만 읽습니다(skill-file-too-large).

--from으로 설치하면 전체 설치 기록 .lyra-install.json이 같이 쓰입니다(매니페스트 이름과 SHA-256, zip의 SHA-256, 출처 commit, 제품 버전). 이 기록이 있으면 읽는 쪽은 그 기록을 먼저 보고, 있는데 읽을 수 없거나 기록된 파일이 깨졌으면 번들된 사본으로 돌아가지 않고 거절합니다.

할 수 있는 것과 없는 것

섹션 제목: “할 수 있는 것과 없는 것”
  • 위 세 스킬만 설치합니다. 밖에서 스킬을 더하는 입구는 없습니다. --from은 Lyra가 낸 검증된 릴리스 묶음만 받습니다(skill-release-invalid).
  • 설치하는 에이전트는 Claude, Codex, OpenCode입니다. 그 밖의 에이전트 폴더는 건드리지 않습니다.
  • 링크가 있는 자리(폴더나 SKILL.md)에는 쓰지 않습니다(skill-install-linked).

어떻게 거절하나

섹션 제목: “어떻게 거절하나”

설치 자리가 이상하면 아무것도 바꾸지 않고, 문장이 그 경로와 이유를 말합니다.

이유(reason) 뜻 사람이 할 일
not-a-folder 스킬 폴더 자리에 폴더가 아닌 것이 있음 바꾸지 않았음
incomplete 폴더는 있는데 완전한 SKILL.md가 없음(설치가 끊겼을 수 있음) 그 폴더를 치우고 다시 실행
other-version 같은 Lyra 스킬의 다른 버전이 있음 lyra skills list --installed로 보고 lyra skills update
different 다른 사람의 같은 이름 스킬이 있음 바꾸지 않았음

이 이유는 skill-install-conflict(설치)나 skill-update-conflict(맞추기)의 한 칸으로 나옵니다. 그 밖의 코드는 skill-not-found, skill-reference-not-found, skill-home-unavailable(설정 폴더가 절대 경로가 아님 등), skill-root-invalid, skill-path-invalid, skill-install-protected, skill-install-failed, skill-update-failed, skill-publication-failed, skill-link-failed, skill-trash-failed, skill-writer-busy, skill-writer-unavailable, skill-guide-unreadable입니다. 전체 목록은 Errors가 정합니다.

서버에서의 skills.inventory와 skills.apply는 이미 연결된 서버에만 갑니다. 연결이 없으면 몰래 연결하지 않고 host.server-unbound 등으로 거절합니다. 읽기는 일반 호출로 가지만 바꾸는 쪽은 그 연결에 묶여 연결이 바뀌면 다시 보내지 않습니다. 답을 읽을 수 없으면 skills.answer-unreadable이고, 퇴역한 에이전트 행은 답에 있어도 보이지 않습니다.

설명서와 맞추는 검사

섹션 제목: “설명서와 맞추는 검사”

오케스트레이션 설명서는 이 사이트의 사용 안내 묶음입니다. 설명서의 말 하나하나가 기대는 근거(스킬 글의 제목, lyra 명령, 사유 코드, docs/_index/ids.tsv의 ID)는 Lyra 저장소의 crates/lyra-cli/src/nouns/skills/book/(이 사이트는 고정한 출시에서 복사해 옵니다)의 claims.json과 experiments.json에 지문(fingerprint)과 함께 적혀 있고, stamp.json은 설명서가 맞춰진 스킬 버전과 태그, lyra 버전, 명령 수, 확인한 날을 담습니다. 설명서의 첫 페이지가 이 stamp.json을 읽어 보여 줍니다.

페이지와 데이터는 MDX 주석 표지로 이어집니다.

표지 놓는 곳
book: 뒤에 항목 id를 적은 MDX 주석 claims.json의 항목마다 한 번, 그 항목을 말하는 제목 · 문단 · 목록 · 표 · 단계 목록 바로 위의 줄
book-experiment: 뒤에 실험 id를 적은 MDX 주석 experiments.json의 실험마다 한 번, 해 볼 실험 페이지에서 그 실험 바로 위의 줄
examples[].text 그 항목의 표지 아래 ```sh 블록 안에 한 줄 그대로

lyra-cli의 book_sync 검사는 LYRA_BOOK_DOCS가 Docs 저장소(Runixs/lyra-docs)의 체크아웃을 가리킬 때 그 src/content/docs/**/*.mdx에서 이 표지와 예시를 확인하고(가리키지 않으면 데이터만 확인합니다), 근거의 지문을 다시 계산해 바뀐 근거에 기대는 항목을 표지가 있는 페이지와 줄로 알려 줍니다. 다시 읽은 항목만 LYRA_BOOK_STAMP=<ids|stamp|all>로 다시 찍는 순서와, 어느 항목도 인용하지 않은 오케스트레이션 명령을 알려 주는 힌트는 그대로입니다. 순서는 팀 규칙이라 여기서 다루지 않습니다.

아직 없는 것

섹션 제목: “아직 없는 것”

실행 파일에 넣은 skills/bundled/는 1단계의 임시 대체물입니다. 전체 설치 기록이 없는 모든 자리에서 쓰이고, 승격된 릴리스(skills/vendor/)와 같은 글을 담아야 합니다. 설치된 글만 읽는 2단계는 코드에 없습니다. 이 내용은 구현 현황에 올립니다.
