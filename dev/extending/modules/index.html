Modules

모듈은 에이전트에게 붙여 줄 수 있는 이름 붙은 내용 묶음입니다. 지시문 한 파일, 스킬 폴더, MCP 서버 정의 중 하나이고, 출처와 내용 지문을 함께 보관합니다. 이 쪽은 그 보관소(lyra-module)가 받아들이는 것과 거절하는 것을 설명합니다.

이 빌드에서 모듈은 쓰이지 않습니다. 보관소 라이브러리는 있지만 어떤 프로세스도 그것을 만들어 쓰지 않고, 모듈을 다루는 연산도 없고, 화면과 명령줄에도 모듈 입구가 없습니다. 아래 그림의 왼쪽 위 칸에서 나가는 선은 있으나 오른쪽에서 막힙니다.

무엇을 더할 수 있나

섹션 제목: “무엇을 더할 수 있나”

보관소가 받는 모듈은 세 종류입니다(ModuleKind, 철자는 prompt · skills · mcp).

종류 내용 비고
prompt 지시문 파일 하나
skills 뿌리에 SKILL.md가 있는 폴더 이 폴더가 Lyra가 싣는 번들 스킬과 같은 것은 아닙니다.
mcp MCP 서버 정의 프로세스 수명은 이 보관소의 몫이 아닙니다.

목록에 없는 철자는 MODULE_KIND_UNSUPPORTED로 거절합니다.

모듈 하나는 ModuleId, 이름(ModuleName), 종류, 출처 서술자, 내용 목록과 내용 지문, 등록 시각을 가집니다. 이름은 한 보관소 안에서 겹치지 못하고(MODULE_NAME_CONFLICT), 출처 서술자는 출처 종류, 위치, 선택 revision, 선택 자격증명 참조로 이루어집니다. 자격증명 값 자체는 담지 못합니다. 그 값이 든 것으로 보이는 출처는 MODULE_SOURCE_SECRET_FORBIDDEN입니다.

어디에 꽂히나

섹션 제목: “어디에 꽂히나”
  • 아바타: lyra-avatar가 모듈 ID를 가리킵니다. 명시한 참조는 prompt와 mcp, 스킬 참조는 skills 종류만 받습니다.
  • 발사 계획: lyra-harness가 발사를 계획할 때 read_module로 모듈을 읽습니다. 종류가 허용 목록에 없거나, 읽은 모듈의 ID가 다르거나, 지문이 비어 있으면 HA002_UNSUPPORTED_FIELD로 거절합니다.
  • 설치: 모듈은 실행 위치마다 따로 설치됩니다. 위치를 찾는 일과 놓는 일은 보관소가 직접 하지 않고, 부르는 쪽이 넣어 주는 두 틀(LocationAdapter · InstallAdapter)이 합니다. 보관소는 파일도 망도 자식 프로세스도 열지 않습니다.

설치 기록의 상태(InstallState)는 Requested → Installing → Installed, 지우는 쪽은 Removing이고, 실패하거나 결과를 모르면 Failed입니다. 내용을 다시 재어 본 결과(IntegrityState)는 Unverified · Verified · Drifted이고, 달라진 파일은 Added · Removed · Changed로 나옵니다. 실패한 전이는 놓은 것의 정도를 NothingPlaced · SomePlaced · Unknown으로 기록합니다.

할 수 있는 것과 없는 것

섹션 제목: “할 수 있는 것과 없는 것”

내용은 이 한도 안에서만 받습니다.

한도 값
파일 수 512개 이하
한 파일 4 MiB 이하
합계 32 MiB 이하
경로 전체 1024바이트, 조각 255바이트, 깊이 16 이하

경로는 이런 것을 거절합니다(PathRule의 철자). empty, absolute, backslash, dot-or-empty-segment, not-nfc, control-character, forbidden-character(Windows 금지 문자 :*?"<>|), trailing-dot-or-space, windows-reserved-name, too-long, too-deep, link(심볼릭 링크 · 하드 링크), special-file, duplicate, case-collision, file-directory-conflict. 위반하면 MODULE_CONTENT_INVALID입니다. 운영체제가 스스로 만드는 파일(.DS_Store, Thumbs.db, ehthumbs.db, desktop.ini, ._로 시작하는 곁 파일)은 일반 파일일 때 지문에서 뺍니다.

모양과 버전

섹션 제목: “모양과 버전”
  • 지문: 파일마다 SHA-256을 둘 잽니다. 바이트 그대로의 지문(exact)과, 실행 파일이 아닌 글 파일은 줄 끝을 \n으로 맞춘 뒤의 지문(identity)입니다. 모듈의 내용 지문은 파일 목록의 경로, 실행 여부, 구분, 비교용 지문을 순서대로 늘어놓아 다시 SHA-256으로 묶은 값입니다.
  • 버전: 모듈이나 보관소에 version 필드는 없습니다. 같은 모듈인지는 내용 지문으로 가립니다. 지문이 다르면 MODULE_DIGEST_MISMATCH입니다.

어떻게 읽고 거절하나

섹션 제목: “어떻게 읽고 거절하나”
코드 언제
MODULE_SOURCE_INVALID 출처 서술자의 칸이 비었음
MODULE_INSTALL_CONFLICT 같은 위치에 진행 중인 설치가 있음
MODULE_INSTALL_FAILED 설치가 실패했거나 결과를 모름
MODULE_NOT_INSTALLED · MODULE_VERIFY_FAILED 끝나지 않은 설치 기록을 검증하려 함, 설치된 내용을 읽지 못해 검증하지 못함
MODULE_IN_USE · MODULE_HAS_INSTALLATIONS · MODULE_REMOVE_FAILED 전이 중이라 지울 수 없음, 설치 기록이 남아 지울 수 없음, 지우다 실패
MODULE_USAGE_CONFLICT · MODULE_NOT_FOUND 호출자가 본 revision이 현재와 다름, 모듈이나 사용 기록이 없음
EXECUTION_LOCATION_NOT_FOUND · REMOTE_INSTALL_UNAVAILABLE 실행 위치를 모름, 원격 설치 경계가 이 버전에 없음
REDACTION_REQUIRED 가릴 수 없는 원문이 출력 후보에 있었음. 이 빌드에서 이 오류를 내는 길은 없고, 코드 표를 닫아 두려고 있습니다.

실패 요약의 문자열 칸은 모두 고정 문구라서 환경 변수 값이나 자격증명, 명령줄, stderr를 담을 수 없습니다. 코드 전체는 Errors가 정합니다.

아직 없는 것

섹션 제목: “아직 없는 것”
  • 모듈을 등록 · 설치 · 지우는 연산이 없습니다. 연산 목록에 module.로 시작하는 이름이 없고, module.install을 부르면 모르는 연산입니다. 화면의 창 다리도 이 이름을 받지 않습니다.
  • 엔진이 ModuleRegistry를 만들어 쓰지 않습니다. 발사 계획은 모듈 읽기 대신 “모듈 없음”(NoModules)을 씁니다.
  • 아바타를 건 session.open은 거절됩니다.

이 목록은 구현 현황에 올립니다. 아바타는 아바타와 모듈이 다룹니다.
