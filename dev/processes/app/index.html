Lyra app

Lyra 앱은 Electron 프로그램 하나입니다. 안에 세 조각이 있습니다. 화면을 그리는 renderer, 화면에 다리를 놓는 preload, 창과 lyra-desktop-sidecar 자식을 맡는 main입니다. 기능을 직접 실행하는 조각은 없습니다. main은 기능 연산을 모두 sidecar에 넘기고, 답을 가공하지 않습니다.

어디서 도는가

섹션 제목: “어디서 도는가”
조각 소스 실행되는 곳
main apps/desktop/src/main/ Electron의 main 프로세스. 앱을 연 사람의 OS 계정으로 돕니다.
preload apps/desktop/src/preload/ 창마다 한 번, 화면보다 먼저 도는 격리된 스크립트입니다.
renderer apps/desktop/src/renderer/ 창 안의 웹 화면입니다. lyra-app://app/index.html에서 싣습니다.

앱 자료 폴더는 macOS에서 <account home>/Library/Application Support/Lyra, Windows에서 %LOCALAPPDATA%\Lyra입니다. 그 밖의 OS에서는 정하지 않고 비워 둡니다. 폴더를 정할 수 없으면 main은 로그를 쓰지 않고, 창이 뜨면 log.write-failed 알림으로 알립니다.

누가 언제 시작하고 끝내는가

섹션 제목: “누가 언제 시작하고 끝내는가”

사람이 앱을 열면 시작합니다. 같은 사용자 폴더에서 앱을 한 번 더 열면 두 번째 프로세스는 곧바로 끝나고, 처음 앱의 창이 앞으로 나옵니다. 잠금은 선택된 사용자 자료 폴더를 따라갑니다.

시작은 이 순서입니다.

  1. main이 lyra-app 주소 규칙, 메뉴, IPC 처리기를 올립니다.
  2. 창을 하나 만들고 lyra-app://app/index.html을 싣습니다.
  3. 창을 기다리지 않고 sidecar를 띄웁니다. macOS에서는 로그인 셸의 PATH를 먼저 읽어 sidecar가 물려받게 합니다.

끝내는 길은 하나입니다. 창이 모두 닫히면 app.quit()을 부릅니다. before-quit에서 main은 다음을 합니다.

  1. 감시 타이머와 알림 구독을 멈춥니다.
  2. 스킬 명령 일꾼을 마무리합니다.
  3. sidecar의 입력을 닫고 5초 기다립니다. 그때까지 끝나지 않으면 SIGKILL로 끊습니다.
  4. exited를 로그에 쓰고 app.exit(0)을 부릅니다.

앱이 끝나도 엔진은 끝나지 않습니다. 데스크톱 앱은 엔진을 띄우는 손님일 뿐이고, 창을 닫아도 엔진은 켜 둡니다.

누구와 말하는가

섹션 제목: “누구와 말하는가”

renderer가 할 수 있는 것

섹션 제목: “renderer가 할 수 있는 것”

renderer가 쓰는 길은 preload가 window.lyraBridge로 내주는 네 가지뿐입니다.

함수 하는 일
call(operation, input) 목록에 있는 연산 하나를 부릅니다. 답은 늘 { ok, result } 또는 { ok: false, error } 꼴입니다.
on(event, handler) 닫힌 목록의 사건을 받습니다. 목록: sidecar-state, link-state, update-progress, notice, window-command, view-zoom, data-changed, runtime-events, runtime-watchdog, runtime-watchdog-failed, notices, status-changed, folder-dropped, artifact-page, artifact-key
window(command, requestId) 창 명령 minimize, maximize, restore, close 중 하나를 청합니다.
diagnostic(row) 버전이 붙은 작업 영역 시간 기록 한 줄을 main 로그로 보냅니다. 연산을 요청하지는 않습니다.

떼어 낸 상태판 창은 lyraBoard라는 다른 손잡이를 받습니다. 앱 창이 스냅숏을 보내고, 상태판 창은 고른 Session 번호만 돌려줍니다.

구독하기 전에 온 사건은 버리지 않고 모아 둡니다. 모음의 상한은 256개이고, 넘으면 가장 오래된 것부터 버리면서 버린 수를 세어 bridge.events-dropped 알림으로 알립니다. sidecar-state는 마지막 값 하나만 새 구독자에게 줍니다.

renderer가 할 수 없는 것

섹션 제목: “renderer가 할 수 없는 것”
  • main 전용 연산(window.authorize, system.woke, app.local-rollback-context 등)을 부를 수 없습니다. 목록에 없는 이름은 preload가 한 번, main의 문지기가 한 번 더 bridge.not-allowed로 거절합니다.
  • 입력은 1,048,576바이트(1MB)까지입니다. 넘으면 bridge.input-too-large로 거절합니다. 직렬화할 수 없는 입력도 넘은 것으로 봅니다.
  • 요청은 앱 창의 main frame에서 온 것만 받습니다. 다른 frame이나 앱 주소 밖 문서에서 온 요청은 거절합니다.
  • Node, 파일 시스템, 임의의 OS 호출을 쓸 수 없습니다. 창은 sandbox와 contextIsolation이 켜져 있고 nodeIntegration이 꺼져 있습니다.
  • 네트워크를 쓸 수 없습니다. 화면 문서의 CSP는 connect-src 'none'이고, lyra-app 주소 밖으로 나가는 요청은 취소하고 기록합니다.
  • 새 창을 열거나 앱 주소 밖으로 이동할 수 없습니다. 권한 요청(카메라, 알림 등)은 모두 거부합니다.
  • 클립보드는 app.copy-text 연산으로만 씁니다. 창 세션이 Clipboard API를 거부하기 때문입니다.

main이 직접 처리하는 연산

섹션 제목: “main이 직접 처리하는 연산”

app.으로 시작하는 연산은 sidecar에 가지 않고 main이 처리합니다. 폴더 고르기(app.pick-folder), 폴더 열기(app.reveal-folder), 테마(app.set-theme), 바깥 링크 열기(app.open-external), 복사 · 붙여넣기(app.copy-text, app.paste, app.paste-image), 확대(app.zoom), 스킬(app.skills.*), 사용 중인 메모리(app.memory-snapshot), 웹 카드(app.artifact.*) 등입니다. 목록 전체는 연산 목록에 있습니다.

스킬 명령(app.skills.*)은 main이 일꾼 스레드에서 lyra 실행 파일을 짧게 띄워 처리합니다. 앱이 닫히는 중이면 skills.command-failed로 답합니다.

무엇을 지니는가

섹션 제목: “무엇을 지니는가”
  • 창 둘: 앱 창과, 사람이 떼어 낸 상태판 창입니다. 상태판 창은 앱 창이 닫히면 함께 닫힙니다.
  • sidecar 자식 하나와 그 상태입니다. 상태는 starting, ready, blocked, closing, gone, exited 중 하나입니다.
  • 요청 표와 사건 줄: 요청마다 번호를 붙여 sidecar에 보내고, 답이 올 때까지 쥡니다.
  • 복구 기록: 엔진이 끊겼을 때 이어 갈 정보를 Electron 사용자 자료 폴더 아래 recovery/에 둡니다.
  • main 로그: 앱 자료 폴더의 logs/main.log입니다. 연산은 이름, 번호, 결과 코드, 걸린 시간만 적고 입력은 적지 않습니다.

테마를 고르면 창이 처음 그려지기 전에 읽을 복사본을 Electron 사용자 자료 폴더의 appearance.json에 둡니다. 이 파일과 그 밖의 폴더는 폴더와 로그가 설명합니다.

멈추면 어떻게 되는가

섹션 제목: “멈추면 어떻게 되는가”
멈춘 것 일어나는 일
sidecar main은 스스로 다시 띄우지 않습니다. 상태가 gone이 되어 sidecar-state 사건으로 화면에 알리고, 사람이 다시 시작을 청할 때만 app.restart-sidecar로 다시 띄웁니다. 그 사이 들어온 요청은 bridge.sidecar-gone으로 곧바로 실패합니다.
sidecar가 준비 사건을 안 보냄 300초(5분) 뒤 sidecar-start-failed로 gone이 되고 SIGKILL로 끊습니다.
다시 시작하려는 sidecar가 안 끝남 입력을 닫고 5초 기다린 뒤 SIGKILL을 보냅니다. 그래도 끝났다는 것을 확인하지 못하면 blocked와 sidecar.stop-observation-failed로 답합니다.
창이 모두 닫힘 window-all-closed가 앱 전체를 끝냅니다. macOS도 같습니다.
엔진 엔진이 끊기는 일은 sidecar가 알립니다. 자동 재연결과 복구는 엔진 시작이 설명합니다.

업데이트와 main

섹션 제목: “업데이트와 main”

main은 Electron의 내장 자동 업데이트와 충돌 보고를 쓰지 않습니다. 소스에 crashReporter, autoUpdater, setFeedURL이 없는지 검사하는 pnpm verify:main-apis가 이를 지킵니다. 새 버전을 확인하고 받는 일은 엔진의 연산(update.apply 등)이 하고, main은 그 답에 앱 교체 단계가 들어 있을 때만 움직입니다.

그때 main은 이 순서로 넘깁니다. 사람이 update.apply를 청하면 sidecar가 답하고, 답에 앱 교체 단계(appInstall)가 들어 있으면 main이 이어받습니다. main은 먼저 그 서술이 읽히는지 확인하고, sidecar의 입력을 닫아 끝나기를 기다립니다. 그다음 앱 자료 폴더의 update/transitions/<id>/에 lyra-desktop-sidecar 사본을 놓고 --update-worker로 떼어 띄웁니다. 띄운 것을 확인하면 앱을 닫습니다. 앱이 20초 안에 끝나지 않으면 감시 타이머가 app.exit(0)을 부릅니다. sidecar가 닫히지 않거나 사본을 띄우지 못하면 sidecar를 다시 띄우고 app-update-not-started로 답합니다. 넘기는 동안에는 sidecar를 다시 띄우는 요청을 handoff.busy로 거절합니다. 전체 흐름은 업데이트 생애와 업데이트가 설명합니다.

설계와 다른 점

섹션 제목: “설계와 다른 점”

main 소스 머리말의 설명 몇 곳은 지금 코드와 다릅니다. 이 쪽은 코드를 따랐습니다. 차이는 구현 현황에 모았습니다.
