Sessions and Turns details

Sessions and Turns의 찾아보기 표입니다. 모든 연산은 Operations, 모든 오류 코드는 Errors가 정합니다. 여기에는 이 기능의 것만 한 줄씩 적습니다.

Session의 상태

섹션 제목: “Session의 상태”

기록의 상태 SessionState는 여섯 가지입니다. 화면의 Lyra 대화 목록은 이 이름을 그대로 보입니다.

상태 화면 뜻
Opening Opening 열기를 기록했고 실행 위치의 결과를 기다립니다.
FailedUnverified Failed · Unverified 발사 실패는 알지만 원래 프로세스가 멈췄는지, 인수됐는지 확인하지 못했습니다.
Active Active 실행 손잡이가 확인됐습니다.
Closing Closing 명시적 종료가 진행 중입니다.
Closed Closed 실행 위치의 종료가 확인됐습니다.
Failed Failed 원인(failureCode)과 함께 실패했습니다.

Working · Waiting · Idle · Done 같은 상태 낱말은 이 기록의 상태가 아니라 에이전트가 지금 무엇을 하는지를 말합니다. 그 길은 Status가 설명합니다.

이동

섹션 제목: “이동”

SessionCore::transition이 허용하는 이동은 아래뿐입니다. 그 밖의 이동은 오류입니다. 출발이 Closed 또는 Failed이면 late-session-command, 그 밖에는 invalid-session-transition입니다. 이동마다 revision이 1 오릅니다.

에서 로 갈 수 있는 곳
Opening Active · Failed · FailedUnverified
FailedUnverified Active · Failed · FailedUnverified · Closing
Active Closing · Failed
Closing Closed · Failed
Failed Closing
Closed 없음

닫기의 세 갈래

섹션 제목: “닫기의 세 갈래”

SessionCore::close_action이 증거로 고릅니다. 닿지 못함은 증거가 아닙니다.

갈래 고르는 때
Local 이미 Closed. 또는 Failed이면서 실행과 함께 끝난 실패(daemon-instance-mismatch · update-cut · wsl-work-stopped)이거나 실행 손잡이가 없음. 또는 기록된 주인 daemon이 지금 답하는 daemon과 다름
Reconcile Opening, 또는 주인이 같은 FailedUnverified. 원래 열던 작업을 먼저 맞춰 봄
Owner 저장된 실행이 지금 답하는 daemon의 것임. 그 daemon에 닫으라고 함

Session 한 줄

섹션 제목: “Session 한 줄”

session_records의 본문(SessionRecord)이 지니는 값입니다. 비밀 값은 없습니다.

값 뜻
id 엔진이 발급한 Session ID
state · revision 상태와 바뀔 때마다 오르는 버전
projectId 프로젝트에 속한 Session이면 그 프로젝트. Lyra 화면의 독립 대화에는 없음
context 열 때 고정되는 조건: profileRef, 고른 모델, 규칙 참조, 연 쪽(opened_by), 원점(origin), 발사 조건
title 제목 글, 출처(Temporary · ModelSummary · User), 바뀐 시각
launchOperationId 처음 연 요청의 멱등 키
executionHandle 실행 위치가 발급한 참조와 열기 결속: 위치(hostId), 주인 daemon 기동 참조, remoteSessionRef, 기록 시각
openedAt · closedAt · failureCode 열기 확인, 종료 확인 시각과 비밀 없는 실패 코드
continuedFrom 이어받은 닫힌 앞 Session
providerBinding 에이전트의 대화 신원과 쓰는 쪽(writer: Live · Exited · Unknown)의 세대
conversationOptions 마지막으로 확인된 권한 모드와 노력 단계. 발사 조건과 따로 둠
daemonPlace 실행이 받아들여진 곳
cacheObservation 열 때 읽은 캐시 설정(5m · 1h · off)

연 쪽 SessionOpener는 user · orchestrator · workflow_run 셋입니다.

발사 조건 LaunchSnapshot

섹션 제목: “발사 조건 LaunchSnapshot”

열기 직전에 한 번 고정하고 이후 바꾸지 않습니다. 다이제스트(SHA-256)가 함께 저장됩니다.

값 뜻
profileRef · profileRevision · endpointRef 열 때의 Profile과 비밀 없는 접속점 이름
executionHostId · executionLocationId 실행 Host와 위치
workspaceId · nativeCwd 작업 자리와 실행 위치 쪽 철자의 작업 폴더
configRoot · configRootKind 에이전트 설정 폴더와 종류(user_default · sandbox_isolated)
harnessKind · harnessVersion 에이전트 종류와 설치본 버전
environmentNames 환경 변수의 이름만. 값은 없음
primaryModel 실제 쓰는 모델과 출처(session · avatar · profile_global · provider_default)
permissionMode · effort · cacheLifetime · conversationKind 처음 고른 권한 모드, 노력 단계, 캐시 수명, 대화 종류

작성 칸의 선택

섹션 제목: “작성 칸의 선택”
선택 값
권한 모드 PermissionMode default · acceptEdits · plan · bypassPermissions
노력 단계 ReasoningEffort none · minimal · low · medium · high · xhigh · max · ultra. 비우면 에이전트의 기본값. 모델이 내세운 단계만 받음
캐시 수명 5m · 1h · off(에이전트 기본, 시계 없음). 화면은 off나 값 없음(자동)만 고릅니다

두 선택은 한 묶음(ConversationOptions)으로 다음 글 앞에 함께 보내지고, 확인이 와야 글이 갑니다.

Turn 한 줄

섹션 제목: “Turn 한 줄”

session_turns의 한 행은 에이전트 출력의 Card 하나입니다.

값 뜻
id · sessionId 엔진이 준 Turn ID와 소속 Session
sourceKey Card의 원본 참조에서 정해지는 안정 키. 같은 Session 안에서 유일
card · initialCard · updates 검증된 Card, 처음 받은 불변 Card, 받아들인 부분 갱신
outcome 도구 결과의 확인 정보. 본문은 저장하지 않고 ID, 다이제스트, 실패 여부만 둠
contentDigest Card JSON의 SHA-256
receivedSequence · receivedAt 엔진이 받은 순서와 시각
state TurnState
routeDedupeKey 질문 · 승인은 이 키를 먼저 적음

Card의 종류(CardKind)는 Message · ToolCall · Change · Status · Approval · Question · Delegation · ChildWork · PeerMessage 아홉입니다. ChildWork는 같은 Session의 하위 작업(Claude의 sub-agent나 백그라운드 명령), PeerMessage는 다른 Session이 보낸 글이 대화 기록에 나타난 것입니다.

TurnState 뜻
Routing Turn과 중복 키가 먼저 확정됐습니다.
Routed Inbox 항목이 확인됐거나 보낼 필요가 없습니다.
RouteFailed 결과를 몰라 같은 키로 다시 물어야 합니다.

연산

섹션 제목: “연산”

모든 연산은 window bridge의 lyra:call로 부를 수 있습니다. 예외는 session.image.* 넷으로, main만 부릅니다.

연산 한 줄
session.open Session을 엽니다.
session.prompt 글을 보냅니다. 작성 칸 선택(conversationOptions)을 함께 보냅니다.
session.close 닫습니다. 사람이 확인하면 FailedUnverified 기록만 닫습니다.
session.force-stop 되돌릴 수 없는 종료. 확인하지 못한 출력은 남깁니다.
session.interrupt 지금 글 하나만 멈춥니다.
session.resumable · session.continue 이어갈 수 있는지 보고, 같은 에이전트 대화로 이어갑니다.
session.reset 쉬는 Session을 에이전트의 /clear로 갈아타고 메모를 줍니다.
session.retry 이름만 있고 아직 동작하지 않습니다. 항상 session.retry-delivery-port-unavailable로 거절합니다.
session.rename 제목을 바꿉니다. 버전을 말하면 그 버전에서만 바꿉니다.
session.list · session.show 목록과 하나를 읽습니다.
session.turns · session.transcriptCards Turn의 쪽과 대화 기록 Card를 읽습니다.
session.cards · session.cardAction 카드 프로토콜 @2(C-27)의 카드 목록과 기록 쪽을 읽고, 카드의 동작을 보냅니다. 엔진은 Session의 실행 위치 lyra-daemon의 session.cards.read · session.cards.act로 넘깁니다. 이 연산을 부르는 카드 보기는 잠겨 있습니다.
session.read 감독하는 쪽이 감독 대상이 한 말과 일을 읽습니다. 아무것도 보내거나 확인하지 않습니다.
session.artifact 화면에 보이는 그림의 조각을 읽습니다. 조각은 128 KiB입니다.
session.image.begin · append · commit · abort 이미지 올리기. main만 부릅니다.
session.model-calls Lyra가 일으킨 지시의 횟수 같은 메타 정보. 입력 내용은 없습니다.
session.models · session.models.remembered 에이전트의 모델 목록과 엔진이 기억한 마지막 목록입니다.
session.commands 에이전트의 / 명령 목록입니다.
session.capabilities 실행 위치가 하는 일의 목록입니다.
session.inventory Claude Code Session이 쓰는 것의 목록을 실행 위치에서 읽습니다. 다른 에이전트는 session.inventory-unsupported입니다.
session.configuration.show · set Profile 복사본의 실행 명령 설정을 읽고 씁니다.
session.configuration.test.start · show · close 그 설정을 시험해 봅니다.
session.defaults.show · set 에이전트 종류별 기본 모델을 읽고 씁니다.
session.subscribe Session 기록의 바뀜을 구독합니다. sessionId · workspaceId · hostId로 범위를 좁힐 수 있습니다.
session.detach · session.move · session.role.set Orchestration의 dispatch가 처리합니다.

사건

섹션 제목: “사건”

엔진이 Session 기록을 바꾸면 changed(inner, "sessions")가 data-changed 사건을 만들고, sidecar가 { document }로 화면에 전합니다. 화면은 이 사건을 받으면 다시 읽습니다. 중간 버전은 합쳐질 수 있습니다. 사건의 전달은 Sidecar line protocol이 설명합니다.

오류 코드

섹션 제목: “오류 코드”

이 기능의 SessionErrorCode 가운데 사람이 마주치는 것만 적습니다. 전체는 Errors입니다.

코드 뜻
invalid-input 입력의 모양이나 길이가 틀립니다.
invalid-session-transition 허용되지 않는 상태 이동입니다.
late-session-command 이미 끝난 Session에 명령을 보냈습니다.
late-session-input 끝난 Session에 새 입력이 왔습니다.
profile-changed-during-open 여는 동안 Profile이나 실행 지도가 바뀌었습니다.
execution-location-unresolved 실행 위치가 없거나 겹칩니다.
launch-rejected 실행 위치가 발사를 거절했습니다.
launch-outcome-unknown 발사나 닫기의 결과를 증거로 알 수 없습니다.
launch-transport-failed daemon으로의 전송이 명시적으로 실패했습니다.
daemon-instance-mismatch 기록된 주인 daemon이 지금과 다릅니다. 실행과 함께 끝난 실패라 이어갈 수 있습니다.
update-cut 업데이트가 실행을 잘랐습니다. 이어갈 수 있습니다.
wsl-work-stopped 배포판이 꺼져 일이 끝났습니다. 다음 켜기가 켜기 전에 기록합니다. 이어갈 수 있습니다.
session.request-conflict 같은 requestId인데 다른 조건으로 다시 열려 했습니다.
session.retry-delivery-port-unavailable session.retry는 아직 없습니다.
session-resetting 갈아타는 중이라 Lyra의 입력이 기다립니다.
session-reset-clear-unsupported 따라갈 수 있는 clear 명령이 없는 에이전트입니다(Claude Code만 있음).
session-reset-clear-unconfirmed clear를 쳤지만 시간 안에 새 대화를 보지 못했습니다. 다시 치지 않습니다.
store-conflict 기록의 버전이 어긋났습니다.
store-busy · store-wait-timeout home.sqlite가 바쁩니다.
IDENTITY_UNVERIFIED · WRITER_ACTIVE · WRITER_STATE_UNKNOWN · RESUME_PROOF_FAILED 이어가기를 받아들이기 위한 증거가 모자랍니다.

session.reset의 단계

섹션 제목: “session.reset의 단계”

한 번의 갈아타기는 단계마다 먼저 저장하고 나서 쓰므로 엔진이 다시 떠도 clear나 메모를 두 번 치지 않습니다.

단계 뜻
pending Session이 쉬기를 기다립니다.
clearing clear를 쳤고 새 대화를 기다립니다.
cleared 새 대화가 보였습니다.
noting 메모를 주는 중입니다.
done 끝났습니다.
refused 아무것도 치지 못했거나 Session이 닫혔습니다.

clearing · cleared · noting인 동안 그 Session에 가는 Lyra의 입력은 기다립니다. 메모의 한도는 16384바이트이고 기한은 10분입니다.

저장소 버전

섹션 제목: “저장소 버전”

Session 표는 lyra_schema_versions의 구성 요소 session, 버전 3입니다. 버전 1과 2는 열 때 3으로 올리고, 그 밖의 버전은 열지 않고 unsupported-schema입니다.
