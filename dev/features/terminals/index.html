Terminals

터미널은 작업 자리의 폴더에서 도는 셸 하나입니다. 에이전트의 터미널은 Session이 쥐고(Sessions and Turns), 여기서 말하는 것은 사람이나 lyra terminal이 따로 여는 셸 터미널입니다. 연산과 표의 전체 목록은 Terminals details에 있습니다.

화면에서 하는 일

섹션 제목: “화면에서 하는 일”

프로젝트 화면의 탭 줄에서 아래를 합니다.

  • 새 탭: New Terminal(Windows에서는 CMD), New PowerShell, New Git Bash, New Markdown, Open Browser, New Serial입니다. 터미널을 고르면 terminal.split이 셸을 엽니다.
  • 나누기와 Layout: 한 칸(pane)을 나누면 같은 작업 폴더에서 또 하나의 셸이 열립니다. Layout은 여러 Worktree를 한 화면에 보이는 묶음입니다.
  • 터미널 보기: 칸은 terminal.attach로 붙고(terminal-pane-controller), 출력은 terminal.subscribe로, 키 입력은 terminal.input으로 갑니다. 셸 자체를 끝내는 것은 terminal.close이고, 탭을 닫는 동작이 부릅니다(projects-place-controller).

탭의 종류에 따라 엔진을 거치는 정도가 다릅니다.

탭 엔진 어디서 도는가
터미널 terminal.* 작업 자리의 Host에서 PTY
Markdown file.read · file.write 같은 파일 연산(Projects의 작업 자리 폴더) 화면의 편집기
브라우저 없음 Electron main의 WebContentsView(main/artifact-view.ts)
시리얼 serial.*(Serial) 포트가 있는 Host

코드 속 길

섹션 제목: “코드 속 길”

route_unguarded는 terminal.으로 시작하는 이름을 engine/terminal.rs로 보냅니다. 같은 이름 앞머리의 terminal.release · terminal.reuse · terminal.reclaimable은 Worker 터미널의 정산이라 Orchestration이 맡고, file.open-terminal(파일 위치에서 터미널 열기)만 terminal::open_at_path로 갑니다.

열기와 나누기

섹션 제목: “열기와 나누기”

terminal.split은 engine/terminal/completion.rs가 합니다.

  • 요청마다 requestId가 있어야 하고, 같은 requestId는 home_terminal_splits(요청, 요청 내용의 다이제스트, 터미널 번호)로 알아봅니다. 같은 요청이 다시 오면 새 셸을 만들지 않고 이미 만든 것을 답합니다.
  • 작업 자리의 Host에 pty.capabilities를 물어 기본 셸과 쓸 수 있는 셸을 읽습니다(terminal.shells). Windows Host의 셸 이름은 powershell · cmd · git-bash이고 기본은 cmd입니다. powershell-workflow는 워크플로 전용이라 사람에게 고르게 하지 않습니다. 셸 이름은 새 터미널을 만들 때만 받고, 다시 붙거나 읽을 때 바꾸는 요청은 invalid-input입니다.
  • Windows에서 Windows 드라이브의 폴더에 더해진 배포판이 있으면 셸 선택에 배포판 행이 더해집니다(Projects의 WSL 폴더).
  • 어느 Project에도 속하지 않는 터미널(scope: "free")은 내부 소유자 lyra-free-terminal-local로 열고 Project · 작업 자리 장부에는 올리지 않습니다.
  • 나누기는 원래 칸의 확인된 작업 폴더에서 새 셸을 엽니다. 에이전트를 복제하지 않습니다.
  • 에이전트가 끝난 뒤의 셸. 에이전트 칸이 끝나면 칸이 requestId가 agent-exit-shell:<Session 번호>인 terminal.split으로 같은 Session의 셸을 엽니다. 입력이 칸이 보내는 것(cols 80, rows 24, sessionId, sourceTerminalId 없음)과 정확히 같을 때만 이 셸로 받고, 이 requestId를 단 다른 모양은 나누기 구역을 잡기 전에 거절합니다. active가 아닌 Session에는 열지 않고 session.not-active로 거절합니다. 칸은 셸의 첫 스냅숏을 에이전트의 마지막 화면 아래에 쓰고(에이전트의 줄은 스크롤 기록으로 올라가고 마우스 · 포커스 · 붙여넣기 모드는 꺼집니다), 그때까지 입력을 받지 않습니다. 엔진 재시작이나 연결 틈으로 열기가 끊기면 붙기 재시도와 같은 간격으로 다시 묻고, 그래도 안 되면 terminal.return-shell-failed와 원인으로 칸이 끝납니다. Session을 닫는 쪽은 닫기 전후에 이 셸을 찾아 닫고, 열리는 중인 나누기가 있으면 그것을 기다립니다.

붙기와 출력

섹션 제목: “붙기와 출력”

terminal.attach는 저장된 서술자(ShellTerminal)만 PTY에 붙이고, 붙을 때 프로세스를 만들지 않습니다. 엔진은 Host에 터미널 채널을 열고 pty.attach로 보기를 등록한 뒤 daemonInstanceRef가 저장된 값과 같은지 확인합니다. 다르면 terminal.daemon-instance-changed로 거절합니다. 출력은 한 번에 128 KiB 창(VIEW_WINDOW_BYTES)씩 흘러가고, 사람의 키가 긴 출력 뒤에 줄 서지 않게 이 창을 256 KiB 기본값보다 작게 잡았습니다.

화면의 보기는 임대(viewRef, leaseGeneration)로 한 손님에게 묶입니다. 다른 손님이 쓰려 하면 terminal.view-not-owner, 이미 낡았으면 terminal.view-stale입니다.

명령줄에서 붙기

섹션 제목: “명령줄에서 붙기”

lyra terminal의 동사는 list · show · shells · split · attach · reopen · detach · release · reuse · create · send · read · close · rename입니다. 셸 터미널만 다루고, 에이전트 터미널의 번호는 not-found로 답합니다(에이전트는 session prompt · session close).

  • attach: 이미 있는 PTY를 보기만 합니다. 입력 임대를 가질 수 있는 것은 앞에 앉은 TTY의 입력뿐입니다. reopen은 attach의 다른 이름이고, 실행이 사라졌다고 새 셸을 만들지 않습니다.
  • send: 64 KiB 이하의 글을 임시 보기를 열어 pty.claim, pty.input(확인 요구)으로 쓰고, 모든 바이트가 OS에 쓰인 뒤에 답합니다. 사람이 가로챈 것으로 기록하지 않고 대화 Card도 만들지 않으며, 글은 로그에도 답에도 남기지 않습니다.
  • read: 임시 보기로 화면을 다시 그려 마지막 줄들을 돌려줍니다. 기본 120줄, 최대 2000줄입니다.
  • close: Closing을 먼저 적고 pty.close가 확인되면 Closed로 적습니다.
  • rename: 저장된 제목만 바꿉니다. PTY는 건드리지 않습니다.

터미널이 스스로를 알리기

섹션 제목: “터미널이 스스로를 알리기”

엔진이 여는 로컬 셸은 환경에 LYRA_TERMINAL_ID · LYRA_TERMINAL_INCARNATION · LYRA_TERMINAL_NONCE를 받습니다. 그 셸에 에이전트가 쳐 넣은 lyra 명령은 이 값을 terminal.caller에 내보내 어느 Session으로 행동하는지 밝힙니다. 이 이름표는 같은 OS 사용자의 세션끼리 가르는 협조용이고 권한을 더 주지 않습니다. 저장하는 것은 nonce의 SHA-256뿐입니다.

남기는 기록

섹션 제목: “남기는 기록”
어디에 무엇
home.sqlite의 session_shells 셸 터미널 하나(id, 본문 data, SHA-256 digest). 상태 Opening · Attached · Detached · Closing · Closed · Failed
home.sqlite의 home_terminal_splits 나누기 요청의 requestId와 만든 터미널. 버전 1(home_terminal)
Host의 PTY 셸 프로세스와 화면 상태. 엔진이 아니라 Host가 쥡니다.
화면의 localStorage 모든 Layout, 작업 자리마다의 보기, 화면이 마지막에 보인 것: 키 lyra.projects.window-layout.v3

Layout을 쓰는 때는 마지막 변경 250 ms 뒤, 처음 저장하지 못한 변경으로부터 늦어도 1초 뒤, 그리고 창을 닫을 때입니다(useLayoutSave). 바뀐 것이 없으면 타이머를 돌리지 않습니다. 옛 기록(lyra.projects.tab-layout.v1, 이전 창 배치)은 한 번 읽어 옮기고 되돌림을 위해 그대로 둡니다. session_shells가 다른 표와 함께 어떻게 저장되는지는 Sessions and Turns와 home.sqlite가 설명합니다.

연산

섹션 제목: “연산”

연산 이름과 한 줄 설명은 details에 모았습니다. 전체 연산 목록은 Operations가 정합니다.

한도와 기본값

섹션 제목: “한도와 기본값”
값 크기
출력 보기의 창 128 KiB
terminal.send 글 64 KiB 이하
terminal.read 기본 120줄, 최대 2000줄
기본 셸 Windows Host는 cmd. 그 밖의 Host는 pty.capabilities의 defaultShell
Layout 저장 변경 250 ms 뒤, 늦어도 1초

실패할 때

섹션 제목: “실패할 때”
  • terminal.view-stale(보기가 낡음), terminal.view-not-owner(다른 손님의 보기), terminal.stream-invalid · terminal.stream-lost · terminal.stream-gap(출력 채널이 틀렸거나 끊김)입니다. 화면은 다시 붙어서 읽습니다.
  • terminal.daemon-instance-changed · terminal.incarnation-changed · terminal.execution-binding-changed는 PTY를 쥔 daemon이나 실행이 바뀌었다는 뜻입니다. 같은 터미널이라고 이어 붙지 않습니다.
  • terminal.return-shell-failed는 에이전트가 끝난 뒤의 셸을 열지 못해 칸이 끝났다는 알림입니다. 원인 코드가 함께 나옵니다. 엔진이 돌려주는 오류 값이 아니라 칸이 붙이는 알림입니다.
  • terminal.split-unconfirmed · terminal.send-unconfirmed · terminal.detach-unconfirmed는 Host의 답을 받지 못해 결과를 모른다는 뜻입니다. 성공으로 바꾸지 않습니다.
  • terminal.exited · terminal.not-running · terminal.pty-missing은 셸이 이미 끝났거나 Host에 없다는 뜻입니다.
  • terminal.shell-unavailable은 고른 셸이 그 Host에 없을 때, terminal.split-unavailable · terminal.split-store-unavailable · terminal.split-store-conflict는 나누기를 할 수 없거나 요청 기록이 막혔을 때입니다.

코드 전체는 details에 있습니다.

아직 없는 것

섹션 제목: “아직 없는 것”

설계와 다른 점은 구현 현황에 적어 둡니다. 이 기능에서는 Layout이 엔진이 아닌 화면의 localStorage에 있다는 점(LayoutStore는 나중에 엔진 쪽으로 옮길 수 있게 비동기 포트로 두었습니다)이 있습니다.
