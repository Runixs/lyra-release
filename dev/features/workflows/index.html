Workflows

Workflow는 여러 걸음을 묶어 되풀이해 쓰는 흐름이고, 한 번 도는 것이 run, 그 안의 한 칸이 node입니다. 파일의 읽기와 검사, 다음에 할 일의 판단은 crates/lyra-workflow가 하고, 저장하고 시작하고 지켜보는 일은 엔진의 engine/workflows가 합니다. lyra-workflow는 입출력을 하지 않습니다. 찾아보기 표는 Workflows details에 있습니다.

화면에서 하는 일

섹션 제목: “화면에서 하는 일”
  • 워크플로 목록에서 켜고 끄고, 직접 실행합니다.
  • 편집기에서 그래프나 글로 워크플로를 고칩니다.
  • 실행 화면에서 걸음의 상태, 기록, 증거를 봅니다.
  • 승인이나 실패한 걸음의 결정처럼 사람을 기다리는 걸음에 답합니다.

조작은 워크플로 화면에 있습니다. 화면 코드는 apps/desktop/src/renderer/places/workflows/에 있고 새 워크플로의 바탕 글(WORKFLOW_TEMPLATE)은 logic/workflow-wire.ts에 있습니다.

파일 형식

섹션 제목: “파일 형식”

저장된 워크플로는 YAML 글이고 첫 칸 lyraWorkflow가 형식 번호입니다.

형식 엔진이 돌리나 어디까지 있나
1 예 lyra-workflow의 definition이 읽고 검사합니다. 엔진은 이 형식만 저장하고 돌립니다. 화면의 새 워크플로 바탕 글도 lyraWorkflow: 1입니다.
2 아니요 format2가 읽고 거절합니다. 자율 규칙, 예산, 저장된 꼴을 가진 규칙 엔진입니다.
3 아니요 format3이 읽고, 점검하고, 쓰고, 형식 1 · 2의 글을 3으로 올립니다. 올릴 때 버려진 것을 알려 줍니다.

형식 2와 3은 엔진도 화면도 아직 부르지 않습니다. 엔진 쪽에서 lyra_workflow::format2나 format3을 쓰는 곳이 없고, workflow.save는 definition::check로 형식 1만 받습니다. 형식 3은 코드 머리말도 “새 종류의 걸음을 걷는 일은 다른 묶음의 몫”이라고 합니다. 이 차이는 구현 현황에 적어 둡니다.

형식 1

섹션 제목: “형식 1”

글의 큰 칸은 name, description, orchestrator(값은 lyra만 받음), limits(maxTime), policy, floor, nodes, layout입니다. 걸음 종류는 둘이고 두 종류만 돕니다.

  • trigger: 실행을 시작합니다. 한 파일에 하나만 있습니다. manual(사람이 workflow.run-start로)이거나 연결의 issue-assigned 신호입니다. 신호는 연결 이름과 match(Jira 프로젝트 또는 GitHub 저장소)를 가집니다.
  • agent: 에이전트의 Worker Session이 프롬프트를 일하거나(launch가 session), 터미널에서 명령을 칩니다(terminal). 일할 자리(where: 새 작업 자리의 이름 또는 앞 걸음의 자리), Profile, 모델, 노력 단계, 출력 칸, 통과 검사, 시간 한도, 실패했을 때(onFail), 기록 수준을 가질 수 있습니다.

걸음 글의 ${node.port.field}는 앞 걸음의 값으로 채워집니다.

형식 3

섹션 제목: “형식 3”

형식 3은 걸음 종류를 데이터로 둡니다: trigger · agent(에이전트) · command(명령) · model-query(모델 질의) · if-else(IF/ELSE) · classify(내용 분류) · merge(합치기) · template · result(결과). tool-call과 http는 아직 돌 수 없어 이름으로 거절합니다. 값 참조는 {{#node.var#}}입니다. 실행 방식은 engine-driven(기본)과 orchestrator-driven이고, 걸음의 needsApproval은 agent와 command만 받습니다. 사람이 그리는 동안 비워 둔 칸은 저장하되 점검이 무엇이 비었는지 알려 줍니다.

코드 속 길

섹션 제목: “코드 속 길”

workflow. 로 시작하는 모든 연산이 engine/workflows/mod.rs로 갑니다. 저장(workflow.save)은 글을 검사해서 다음 버전(home_workflow_versions)을 만들고, 실행은 시작할 때의 버전에 고정됩니다. 실행의 한 걸음은 한 번의 시도를 가집니다.

실행이 시작되는 길

섹션 제목: “실행이 시작되는 길”
  • 직접: workflow.run-start. 시작 키는 manual:<요청 번호>입니다.
  • 연결의 신호: Issues의 연결이 “내게 새로 배정된 열린 이슈”를 보면 IssueAssigned를 엔진 안으로 보냅니다. 켜진 워크플로 가운데 연결 이름이 같고 프로젝트(Jira) 또는 저장소(GitHub)가 맞는 것마다 실행이 하나씩 생깁니다. 시작 키는 <워크플로>:<연결>:<이슈 키>:<처음 본 시각>이라 같은 신호가 두 번 와도 실행은 하나이고, 같은 신호에 맞는 서로 다른 워크플로는 각자 실행을 가집니다.

걷기

섹션 제목: “걷기”

엔진 안의 반복(engine/workflows/engine.rs)이 2초마다 열린 실행을 걷습니다. lyra-workflow의 run이 저장된 사실만 보고 “다음에 할 일”을 판단하고, 엔진이 그것을 합니다. 한 번 걷는 동안 한 실행에서 내리는 결정은 64개까지이고 넘으면 다음 번으로 미룹니다. 한 컴퓨터에서 동시에 시작 중인 걸음은 모든 실행을 합쳐 4개까지입니다.

실행의 상태는 Queued → Running → Passed · Failed · Stopped이고, 걸음의 상태는 Ready · Running · Passed · Failed · Stopped · Skipped입니다. 실행 시간 한도(limits.maxTime)를 넘으면 실행은 실패합니다.

한 걸음은 일할 자리를 쥡니다. 새 작업 자리를 만들거나 앞 걸음의 자리를 씁니다. 실행이 만든 자리와 Worker Session은 실행에 속해서 프로젝트 화면과 Lyra 화면에는 나오지 않고 워크플로 화면에서만 보입니다.

사람을 기다리는 걸음

섹션 제목: “사람을 기다리는 걸음”

실행은 엔진 안에서 Inbox 항목을 만들고 사람의 답을 기다립니다. 항목은 Inbox와 같은 표를 쓰고 본문은 home_inbox_bodies에서 workflow-gate:로 시작하는 참조로 가리킵니다. 종류는 넷입니다.

종류 언제 사람이 정하는 것
approval 걸음에 needsApproval이 있어 시작 전 승인(approve) 또는 거부(deny)
decision 시도가 실패했고 자동 시도가 남지 않음 면제(waive: 통과로 침), 한 번 더(retry), 멈춤(stop)
check 시도의 턴이 끝 보고 없이 끝남 같은 Session에 이어서 하라고 함(continue) 또는 걸음을 다시 보냄(retry)
question 에이전트가 터미널에서 답을 기다림 아무도 정하지 않습니다. Session이 다시 일하면 사라집니다.

이 항목은 앱만 답합니다. lyra inbox answer를 포함한 다른 호출은 “Lyra 앱의 받은 요청에서 답하라”는 문장으로 거절합니다. 앱은 workflow.approval-show로 항목을 읽고 workflow.decide로 답하며 메모(4000바이트까지)를 함께 보냅니다. 답은 걸음의 기록과 사람의 기록(approval 또는 waiver)과 함께 한 트랜잭션으로 저장되고, 그다음에야 Inbox 항목이 닫히고 엔진이 깨어납니다.

기록과 증거

섹션 제목: “기록과 증거”

걸음은 기록(choice · assumption · finding · approval · waiver)을 남길 수 있고, 걸음의 에이전트는 lyra workflow record로(workflow.record) 쓰되 엔진이 그 호출자가 지금 도는 걸음인지 확인합니다. 수준(off · requested · required)에 따라 에이전트에게 묻고, 걸음이 끝날 때 확인하며, required가 빠지면 시도를 실패로 칩니다. 사람만 면제할 수 있습니다.

장부와 끊긴 시작 이어가기

섹션 제목: “장부와 끊긴 시작 이어가기”

엔진은 실행마다 장부(home_workflow_journal)를 덧붙이기만 합니다. 걸음 표가 바뀔 때마다 DB 트리거가 한 줄을 적고(step-made, step), 엔진이 start · effect · start-ended · turn · comment-refused · report-held · report-taken을 더합니다. 줄을 고치려는 시도는 workflow.journal-append-only로 중단됩니다.

걸음 시작은 여러 효과로 이루어집니다. 작업 자리 만들기, Session 열기, 터미널 열기, 작업 보내기, 명령 치기입니다. 엔진은 시작 전체를 먼저 start로 적고, 되짚어 찾을 수 없는 효과 앞에는 effect를 먼저 적고, 시작이 끝나면 start-ended를 적습니다.

Lyra가 멈췄다 다시 뜨면 fold가 열린 실행의 줄을 읽어 메모리의 사실을 되살립니다. start-ended가 없는 시작은 중간에 끊긴 것이고 resume_starts가 효과 하나씩 이어갑니다. 되찾을 수 있는 것은 되찾습니다. 실행이 잡아 둔 작업 자리, 요청 번호로 찾는 Session, 터미널, 작업입니다. 되찾을 수 없는 두 효과, 곧 작업 자리 만들기(WorkspaceCreate)와 명령 치기(TypeCommand)는 시작했는데 끝났는지 모르면 다시 하지 않습니다. 그 시도는 “결과를 모름”으로 잃은 것이 되고 사람을 기다립니다. 시작한 걸음이 이미 다른 상태로 갔거나 실행이 멈추는 중이거나 시간 한도를 넘었으면 그 시작은 버립니다.

멈추기와 정리

섹션 제목: “멈추기와 정리”

workflow.run-stop은 멈춤을 먼저 영속 울타리(home_workflow_stop_fences)에 적고 나서 자원을 하나씩 멈춥니다. 증거는 home_workflow_stop_proofs와 home_workflow_execution_identities에 둡니다. 끝난 실행이 만든 작업 자리는 workflow.run-clean이 한 호출에 2개까지 지웁니다. 지우는 데 실패하면 workflow.workspace-not-removed입니다.

남기는 기록

섹션 제목: “남기는 기록”

모두 home.sqlite의 구성 요소 home_workflows(버전 11)입니다. 파일은 home.sqlite가 설명합니다.

표 한 행
home_workflows · home_workflow_versions 워크플로와 저장할 때마다 만들어지는 버전
home_workflow_runs · home_workflow_steps · home_workflow_attempts 실행, 걸음(한 시도씩), 시도
home_workflow_outputs 걸음의 출력
home_workflow_gates 사람을 기다리는 걸음의 항목
home_workflow_journal 덧붙이기만 하는 장부
home_workflow_workspaces · home_workflow_leftovers 실행이 만든 작업 자리, 지우다 남은 폴더
home_workflow_stop_fences · home_workflow_stop_proofs · home_workflow_execution_identities 멈춤 울타리, 증거, 실행 신원
home_choice_records · home_choice_evidence · home_choice_asks 기록과 그 증거, 에이전트에게 다시 물은 것(engine/workflows/records.rs)

세부는 details에 있습니다.

연산

섹션 제목: “연산”

연산 이름과 한 줄은 details에 모았습니다.

한도와 기본값

섹션 제목: “한도와 기본값”
값 크기
걷기 간격 2초
한 번 걸을 때 한 실행의 결정 64개
동시에 시작 중인 걸음 4개(설정이 아님)
걸음의 출력 칸, 통과 검사 각각 8개까지
재시도, 되돌려 보내기 4번, 10번까지
통과 검사의 시간 기본 600000ms(10분)
사람의 메모 4000바이트까지
workflow.run-clean 한 호출 작업 자리 2개
실행 화면의 출력 목록에서 앞 280자, 64 KiB까지는 전부

실패할 때

섹션 제목: “실패할 때”
  • 파일이 형식 1이 아니면 workflow.save가 거절하고 어느 칸이 왜 틀렸는지 경로와 함께 알려 줍니다.
  • 시작했다가 끊긴 효과 가운데 되찾을 수 없는 것은 다시 하지 않고 사람을 기다립니다.
