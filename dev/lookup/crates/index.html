Crates

작업 공간 멤버마다 한 줄이고, 그 멤버를 설명하는 쪽은 하나입니다. 모든 멤버에 쪽이 있습니다. 멤버 수와 세는 방법은 이렇습니다.

  • 멤버는 루트 Cargo.toml의 members에 드는 것입니다. contracts/* 1개, crates/* 33개, testkit/* 2개, 앱 3개(apps/daemon, apps/cli, apps/desktop-sidecar), 모두 39개입니다. 각 글롭은 Cargo.toml이 있는 폴더를 셌고 폴더 하나도 빠지지 않았습니다. apps/desktop은 Electron 프로젝트라서 멤버가 아닙니다. third_party/*는 exclude입니다.
  • “하는 일”은 각 crate 머리말(src/lib.rs나 src/main.rs의 //!)과 Cargo.toml의 description에서 옮겼습니다. 머리말이 지금 코드와 다른 곳은 구현 현황에 적었습니다.
  • “설명하는 쪽”은 그 crate의 일을 풀어 쓴 쪽입니다. 이름이 한 번 나오는 것만으로는 셈하지 않았습니다. 일을 나눠 설명하는 쪽이 둘 이상이면 가장 많이 설명하는 쪽 하나를 골랐습니다.
  • 엔진의 기능 모듈(crates/lyra-app/src/engine/ 아래)은 연산마다 Operations가 어느 모듈이 맡는지 적습니다. 이 표는 crate 단위입니다.

crates/lyra-dispatch 작업, 실행 시도, 끊김 정책, 작업 순서도, 갈림길, 세션 사이 메시지 장부 Orchestration
crates/lyra-harness 에이전트 종류별 파일 · 실행 계획 · 신호의 순수 번역 Avatars and Modules
crates/lyra-host Host와 실행 위치의 지도(ExecutionMap)와 공용 위치 값 Projects and Workspaces

crates/lyra-link 이 컴퓨터에서 서버로 거는 쪽 전송: SSH 연결 하나 위에 Link의 논리 채널을 얹습니다. Link
crates/lyra-link-protocol 기계 경계를 넘는 메시지의 모양과 판정: 프레임, 채널, 버전 악수, 오류 Link
crates/lyra-module prompt · skills · mcp 모듈의 보관, 실행 위치별 설치 기록, 내용 지문 검증(ModuleRegistry) Modules
crates/lyra-platform macOS와 Windows가 다르게 구는 자리(실행 위치, 경로, 창 값, 프로세스 수명, OS 서비스)를 한 곳에 모읍니다. Engine
crates/lyra-plugin 나중의 확장 경계와 외부 신호 자리를 닫힌 값으로 둡니다. Plugins
crates/lyra-process Lyra가 띄운 자식의 정책, 목록, 수명 Agent and terminal children
crates/lyra-profile Host마다 깔린 에이전트 CLI 탐지(RuntimeCatalog)와 정본 · 파생 Profile(ProfileRegistry) Profiles and agents
crates/lyra-project Project 등록과 작업 자리의 생성 · 준비 · 재개 · 안전 제거 판단(ProjectRegistry) Projects and Workspaces
crates/lyra-sandbox 사용자 전역 설정과 전역 프롬프트가 보이지 않는지 확인하는 선택적 실행 조건 Agent and terminal children
crates/lyra-serial 시리얼 줄 검증, 바이트 위치 한도, 쓴 쪽과 보기 임대의 판단 Serial

crates/lyra-trace 범위(프로젝트 또는 앱)별 불변 실행 기록, 복구 대기열, 에이전트 대화 파일의 토큰 사용량 읽기 Status and diagnostics
crates/lyra-tui lyra tui: 터미널 안의 문자 화면(시작 점검, 키 해석, 터미널 계층, 트리, 엔진 세션, 나눈 칸) Command line
crates/lyra-update 앱 묶음의 새 버전 확인 · 검증 · 적용 · 되돌림의 판단과 순서(UpdateEngine) Updates
crates/lyra-usage 입출력 없는 사용량 세기. 게이트웨이의 사용량 답 읽기(gateway)와 릴리스에 담긴 가격표(price) Status and diagnostics
crates/lyra-vt-toolchain lyra-tui가 쓰는 고정된 터미널 에뮬레이터 라이브러리와 그 빌드 규칙의 검사 Command line
crates/lyra-worker-supervisor LLM 없이 Worker의 진행을 판정하고, 닫힌 원인의 일시 장애만 복구하고, 못 푼 것을 묶어 올립니다. Orchestration
crates/lyra-workflow 저장된 워크플로, 실행, 시작 신호(입출력 없음) Workflows
crates/lyra-workspace 작업 자리의 공유 파일 읽기와 Git 상태, 감시의 판단 Projects and Workspaces
testkit/lyra-fake-link 시험용 가짜 SSH 서버, 가짜 daemon, 가짜 ssh-agent. 제품 코드가 아닙니다. 이 쪽 (아래 “시험 전용 멤버”)
testkit/lyra-testkit 시험 전용 시나리오와 부분 실행 결과. 제품 코드가 아닙니다. 이 쪽 (아래 “시험 전용 멤버”)
apps/daemon (lyra-daemon-app) 실행 파일 lyra-daemon의 main과 authority/: 엔진과 keeper의 고정된 진입(native_entry.rs), 계정 초기화, 엔진 시작 허가, 넘기기의 엔진 쪽, 시작 단계 보고(parts.rs) Engine
apps/cli (lyra-cli-app) 실행 파일 lyra: 인자와 표준 입출력을 lyra-cli에 넘기고 종료 코드로 끝납니다. Command line
apps/desktop-sidecar 실행 파일 lyra-desktop-sidecar: Electron main과 한 줄 JSON으로 이어져 공용 연산 목록을 부릅니다. Desktop sidecar

시험 전용 멤버

섹션 제목: “시험 전용 멤버”
  • testkit/lyra-fake-link는 시험 전용입니다. lyra-link · lyra-update 같은 시험이 쓰는 가짜 SSH 서버, 가짜 daemon, 가짜 ssh-agent를 가집니다. 제품 프로그램에는 들어가지 않습니다. 다만 lyra-app이 기능 test-seams를 켠 시험 빌드에서만 선택 의존으로 끌어옵니다(crates/lyra-app/Cargo.toml).
  • testkit/lyra-testkit은 시험 전용입니다. 수용 시험이 쓰는 시나리오와 부분 실행 결과를 가집니다. 어떤 제품 crate도 이것을 쓰지 않고 apps/cli의 시험만 개발 의존으로 씁니다.
