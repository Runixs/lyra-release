WSL channel

Windows PC에서 WSL 배포판을 서버처럼 쓸 때, 엔진은 SSH 대신 wsl.exe 자식 프로세스 하나를 띄워 그 표준 입출력으로 배포판 안의 lyra-daemon과 이야기합니다. 네트워크도 SSH도 거치지 않습니다. 화면에서 쓰는 방법은 WSL을 서버로 쓰기에 있습니다.

두 끝

섹션 제목: “두 끝”
끝 하는 일 코드
Windows의 엔진 배포판을 고르고, wsl.exe 자식 하나를 시작하고, 연결이 끊기면 배포판이 돌고 있는지 봅니다. crates/lyra-link/src/wsl_channel.rs
배포판 안의 lyra-daemon serve --socket <경로> --remote --wsl로 떠 있다가 attach가 이어 주는 입출력으로 Link 줄을 받습니다. crates/lyra-daemon/src/runtime/args.rs

서버 쪽 프로그램은 Server daemon에서 다룹니다.

통로

섹션 제목: “통로”

한 번 연결할 때 wsl.exe는 한 번만 시작합니다.

  • --exec이라서 wsl.exe가 사이에 셸을 끼우지 않습니다. 환경은 WSL_UTF8=1만 더하고, 자식의 작업 폴더는 wsl.exe가 있는 시스템 폴더입니다. Workspace가 아닙니다.
  • 명령줄은 32,000 글자 단위(MAX_COMMAND_LINE_UNITS)를 넘지 못합니다.
  • 배포판은 wsl.exe -d가 쓰는 이름으로 레지스트리 목록에서 고릅니다. 대소문자를 구분하지 않고, 같은 이름이 둘이면 하나를 고르지 않고 거부합니다. WSL 1 배포판도 거부합니다.
  • 연결은 이 순서입니다. 자식이 시작되어 루프의 첫 줄 ready가 오면 → run으로 서버 점검 · 설치 · 시작을 하고 → 마지막에 exec으로 루프가 lyra-daemon attach --socket <경로>가 되면 → 그 입출력이 Link 줄이 됩니다.

1단계: 루프

섹션 제목: “1단계: 루프”

루프 스크립트는 고정된 글입니다. 경로, 버전, 이름 같은 값을 스크립트에 넣지 않고, 루프 버전만 첫 인자 $1로 받습니다. 줄은 JSON 한 줄이고 모든 줄에 lyraWslLoop로 루프 버전을 싣습니다. 값은 LOOP_VERSION이고 1입니다.

  • 명령은 /bin/sh -c로 돌고, 표준 출력은 임시 파일에 모아 길이를 알린 뒤 그 길이만큼만 보냅니다. 표준 오류는 버립니다. 명령이 남긴 자식이 나중에 쓰는 글이 다음 답에 섞이지 않게 하려는 것입니다.
  • 명령은 $HOME에서 돕니다. ssh 명령과 같습니다.
  • 한 명령의 출력은 1 MiB(MAX_ANSWER_BYTES)까지이고 줄 하나는 4,096 바이트(MAX_FIRST_LINE_BYTES, 개행 포함)까지입니다.
  • 모르는 동사를 받으면 종료 코드 64로, 임시 폴더를 만들지 못하면 setup-failed와 종료 코드 70으로 끝납니다. 연결이 끊기는 신호(HUP · INT · TERM · PIPE)를 받으면 종료 코드 75로 끝납니다.

2단계: Link

섹션 제목: “2단계: Link”

exec 뒤에는 SSH와 같은 Link 줄입니다. 같은 PROTOCOL_VERSION, 같은 bootstrap, 같은 봉투와 바이트 프레임이므로 Link를 보세요. 버전 맞추기 5초 제한은 루프의 첫 줄을 받은 뒤부터 셉니다.

SSH와 다른 점

섹션 제목: “SSH와 다른 점”
SSH WSL
전송 네트워크 위의 SSH 연결 wsl.exe 자식의 표준 입출력
호스트 키 · 인증 있음 없음. 이 PC의 같은 사용자 안입니다.
시작 SSH 연결이 서면 서버에서 명령 자식을 띄우면 루프가 먼저 서고 그 안에서 명령
끊김 감지 SSH 무응답 확인 입출력 끝(EOF)
끊긴 뒤 다시 붙기 계획 배포판이 도는지 한 번 확인한 뒤 결정
서버의 lyra-daemon이 내려가기까지의 대기(전송과 무관) 서버의 lyra-daemon의 기본: 연결 0 · 자식 0이 15분, 한 번도 안 붙었으면 60초 WSL에서만 다른 값: 한 번이라도 붙은 뒤에는 스스로 내려가지 않고 배포판이 도는 동안 떠 있음. 한 번도 안 붙었으면 60초

누가 붙을 수 있나

섹션 제목: “누가 붙을 수 있나”

이 채널에는 호스트 키 확인도 로그인도 없습니다. 입출력 파이프를 쥔 것은 엔진과 엔진이 띄운 wsl.exe 자식 둘뿐입니다. Windows가 아닌 OS에서는 이 채널을 열지 않고 wsl.unsupported-os(refused)로 거부합니다.

한도

섹션 제목: “한도”
한도 값
루프의 첫 줄을 기다리는 시간(STARTING_DISTRIBUTION_DEADLINE) 20초. 멈춘 배포판을 깨우는 시간을 포함합니다. 단계 이름은 starting-distribution입니다.
시작 실패 때 읽는 글 4,096 바이트(MAX_START_FAILURE_BYTES)
돌고 있는지 확인(wsl.exe --list --quiet --running) 30초, 출력 64 KiB
멈춤 요청 도우미 75초, 채널 80초(STOP_HELPER_TIMEOUT · STOP_CHANNEL_TIMEOUT)
서버 쪽 대기 한 번이라도 붙은 뒤에는 연결 0 · 자식 0이어도 내려가지 않고, 한 번도 안 붙었으면 60초 뒤 시작 실패로 내려갑니다(IdlePolicy::WSL, crates/lyra-daemon/src/config.rs). Lyra는 배포판을 끄는 요청이 없습니다. 서버의 lyra-daemon의 기본은 15분(IdlePolicy::PRODUCT)입니다.

돌고 있는지 확인하는 wsl.exe는 배포판 전체에 대해 한 번만 읽고, 끊김이나 사람의 동작으로 답이 낡았을 때만 다시 읽습니다. 이 확인이 시간 안에 끝나지 않으면 “멈춤”이 아니라 “모름”으로 봅니다.

끊기면

섹션 제목: “끊기면”
일 일어나는 일
요청 없이 입출력이 끝남 wsl.exe --list --quiet --running을 한 번 돌립니다. 돌고 있으면 다시 붙기 계획으로, 멈췄으면 distribution-stopped로, 알 수 없으면 distribution-state-unknown으로 갑니다. 뒤의 둘은 다시 시도하지 않습니다.
앱이 시작될 때 판정이 없으면 배포판마다 확인하지 않고 한 번의 읽기로 전부 알아봅니다. 이때 멈춘 배포판을 깨우지 않습니다.
멈춘 배포판을 깨우는 것 사람이 WSL Project를 열거나 Session을 시작하거나 연결 · 시작을 누를 때만 합니다. 다시 붙기, 상태 읽기, 앱 시작은 깨우지 않습니다.
루프의 버전이 다름 link-wsl-loop-version-mismatch
루프의 줄이 읽히지 않음 link-wsl-loop-framing

그 밖의 코드는 아래와 같습니다. 뜻은 Errors에 모읍니다.

link-wsl-not-installed · link-wsl-distribution-not-found · link-wsl-version-one-refused · link-wsl-distribution-ambiguous · link-wsl-failed · link-wsl-start-timed-out · link-wsl-distribution-stopped · link-wsl-distribution-state-unknown
