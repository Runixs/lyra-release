First Session

This page is for people who have finished Install. The steps are:

  1. Add a project.
  2. Create a workspace (a Worktree or a Workspace).
  3. Open an agent Session.

1. Add a project

Section titled “1. Add a project”

A Project is a repository or folder you registered in Lyra.

  1. Open Projects in the left rail.

  2. Click the folder-shaped Add project button at the top of the Explorer. If you have no project at all, the same button is also inside the list. You can also drag a folder onto the Explorer to add it.

    This screen was captured with sample data.

  3. In the Add Project dialog, choose a method: Open folder, Clone from URL, or Create new.

  4. Type the folder path in Path, or pick the folder with the folder-shaped button (Browse folders).

  5. Click Add.

If you have a connected server, choose where to add the project in Host. This computer shows as localhost. If the server is not connected yet, the dialog says “Connect to name, then select a folder.” and shows a Connect button.

For a folder that is not a Git repository, one more confirmation dialog appears. Click Add folder and the folder is added as it is. If you select several folders at once, the folders that are not Git repositories are skipped, and Lyra tells you how many it skipped. Add the skipped folders one by one.

When the add finishes, the new project expands and the workspace for that project folder opens.

2. Create a workspace

Section titled “2. Create a workspace”

For a Git repository, you create a Worktree (a separate working folder for each branch of the same repository). For a folder that is not Git, you create a Workspace (one working folder). The agent works inside this place.

  1. Click the + button on the project row. You can also choose Add Worktree (or Add Workspace if the project is not Git) from the row’s menu.
  2. The Create Worktree dialog opens (Create Workspace if the project is not Git).
  3. For a Git repository, type a name and choose a Starting branch. The Host field appears only when there are two or more choices, or when you have added a WSL distribution on Windows.
  4. In the Agent field, choose the agent to open as soon as the workspace is created. To open none, choose No session.
  5. Click Create.

If you chose an agent and the Setup Script is still running, the screen says “The session starts once the setup command finishes.”

Each Worktree gets its own color, with no overlaps, and you see the same color on its Explorer row and on the card strip.

Setup Script and the trust check

Section titled “Setup Script and the trust check”

The Setup Script is a setup command that runs first when a workspace is created (it lives in the project’s .lyra/config.yaml). You edit it in Setup Script under Project settings. The Create Worktree dialog has no field for it.

  • If a command is new or has changed, the Run Setup Script dialog shows the list of commands. Read it, then choose Run or Do not run. If you turn on Always trust this project, Lyra stops asking for this project from then on.
  • If there is no command, Lyra continues without asking.
  • If the file is wrong or cannot be read, the workspace cannot be created. In that case, turn on Do not run Setup Script this time and you can create it without the script.

For the commands of a project you do not know, read what they do before you click Run.

Delete a workspace

Section titled “Delete a workspace”

Choose Delete Worktree… from the menu of a workspace row, and the Delete workspace dialog opens.

  • Lyra stops the running Sessions and terminals in a fixed order. If it cannot confirm that even one has stopped, it stops there and leaves the folder as it is.
  • If the branch you created has commits that are not merged, choose between Delete and keep the branch and Delete the branch too.
  • The workspace of the project folder itself has no delete item.

3. Open a Session

Section titled “3. Open a Session”

A Session is one task with one agent. When you choose a workspace on the Projects screen, the start screen appears.

Open from the start screen

Section titled “Open from the start screen”

An empty workspace shows a start screen with an input box.

  1. Type what you want done in the input box. (The box says “Write what to do in name”.)
  2. Choose an agent. If a model chip appears, choose a model too.
  3. Click the send button (Send as a new session).

The agent list shows the Profiles (settings that record how to run an agent) that are turned on for this computer (or the server you chose), by name. You can start Claude Code, Codex, and OpenCode. OpenCode starts only at version 2.0.0 or newer. An older one still appears in the list, but when you start it, you see “OpenCode … is older than Lyra needs (2.0.0 or newer), so the session was not opened. Run opencode upgrade on that computer, then start again.”

An agent that cannot take a first message says “Open it without a message below.” Use the menu below.

If Lyra finds none of Claude Code, Codex, or OpenCode on that computer, you see “No installed agent (Claude Code, Codex, OpenCode) was found on …. Install an agent, then start.” and View in Settings › Agents. Click it and the agent settings open with that computer already chosen. While Lyra is still looking, this sentence does not appear.

Open from the menu

Section titled “Open from the menu”

You can also open one from the button on the start screen or the + menu on a tab. The menu has this order:

  1. The list of Profiles that are turned on
  2. Manage agents…
  3. Terminals: New Terminal, New PowerShell, New Git Bash

For Claude Code and Codex, you can choose a model from the arrow next to the Profile. If you choose Default at the top, Lyra opens the Session without setting a model. Even if Lyra cannot read the model list, it tells you “It opens with the default model” and you can still open the Session.

If no Profile is turned on, you see “No profile is turned on for this host”. See “Add a Profile” below.

If you need only a terminal, choose New Terminal (cmd), New PowerShell, or New Git Bash.

While it opens, and when it does not open

Section titled “While it opens, and when it does not open”

While it opens, the send button shows a spinning mark. If it fails, the reason appears on the Session screen or in a notice.

  • “The new session could not be opened.” Lyra keeps what you typed.
  • “The session was opened, but the first message could not be sent.”
  • “It could not be confirmed whether it started or was sent.” Check it with Open the session to check.

Status words

Section titled “Status words”

Session states appear as English words.

  • Work state: Working, Waiting, Done, Idle, Interrupted
  • Open and closed: Opening, Active, Closing, Closed
  • Failure: Failed, Failed · Unverified

Failed · Unverified means that the start is known to have failed but Lyra could not confirm whether the process that started first has stopped. It is covered in Failed · Unverified Session.

When the agent program is not installed

Section titled “When the agent program is not installed”

If Lyra cannot find the agent program on this computer (or the server) while opening a Session, a View in Settings › Agents link appears next to the failure notice. This link takes you to the Agents screen of Settings (under Connections in the left list). The install dialog does not open by itself, so open it yourself.

  1. Open Settings → Agents.
  2. In the Machines list on the left, choose the computer where you want to install, and click Add agent/profile at the top of the right side.
  3. Choose Install agent…. You can also click How to install on that agent’s row under Supported.
  4. Expand Install instructions for the agent you want to install. The app shows the command for that computer’s operating system, and there is a copy button.
  5. Run the command yourself in a terminal on that computer. Lyra does not run this command for you.
  6. When the installation is done, click Check now.

An agent that is not installed appears under Supported as Not installed.

Add a Profile

Section titled “Add a Profile”

A Profile is a setting that records how to run an agent. Each computer (host) has its own.

  1. Open Settings → Agents.
  2. In the Machines list on the left, choose the computer, click Add agent/profile, and then choose Add profile…. It turns on only after the agent has been confirmed on that computer. You can also choose Copy profile… from the ⋯ menu of an agent row.
  3. Set the Profile name and the Agent, and if needed fill in Executable (absolute path), Base arguments, and Model name (optional).
  4. Check it in the Test tab. You can also save without testing.
  5. Save. Turn the Profile on and off with the switch on its row.

Write the executable as an absolute path. You cannot use an alias or a function name. Pre-run command is locked on Windows and cannot be used. The agent version check waits 5 seconds the first time and 8 seconds on a retry. If it does not finish, see When the version check does not finish.
