The top and bottom of the window

About this screen

Section titled “About this screen”

Some parts of the Lyra window stay the same when the screen changes. They are the header bar at the top (the row with the search and the notification bell), the status bar at the bottom (the row that shows run status in cells), and the bottom panel that opens above the status bar. The left rail has the buttons that choose a screen and the Inbox button.

The picture on this page was taken with sample data.

What each screen does is on that screen’s page. This page covers only the parts that all screens share. Parts that another page already explains link there.

Part Where it is explained
The search in the header bar To find things with Quick jump below
The bell in the header bar Notice list
The Inbox button in the left rail Inbox button below, and Inbox
The sessions cell in the status bar To read the status bar below
The Remote and WSL cells in the status bar To see server connections in the status bar
The usage cell in the status bar Appearance
The Board tab of the bottom panel To see the board
The terminal tabs of the bottom panel To use a terminal in the bottom panel below

Header bar

Section titled “Header bar”

The header bar is the single row at the very top of the window. On macOS the left end leaves room for the window buttons (the traffic lights). On Windows the left end has the Lyra mark, and the right end has the Minimize window, Maximize window (after maximizing, Restore window size) and Close window buttons. Selecting the Lyra mark (on macOS, at the top of the left rail) opens Home. Its name is “Go to the Lyra screen”.

On the left there is the search button, and at the right end there is the notification bell. The middle differs by screen. On the Projects screen, the tabs sit in this row.

To find things with Quick jump

Section titled “To find things with Quick jump”

Quick jump is a window that finds a workspace, a conversation, a profile or a project by name and takes you there. It asks Lyra’s lyra-daemon each time you search, and it does not save results.

  1. Select the search button at the left of the header bar. Its name is “Search workspaces, conversations, profiles and projects”, and pointing at it also shows the shortcut. The shortcut is ⌘ K on macOS and Ctrl K on Windows.
  2. When the Quick jump window opens, type a name in the “Find by workspace, conversation, profile or project name…” field. Lyra searches when you pause typing. While it searches you see “Searching.”
  3. Each result row has a kind (Workspace, Conversation, Profile, Project). Move with ↑ ↓ and open with Enter. You can also select a row with the mouse. To close the window, press Esc or the close button. Under the window you see “↑ ↓ Move”, “Enter Open”, “Esc Close” and “N results”.
  4. When you open a row, the window closes and the place the row points to opens.
Row you chose What opens
Project That project on the Projects screen
Workspace That workspace on the Projects screen
Conversation A conversation opened on the Lyra screen opens on the Lyra screen; any other session opens on the Projects screen
Profile That profile in Agents in Settings (Profiles and agents)
  • An Enter you press to confirm a character while typing Korean does not open a row.
  • On Windows, when focus is inside a terminal, Ctrl K is used by the terminal. When focus is inside the file editor, the shortcut does not open on macOS or Windows, so select the search button.
  • If you collapse the Explorer on the Projects screen, the search button leaves the header bar, and the shortcut does not open while it is gone. When the Explorer is hidden because the window is narrow, the button stays.
  • A server’s Project and a profile row end with a Host name. See Servers and Hosts.

Inbox button

Section titled “Inbox button”

The Inbox button is not in the header bar. It is at the top of the left rail of the window. On macOS it sits just below the Lyra mark. Selecting it opens the Inbox screen. The button shows the number of requests you have not answered yet. Its name is “N inbox requests — open the inbox”. If it is still reading the number, you see “Reading the number of inbox requests — open the inbox”. If the last number read may not be up to date, you see “N inbox requests (the last count read, may not be up to date) — open the inbox”. If Lyra could not read it, you see “The number of inbox requests could not be checked.” with the reason.

The number of Inbox requests is not the number of Waiting sessions. A Waiting session is a Session waiting for a person’s answer, and Inbox requests are approvals and questions that ask for an answer.

Notification bell

Section titled “Notification bell”

The bell button is at the right end of the header bar. The number is how many notices you have not seen yet. Selecting it opens the notice list. How to read the list, how to clear it, and the card that pops up briefly next to the bell are in Notice list.

To read the status bar

Section titled “To read the status bar”

The status bar is the single row at the very bottom of the window. Its name is “Run status”. Every cell except the bottom panel button opens a card upward when you select it, and closes when you select it again or press Esc. Pointing at it or only putting focus on it does not open it. If the window is narrower than 1050 px, words in the cells such as “Remote” and “Processes” are dropped and only the numbers stay.

From left to right, the cells are:

Cell What you see When you select it
Sessions The number of Waiting and Working sessions. If any session is Failed, that number is added at the front Sessions card below
Usage (only if turned on) The share of the limit that Claude Code and Codex have used, and the token total counted from a start time Usage card below. Turn the cell on in Appearance
Remote The number of connected servers and registered servers (“Remote 1/2”) To see server connections in the status bar
WSL The state of the WSL distributions you added (Windows only) The same place
Processes “Processes N”. The number of processes Lyra started Processes card below
Memory This computer’s available memory Memory card below
Version The current Lyra version Version card below
Bottom panel button Opens and closes the panel To open and close the bottom panel below

If Lyra cannot read the number of sessions, an unknown mark appears instead of a number, and pointing at it shows Unknown. Lyra does not write 0.

Sessions card

Section titled “Sessions card”

Selecting the sessions cell opens the “Sessions” card. Sessions are grouped by state. The order is Failed, Waiting, Working, Done, with a count next to each title. The Done group is collapsed, so select it to expand it. The Done group also holds Interrupted sessions and Idle sessions that have not had a first turn yet.

  1. Read a session row. A row has the session title, the name of the computer it works on, and its state.
  2. To go to that session, select Open on the row.

An agent that you started directly in a terminal appears in the list marked “Started in a terminal”. That row has no Open button. If Lyra could not read some sessions’ information, you see “Some per-session information could not be read. The count is the value confirmed in the overall summary.” The meaning of the state words is in Status on the Terms page.

On macOS, the number of unread session notices is also put on the app icon. If Lyra could not change it, a notice comes up: “The session indicator on the app icon could not be changed.”

Usage card

Section titled “Usage card”

The usage cell has two cards.

  • Usage: for each agent, the share of each limit (5 hours, Weekly and so on) that has been used, a bar, and the time left until the reset. Lyra reads the value from the last limit record that Codex left in its own session files, and adds the time to it, as in “Value reported by Codex at …”. If the limit has reset since then, the card says the amount left now is unknown. Claude Code leaves no record, so its value is Unknown.
  • Token usage: the Total at the top is counted from a start time, and below it you see “Since …” (or “Since the first record” if it has never been counted again). For each agent and model, one row shows Input, Output, Cache read and Cache write. If an agent does not report cache writes separately (Codex), that value is Unknown. At the end of a row and in Estimated cost, you see a dollar estimate (≈ $…) worked out with the API price list that this version contains. A model that is not on the price list shows Cannot estimate, and a value counted from only part of the usage has a +. The estimate differs from what you actually pay on a subscription plan or through a company gateway.
  1. To count again from now, select Count again under the token card. The start time is saved on this computer, and every open window counts from the same time.

A value Lyra does not know shows as Unknown, not as 0 or —. If the start time cannot be saved, you see “The start time could not be saved on this computer, so counting did not restart. …”.

Processes card

Section titled “Processes card”

Selecting the processes cell opens the “Processes started by Lyra” card. Each process Lyra started, such as an agent or a terminal, has a row with its name and state (Alive, Not observable). If there are none, you see “There are no processes started by Lyra.”

  1. To end a process, select Stop on its row.
  2. Look at “Orphans N” at the bottom of the card. An orphan is a process that Lyra started but that has no owner now, and it is counted separately, not in the cell’s “Processes N”. To clean up, select Clean up orphans.

If Lyra could not read the list, the cell’s name becomes “The list of processes started by Lyra could not be read, open the list”, and the card shows Read again. While writes are blocked, Stop and Clean up orphans cannot be selected.

Memory card

Section titled “Memory card”

The memory cell shows “Available” and the memory this computer can use. If Lyra cannot read this computer’s memory, it shows “Lyra” and the memory the app uses instead. Selecting the cell opens the card.

  • The top shows the available memory and the pressure of this computer (localhost).
  • The “Desktop app” row at the bottom is the memory of the Lyra app’s processes, split into App, Screen and Graphics · helper processes. Terminals, agents, lyra-daemon and lyra-desktop-sidecar are not in this number.
  • If only part of it was measured, you see “Only part of it was measured. Only the app memory that was confirmed is shown.” If Lyra could not read it, the cell’s number shows “—”.

Version card

Section titled “Version card”

The version cell shows the current Lyra version. If a new version exists, a dot and New appear next to the number, and a progress bar appears during an update. Selecting the cell opens the card.

  1. Read Current version, New version and Last checked on the card.
  2. If there is a new version, select Update to start. The steps for reading the confirmation window and continuing are in Update.
  3. To look for a new version again, select Check for the latest version. If this installation is set not to fetch new versions by itself, this button is not there, and you see “This installation does not fetch new versions by itself…”.

When Lyra finds a new version, when an update seems stuck, and when an update finishes, the card opens by itself and closes after 4 seconds. It opens only once for the same event. How to do the same in Settings is in App.

Bottom panel

Section titled “Bottom panel”

The bottom panel is a section that opens just above the status bar. You can use it on every screen, and it opens over the screen without changing the screen’s size. Its name is “Bottom panel”. The first tab is Board, and terminal tabs follow it on the right.

To open and close the bottom panel

Section titled “To open and close the bottom panel”
  1. Select the Open / close the bottom panel button at the far right of the status bar. The first shortcut is Ctrl and the backtick on both macOS and Windows. The shortcut is on the Shortcuts screen.
  2. If the panel is closed and something is waiting for a person, a small dot appears on the button.
  3. To close it, select Close panel at the top right of the panel, or the same button. When you close it, focus returns to where it was before you opened it.
  4. Dragging the top edge of the panel changes its height. Maximize panel makes it larger, and Restore panel size puts it back.

This window remembers whether the panel is open and its height. If it cannot remember, you see “The panel setting could not be saved. Check disk space and folder permissions, then try again.”

To use a terminal in the bottom panel

Section titled “To use a terminal in the bottom panel”

A terminal in the bottom panel runs on this computer (localhost), whatever project you are in.

  1. Select the plus (+) button in the panel’s tab row, and New Terminal opens. Its name is “New Terminal”.
  2. To open another kind, select the down arrow next to the plus button (New terminal or agent) and choose. The list has the terminal kinds, the agents of the profiles you turned on for this computer, Manage agents… and Read again. In a version where Serial can be turned on, if you turned on Serial in Tools in Settings, New Serial is also there. In this version Serial is locked, so it does not appear.
  3. Right-click a terminal tab for a menu (on the keyboard, the menu key or Shift+F10). It has Start fresh (a submenu for choosing a new terminal kind), Split right, Split down, Rename, Copy path, Close split pane (when there is more than one pane), Close other tabs, Close tabs to the left, Close tabs to the right and Close terminal.
  4. You can also close a tab with its close button (named “Close the (tab name) terminal”).

In a version where Serial is turned on, a Serial tab has a different menu. It has only Line settings…, Enter key, the send items, Close other tabs and Close port. For details, see Tabs and Serial.

These notices can appear in the panel.

What you see What it means
“There is a terminal whose start or end result has not been confirmed yet.” Lyra does not yet know the result of opening or closing a terminal. It reads again shortly
An error row and Read again Lyra could not read the list of terminals or agents. Selecting it reads again

While writes are blocked, the panel disables the buttons so you cannot open or close a new terminal.

Words on this screen

Section titled “Words on this screen”

Terms explains what each word means.

Word On this screen
Quick jump The search window in the header bar
Status bar The run status row at the bottom of the window
Bottom panel The section that opens above the status bar
Working · Waiting · Done · Failed · Idle · Unknown The states on the sessions card
Orphan A process counted separately on the processes card
This computer Where the memory card and the bottom panel terminals are
New The new-version mark on the version cell

When something goes wrong

Section titled “When something goes wrong”
What you see What to try
In search, “The search failed. This does not mean nothing was found.” Search again. If it keeps happening, restart Lyra
You open a search row and see “The … can no longer be found.” It was deleted or renamed. Search again
A profile row is “Off” and does not open Turn on the profile in Agents in Settings, then search again
A profile row is “Unavailable” and does not open In Remote in Settings, check that the profile’s server is connected
“—” where a number should be in the status bar It is a value Lyra has not read yet. It does not mean 0. Open the card and read the reason

For developers

Section titled “For developers”

Status and diagnostics covers the path the status bar reads its values from, and Search covers the rules Quick jump uses to find things. The bottom panel’s terminals are in Terminals.
