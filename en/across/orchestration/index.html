Orchestration

About this page

Section titled “About this page”

When a job is big, one agent does not have to do all of it. It can split the work across several Sessions. Think of a building site: the site manager breaks the job up, hands the pieces to foremen and workers, and receives their reports. Lyra passes the work between them, watches the progress and delivers the reports.

The one who splits and hands out the work is an agent, not a person. A person reads the progress on screen, answers what needs a person’s answer, and sets the rules. This page shows where each of those appears on screen. How orchestration works is in the Orchestration guide, and what the engine does is in Orchestration.

The three roles

Section titled “The three roles”

The role names appear on screen in English as Orchestrator, Lead and Worker. A role is not a separate program; it is a place a Session takes. The words “Orchestrator session” on screen mean a Session that holds the Orchestrator role. What each role can start and do is in Structure — who can start whom and Roles in the guide.

Where you see it

Screen What you see More
The Board tab of the bottom panel One table that shows, for each piece of work you handed out, how far each Worker has got To see the board below

To start work

Section titled “To start work”

The screen has no button for handing out work. A person starts a new group from the command line.

  1. In a terminal, run lyra orchestrator start --spec-file <task description file>. --spec-file is required.
  2. Choose which workspace to start in with --workspace <workspace ID>, and which agent to start with --agent <name>.
  3. The Workers or Leads under it are usually started by the agent with lyra worker start.

Who can start a new Orchestrator, and where a new Session stands in the tree, are in New Orchestrator command in the guide. The values you choose in Settings are in Orchestration settings, and the commands are in Command line.

Depth limit

Section titled “Depth limit”

The Depth limit is the value that decides how many levels below an Orchestrator work can be handed down. Only a person changes it, in Depth and roles in the Orchestration settings. When you lower it, the settings screen tells you how many Sessions are running at that depth, and warns you. Who may stand at each depth and which starts are refused are in Structure — who can start whom in the guide, with a picture.

To see the board

Section titled “To see the board”

The picture on this page was taken with sample data.

  1. Select the Open / close the bottom panel button at the far right of the status bar at the bottom of the window. The first shortcut is Ctrl and the backtick (the ~ key at the top left of the keyboard) on both macOS and Windows. If the panel is closed and something is waiting for a person, a small dot appears on the button.
  2. Select the Board tab at the far left of the panel. If a project and a workspace are chosen on the Projects screen, the tab name becomes “Board · (project) · (workspace)”, and only that workspace’s work shows. If something is waiting for a person (Waiting), the tab shows the number.
  3. Each Orchestrator has one table. Selecting the Orchestrator Session name button in the header row opens that Session. Next to the name it says “Orchestrator session”.
  4. Cells are split by kind of work. A row is one piece of work. Each piece of work has a mark for its kind, and the shape of the mark means its state: Waiting, No updates, Working, Done, Not started, Blocked, Failed, Stopped.
  5. Pointing at a mark, or going to it with the keyboard, shows “kind · work name” and the earlier work it waits for. A line is drawn to the earlier work.
  6. Selecting a mark opens the Session that took that work. A mark with no Session that took it cannot be selected.
  7. At the right end of a row there is a button with the name of the Session that took the work, and a one-line note. The notes say:
Note Meaning
Waiting · 3 min It has been waiting for a person for 3 minutes
No news for 3 min There has been no progress news for 3 minutes
3 min ago The last news was 3 minutes ago
Waiting for 2 predecessors It starts when two earlier pieces of work finish
Ready to start It can be handed out now
Process ended · decision needed The program that was doing the work ended, and a decision is needed
Decision needed A decision is needed
No result reported · the turn has ended One turn ended, but no result report came
Approval waiting too long · time, Tool running too long · time It passed the Approval wait limit or the Tool run limit in Settings
  1. Rows are placed in the order of the earlier work they depend on, and a faint row such as “Round 2” marks where the next round starts. Finished work is collapsed as “Finished (n)”, and selecting it expands it. How long Lyra waits before it notes this is set by the Approval wait limit and the Tool run limit in Settings. A changed value applies only after you restart Lyra.
  2. To see the board on its own, select Pop out to a window in the panel. The panel then shows “The board is open in a separate window.”

If there is no work, you see “Select a workspace” or “This workspace has no work being orchestrated”, and “Work assigned to Workers appears here.” If Lyra could not read it, you see “The board could not be read · reason”, and if it read only part, “Some tasks could not be read”.

To read the task graph

Section titled “To read the task graph”

An Orchestrator splits the work into a task graph that has an order. Later work starts only after earlier work ends.

  1. On the Projects screen, choose a Session tab or row, and open the Session info tab in the right panel.
  2. Read Run information below it. The top row is “(Host connection state) · (Session state) · (whether it can be continued)”. Whether it can be continued is one of “Can attach to the current run”, “Can be started and continued” and “Cannot be continued”; if Lyra cannot confirm it, you see “It is not known whether it can be continued.”
  3. “Waiting for approval · (number)” is the number of approvals this Session is waiting for.
  4. In the “Task graph”, the work appears in numbered order. On each row, read the kind of work (Task, Build, Review, Test, Fix, Docs, Decision gate task), the stage, the earlier work, and the run location. The stages are Not started, Ready to start, In progress, Finished, Blocked, Recovering, Failed, Stopped and Removed from the task graph. For work that is blocked or needs a person’s decision, a reason is added under the row. The reason is one of “The recovery budget is used up”, “The result is unknown” and “A person’s decision is needed”.
  5. “Only while connected” and “Keeps going if disconnected” on a row tell you whether that work stops or keeps running when the connection to the server drops.

If this Session is a Worker or a Lead, you see its parent Session’s graph; if it has no parent, you see its own graph. If live updates are unavailable, the reason appears.

To answer a decision gate

Section titled “To answer a decision gate”

A decision gate is a decision point that an Orchestrator puts in front of one piece of work in the graph. It has one question and different choices. Until a person chooses, that work and the work after it cannot start. It is not decided by time passing.

A decision gate does not appear in Inbox, and you cannot choose on screen. You decide by talking to the Orchestrator.

  1. In Session info → Run information, find the “Decision gates” list. A row has a “Decision gate” mark and the question.
  2. Read the note under the row. It is “Before (work) · Open · (n) behind it not started · The Orchestrator session decides”. If it has been decided you see “Decided” with the time, and if it was taken back, “Withdrawn”.
  3. Select the row to expand the “Choices”. The choices are read-only. For a decided gate, the chosen choice shows a time and the others fade.
  4. Select Go to the Orchestrator session. The Orchestrator’s Session opens.
  5. In that terminal a “Talk about the decision gate” field appears, with “> [Decision gate (number)] (question)” already written. Then write which choice you want and select Send. What you wrote and a line break (Enter) are typed into that Session’s terminal.
  6. When the Orchestrator records the person’s answer as exactly the same text as the choice, the gate becomes “Decided” and the blocked work is released.

If the Session you are looking at is that Orchestrator, you see “This session is the Orchestrator session. Speak in this session to decide.” Speak in that Session’s terminal directly.

Sometimes there is no Go to the Orchestrator session, and a sentence about the Orchestrator session appears. That is when the Orchestrator is still opening, is closing, is closed, failed, its start result could not be confirmed, its state has not been read yet or cannot be checked, or it is not in this screen’s Session list. The sentence tells you the reason.

A question that a running Worker asks a person is not a decision gate. A Worker asks its parent Session by message, and if a person’s confirmation is needed, it comes up in Inbox.

To answer approvals and questions

Section titled “To answer approvals and questions”

When a Session that took work needs a person’s confirmation, it comes up in Inbox. Requests are of two kinds, approvals and questions, and a request that cannot be undone has a Cannot be undone mark. The steps for answering are in Inbox.

When the connection drops

Section titled “When the connection drops”

Whether work running on a server keeps running or stops while its connection to the server is down is decided by On disconnect in Settings → Orchestration. Keep running (the first value) keeps work going when it drops, and Stop runs it only while it is connected. For each piece of work, you read which one it is with “Only while connected” and “Keeps going if disconnected” in To read the task graph. How the disconnection itself looks on screen is in When a server connection drops on the Servers and Hosts page.

What these words mean

Section titled “What these words mean”

Terms explains what each word means. The words used on this page are:

Word On this page
Orchestrator · Lead · Worker The three roles a Session takes
Depth limit How many levels work can be handed down below an Orchestrator. The first value is 2
Task graph The order of the work, which you read in run information
Decision gate A place that stops the later work until a person chooses. It is different from Inbox
Board A tab of the bottom panel
Run information The lower part of the Session info tab
Handoff (handoff) Unlike a message, the owner of the work changes
Opening · Active · Closing · Closed · Failed · Failed · Unverified The open state on a Session row and tab. Failed · Unverified is in Failed · Unverified Session
Idle · Working · Retrying · Waiting · Waiting for Workers · Done · Monitoring · Interrupted · Failed · Unknown · No status · Status off The work state on a Session row and tab. If the open state is Failed or Closed, that word shows first

The state of a Session row and tab is also in Read the state on rows and tabs.

When you cannot tell whether it closed

Section titled “When you cannot tell whether it closed”

If you try to close a Session and Lyra cannot confirm that it stopped, it tells you “The session’s close result could not be confirmed.” In that case, try again. If it still cannot be confirmed, a “Close a session that could not be verified?” window says “Its state cannot be confirmed. A process may still be left somewhere.” Close without confirming closes only the session record (or this tab) without checking that the process stopped, and the record keeps “Closed (unverified)”. The next steps are in Failed · Unverified Session.

When something goes wrong

Section titled “When something goes wrong”
What you see What to do
“Select a workspace” on the board Choose a workspace on the Projects screen
“This workspace has no work being orchestrated” on the board The Orchestrator has not handed out any work in this workspace yet
“No updates” or “No news for (time)” on the board Select the Session that took the work and open it
There is no Go to the Orchestrator session on a decision gate row Read the reason sentence under the row. If the Orchestrator is closed, you have to open that Session again
“Live updates are unavailable.” Read the reason and try again. If it keeps happening, see Troubleshooting
Work does not start and you see “The running Worker count has reached its limit.” Wait until some finish, or change Concurrent Worker limit in Settings
