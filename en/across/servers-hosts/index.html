Servers and Hosts

About this page

Section titled “About this page”

This page gathers how a Host (the computer where a Project, a Session or a terminal actually lives) appears on different screens. The Lyra window is on the computer you are sitting at, but the agent may be working on another computer. This page tells you “which computer is my Session running on now?” and “what do I see on screen when the connection to that computer drops?”

How to connect, edit and delete a server is in Settings. The steps for connecting a server for the first time are in Connect a Linux server and Use WSL as a server.

Kinds of Host

Section titled “Kinds of Host”
Kind On screen Description
This computer localhost The computer where you run the Lyra app. In sentences it is called “this computer”.
Server The name you gave the server Another computer you registered and connect to over SSH. It has a row in Remote in Settings.
WSL distribution The distribution name with a wsl mark Windows only. One Linux installed inside this computer. It has no row in the server list, and each distribution gets its own Host.

A Project’s folder is kept separately for each Host, and one Project can span several Hosts.

What runs where

Section titled “What runs where”
Job Where it runs
The Lyra window and screens This computer
Agent programs, terminals, and files on that computer The Host where the Project is
Collecting what happens on a server and passing it to the screen lyra-daemon on this computer

For example, if you register a folder on a server as a Project, the agents of that Project run on the server, and the files are the server’s. This computer handles the window and your input. The server’s lyra-daemon lives under .lyra/daemon/ in the server user’s home, and you do not install Lyra on the server separately.

How Host appears on each screen

Section titled “How Host appears on each screen”
Screen What you see More
Projects · the Explorer’s Project row The Host name at the right end of the row. A server has a connection-state dot before its name; this computer shows only localhost, with no dot. If one Project is on more than one Host, the name appears at the end of the Worktree rows instead of the Project row. Switch the view in the Explorer
Projects · the Explorer’s Host view Each Host has a heading, and its Projects, Worktrees and Sessions sit under it. Switch the view in the Explorer
Projects · the card when you point at a Worktree row, and Session info in the right panel The Host name appears in the Run location row. Read the rows in the Explorer, Session info in the right side panel
Projects · a Session tab Pointing at the tab shows one line: “title · run location (Host name) · open state”.
Projects · the start screen with an input box A chip with the Host name sits next to the agent picker. The chip only shows it; you cannot choose with it.
The Add Project window and the Create Worktree window You choose in the Host field of the Add Project window and in the Host field of the Create Worktree window. Choose a host in Add a Project, Worktree and Workspace
Lyra input box Before you open a new conversation, you choose with the Host chip. Add SSH host… at the end of the list opens Settings. Choose the agent, model, and workspace in the Lyra input box
Home Each row of “Running now” and “Recent projects” has a Host name. Home
Inbox When you expand Show context on a row, the Host name is added at the end. Inbox
Quick jump search (macOS ⌘ K, Windows Ctrl K) The Host name is added at the end of Project and profile result rows.
Run pane If you open a localhost address in a Worktree on a server, you see “This page runs on (Host name), not on this computer”. That address points to your computer, so open it in a browser on that Host.
Settings · Agents The Machines list on the left has one row for each computer. Its name is localhost, a WSL distribution’s name or the server’s name. Settings
The status bar at the bottom There is a Remote cell that shows the number of server connections. See To see server connections in the status bar below

The fields where you choose a Host (Add Project, Create Worktree, the Lyra input box, Token profiling) and Remote and Agents in Settings all show the same machines: this computer, the servers you registered and the WSL distributions you added. Agents in Settings also lists, at the end, a server you have never connected to. You cannot choose a Host left behind by a server you deleted, or a distribution you have not added. While Lyra has not finished reading the server list, it shows all servers’ Hosts without dropping any.

Connection-state dots and words

Section titled “Connection-state dots and words”

The dot before a server’s name shows the connection state right now. Pointing at the dot shows “server name · state”.

Dot Word in the Explorer description Meaning
A filled green dot Connected It is connected now
A blinking dot Connecting You selected Connect and Lyra is waiting for an answer
A grey dot Disconnected The connection dropped or could not be made
An empty grey ring Unknown Lyra has not checked the connection state yet. This is not a failure

If a Host is not in the list, the Explorer description shows “Unknown”. In Remote in Settings and in the status bar, the same states appear as Connected, Disconnected, Not checked yet and Connecting.

A WSL distribution’s Host has, instead of a dot, a wsl mark with a status dot. In the title of the Explorer’s Host view, it appears as wsl · distribution name, so you can tell two distributions apart.

To see server connections in the status bar

Section titled “To see server connections in the status bar”
  1. Select the Remote cell at the right of the status bar at the bottom of the window. The cell shows the number of connected servers and the number of registered servers, such as “Remote 1/2”. If the window is narrower than 1050 px, the word “Remote” is dropped and only the numbers stay.
  2. The card that opens is titled Remote hosts. Next to the title there is a dot for each server, and “Connected 1 / 2” is written.
  3. For each server that has a Host, read one row with its name and state (Connected, Disconnected, Not checked yet, Connecting).
  4. If a Session tab is in front on the Projects screen, one more row at the bottom of the card shows that Session’s Host name and state. If that Session’s Host is a WSL distribution, this row does not appear. If Lyra has not yet confirmed the Host, you see “The run location of the selected session has not been confirmed yet.”
  5. To connect or edit a server, select Manage hosts… under the card. Remote in Settings opens. Press Esc to close the card.

If Lyra does not yet know even one server’s connection state, or could not read the whole server list, the number shows “—” and the card says “The registered server list or the connection state could not be fully checked.” Lyra does not count numbers when it does not know.

The WSL cell on Windows

Section titled “The WSL cell on Windows”

If this computer is Windows, WSL is available and you have added at least one distribution, there is one more cell on the same row: WSL.

  1. Select the WSL cell.
  2. For each distribution you added, read its name and state (Stopped, Starting, Running, Distribution stopped, Not confirmed).
  3. To start one, select Open WSL settings under the card. You cannot start one from this card. Lyra does not stop a distribution.

If this computer is not Windows, or WSL is locked in this build, this cell is not there.

When a server connection drops

Section titled “When a server connection drops”

When the SSH connection to a server drops, the screen changes like this.

  1. The Remote number in the status bar goes down, and that server’s row in the card becomes Disconnected. The dot before the server name in the Explorer turns grey.
  2. The Explorer dims that server’s Projects and blocks menus that need the server, with the reason. If the connection stays down for long, it hides the Projects from the list and tells you in one line below. When the connection returns, it reads the list again. The details and the buttons to select are in When a server is disconnected in the Explorer.
  3. Terminals running on the server stop showing output. If a terminal that was showing output cannot re-attach within 4 seconds, a cover hides the terminal.
  4. To choose a server again, you have to connect first. For a server you have not connected to, the list says “Connect to (server name), then select a folder.”
  5. Whether work already running on the server keeps running or stops while disconnected is decided by On disconnect in the Orchestration settings. The default is Keep running. See When the connection drops on the Orchestration page.

To clear the cover on a terminal of a disconnected server

Section titled “To clear the cover on a terminal of a disconnected server”
  1. Read the cover’s title, “The SSH connection to server “name” was lost”. The explanation is “This terminal’s output has stopped. When the connection is back, the terminal re-attaches by itself. Reconnect now, or check this server’s connection in Remote settings.”
  2. If you wait, the terminal re-attaches by itself when the connection returns. To re-attach right away, select Reconnect. If the window is read-only, or it is already reconnecting, you cannot select this button. If Lyra cannot connect, the reason appears under the button.
  3. To check the server’s connection yourself, select Open Remote settings. Remote in Settings opens with that server chosen.

If the server’s connection has not dropped and only the output has been cut, the title is “Terminal output was lost” and the only button is Reconnect. If every attempt to re-attach failed, the cover appears at once without waiting 4 seconds, and the title is “This terminal cannot be used” with the reason.

When you restart lyra-daemon on this computer

Section titled “When you restart lyra-daemon on this computer”

lyra-daemon (Lyra’s engine, which starts and keeps agent and terminal processes) runs behind the screen on this computer and on servers. If this computer’s lyra-daemon does not answer, the notices show “This computer’s lyra-daemon is not answering”, and the button Restart lyra-daemon in the same notice restarts it. When a newer version exists, an Update lyra-daemon button appears inside Details on this computer’s card in Settings → Agents, and it opens the same confirmation window.

  1. Select the button. The window “Restart this computer’s lyra-daemon?” tells you the running version, the version bundled with the app, and the number of Sessions and standalone terminals that will end. If Lyra cannot read a number, it shows “unknown”.
  2. The window says this computer’s Sessions and standalone terminals will end. To continue, select Restart lyra-daemon; to stop, select Cancel.
  3. When the restart finishes, the ended Sessions stay in the list. Opening one continues the conversation. Check whether there is unfinished work.

Agent work running on a server keeps running even if you restart this computer’s lyra-daemon. You can restart only this computer’s lyra-daemon.

What these words mean

Section titled “What these words mean”

Terms explains what each word means. The words used on this page are:

Word On this page
Host Where work runs. It appears as a name or a dot on each screen
This computer · localhost “This computer” in sentences, localhost on labels
Server What the connection-state dot and the Remote cell in the status bar show
WSL distribution A Host placed under this computer with no server row. The WSL cell in the status bar
lyra-daemon On a server, Lyra starts it when you connect
Project Sessions and workspaces sit under it
Workspace A row in the Explorer is one of primary, a worktree, or a Workspace. A worktree Lyra made and one that was already in Git look the same
primary The row that stands for the Git repository’s original folder
Worktree One kind of workspace
Workspace The workspace of a folder that is not Git
Session Appears under a workspace row, and opens as a tab when you select it

A Project is the outermost, then the workspace inside it, and the Session is innermost. Think of a chest of drawers: a Project is one drawer, a workspace is a box inside that drawer, and a Session is one job you do inside the box. The order for creating them is in First Session.

When something goes wrong

Section titled “When something goes wrong”
What you see What to do
A server row is Disconnected In Remote in Settings, expand the server row, read the reason, and select Connect. If it keeps happening, see When server sign-in fails or times out
The cover on a terminal, “The SSH connection to server “name” was lost” Wait, or select Reconnect. If that does not work, go to Open Remote settings
“—” on Remote in the status bar Read each server’s state in the card. For a server Lyra does not know, select Connect in Remote in Settings
“Connect to (server name), then select a folder.” Choosing that Host tries to connect. If it fails, the reason appears in the window. See Add a Project and Lyra input box
“Removed from the server “name” list” in the Explorer That server was deleted from the server list. See When a server is disconnected in the Explorer
You try to delete a record and see “…cannot be stopped from this computer, and the record cannot be deleted” The Sessions and terminals of a disconnected server cannot be stopped from this computer. Reconnect the server in Remote in Settings, or add it again, then delete
