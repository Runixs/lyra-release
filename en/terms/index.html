Terms

About this page

Section titled “About this page”

This page gathers the meanings of the words that appear in the Lyra window in one place. The words are written exactly as the screen shows them, for example Working and Waiting. Each word has links to the screens where it appears.

When you meet a word you do not know on another page, click its link and you come here. Open the group below where the word is likely to be.

  1. Computers and connections: where work runs, and the words attached to it
  2. Projects and workspaces: the containers that hold work
  3. Sessions and agents: the work you do with an agent, and the words that set it
  4. Status: words that tell how a session, a connection, or a workspace is now
  5. Roles and orchestration: words for splitting up and handing off work
  6. Inbox and notices: requests and notices that come to a person
  7. Workflows: repeated work written down as steps
  8. Issues and connections: issues in Jira and GitHub
  9. Window and layout: the parts of the window and the layout of tabs
  10. Settings words: words on the Settings screens
  11. Tokens and cache: words for reading usage

Computers and connections

Section titled “Computers and connections”

This computer

Section titled “This computer”

The computer where you started the Lyra app. In sentences it is called “this computer”, and on labels it is written localhost. In the Agents and Agent skills screens of Settings, this computer is named localhost, and its memory field shows the free memory of this computer.

Appears in: Servers and Hosts, Settings, Agents, Agent skills, Top and bottom of the window

Host

Section titled “Host”

The computer where work actually runs. It can be this computer, a server, or a WSL distribution. Which Host the work runs on is shown by the name or the dot at the end of a row.

Appears in: Servers and Hosts, Home, Add a Project, Explorer, Lyra input box

Server

Section titled “Server”

Another computer you registered by connecting over SSH. To run agents on a server, the server also needs lyra-daemon. Lyra uploads it when you connect to the server, so you do not install Lyra there yourself.

Appears in: Servers and Hosts, Remote, Settings

Remote

Section titled “Remote”

The word for a server’s connection. In Settings it is the name of the screen where you register servers. In the status bar at the bottom it is the name of the field that shows the number of connected servers and the number of registered servers, like “Remote 1/2”.

Appears in: Remote, Servers and Hosts, Top and bottom of the window

Distribution

Section titled “Distribution”

One Linux installed inside Windows (it runs through a feature called WSL). It sits under this computer, without a server row. In Settings it is called a WSL distribution.

Appears in: WSL, Servers and Hosts

lyra-daemon

Section titled “lyra-daemon”

Lyra’s execution engine, which starts and keeps agent and terminal processes. There is one on each computer where work runs.

Appears in: Servers and Hosts, Agents, Remote, WSL, App

Alias / Nickname

Section titled “Alias / Nickname”

The name by which you refer to a connection. For a server it is the Host alias, the server name you pick from ~/.ssh/config. For a Jira or GitHub connection it is the nickname you give that connection.

Appears in: Remote, Issue connections

Authentication

Section titled “Authentication”

How you sign in to a server. On a connection card there is also Authentication method, which names how you sign in to an issue service.

Appears in: Remote, Issue connections

One-time code

Section titled “One-time code”

A code that a server asks for once when you sign in (also called OTP). It is a number that cannot be used a second time.

Appears in: Remote

Projects and workspaces

Section titled “Projects and workspaces”

Project

Section titled “Project”

A repository or folder you registered in Lyra. In menu headings it is written Project. Sessions and workspaces sit below it. The “Recent projects” on Home and the Project in the Workflow run dialog are this too.

Appears in: Projects, Add a Project, Explorer, Project settings, Home

Workspaces

Section titled “Workspaces”

The folders inside a Project that divide the work. For a Git repository they are Worktrees, and for a folder that is not Git they are Workspaces.

Appears in: Servers and Hosts, Worktree and Workspace, Start work, General, Edit

Worktree

Section titled “Worktree”

A Git feature that lets each branch (a separate line of work) of the same Git repository use its own folder. If you give “Fix the checkout screen” and “Fix the login error” to two different Worktrees, the two agents do not overwrite each other’s files.

Appears in: Worktree and Workspace, Explorer, Project settings, Right side panel, Servers and Hosts

Workspace

Section titled “Workspace”

The workspace of a folder that is not Git. Several Workspaces can share one folder. It is not the same as the Lyra workspace of the Lyra screen.

Appears in: Worktree and Workspace, Explorer, Add a Project, Servers and Hosts

primary

Section titled “primary”

A mark that points at the original folder of a Git project. It sits on a row in the Explorer. It must stay as long as the project exists, so it has no delete menu.

Appears in: Explorer, Worktree and Workspace, Servers and Hosts

Setup Script

Section titled “Setup Script”

A setup command that runs after a workspace is created. You write it in .lyra/config.yaml in the project folder. If a command is new or differs from what you allowed before, the Run Setup Script dialog asks first.

Appears in: Worktree and Workspace, Project settings

Sessions and agents

Section titled “Sessions and agents”

Session

Section titled “Session”

One task with one agent. In menu headings it is written Session. It appears below a workspace row, and when you click it, it opens as a tab. If it has no name, it appears as “Untitled session”.

Appears in: Open a Session, Explorer, Home, Start work, Servers and Hosts

Agents

Section titled “Agents”

The programs that do work for you. Claude Code, Codex, and OpenCode installed on this computer are available, and their names appear in English on the screen. The Agent node of a Workflow runs one session with an agent.

Appears in: Profiles and agents, Agents, Lyra input box

Profile

Section titled “Profile”

A setting that records which agent to run on this computer and how. Each computer has its own, and it holds no role or instructions. In Settings, one agent row is one Profile. There is a default Profile and there are copied Profiles.

Appears in: Profiles and agents, Agents, Lyra input box, Settings

Model

Section titled “Model”

The AI model an agent uses. You choose it when you open a Session.

Appears in: Profiles and agents, Lyra input box

Thinking depth

Section titled “Thinking depth”

A value that sets how deeply the agent thinks things through. In Workflows it is called Reasoning.

Appears in: Profiles and agents, Lyra input box

Permission mode

Section titled “Permission mode”

A value that sets how much the agent asks a person for permission before it works.

Appears in: Lyra input box

Pre-run command

Section titled “Pre-run command”

A command that runs, on the computer where the agent will run, just before the agent starts.

Appears in: Profiles and agents, Agents

Profile test

Section titled “Profile test”

Trying out the pre-run command, the agent start, and the model check before you save a Profile.

Appears in: Profiles and agents, Agents

Prompt cache

Section titled “Prompt cache”

A mechanism where the agent service remembers the early part of a conversation for a while. It disappears over time. The timer at the end of a Claude Code Session row counts down the remaining time, and when it ends, the next message sends the whole context again without a cache. Claude Code decides how long it is kept, and you choose in Settings › Agents, for each Profile, whether the timer shows with Cache timer.

Appears in: Open a Session, Agents

Skills

Section titled “Skills”

A bundle of manuals that agents read.

Appears in: Agent skills

Shared folder

Section titled “Shared folder”

The folder where the skills of one computer are gathered in one place.

Appears in: Agent skills

Link

Section titled “Link”

The connection that makes an agent’s skills folder point to the shared folder.

Appears in: Agent skills

Capability

Section titled “Capability”

A tab of the right panel that shows what features (skills, MCP servers, plugins, subagents, commands) are in the workspace settings files of the Claude Code session in front. It does not mean the feature is on right now; it means it is in the settings files.

Appears in: Right side panel

Lyra conversation

Section titled “Lyra conversation”

A session opened on the Lyra screen. What the agent did appears as a chain of cards.

Appears in: Lyra

Lyra workspace

Section titled “Lyra workspace”

The folder a conversation on the Lyra screen works in. It is kept for later conversations, and it has nothing to do with a Project in Projects. Its name is similar to the Workspace on the Projects screen, but it is a different thing.

Appears in: Lyra, Lyra input box

Card

Section titled “Card”

One piece in the chain shown in a conversation on the Lyra screen. Text, tool calls, changed files, approvals, and questions appear as cards.

Appears in: Lyra

Card view

Section titled “Card view”

A feature that shows a terminal session’s conversation as cards. It is locked in this version and cannot be turned on.

Appears in: General

Run pane

Section titled “Run pane”

A pane for seeing results the agent made and web pages or files a person opened. On the Lyra screen it opens beside the conversation, and on the Projects screen it opens as a viewer tab.

Appears in: Run pane, Lyra

Status

Section titled “Status”

A Session’s state has two layers. First look at the open state, and if the open state is Active, look at the work state. If the open state is Failed or Closed, that word shows first; otherwise the work state shows. A Session with its status display turned off always shows Status off. State names are written in English as they are.

Work status

Section titled “Work status”

What the Session is doing now. From Idle below to Status off are the work states.

Idle

Section titled “Idle”

The agent was started, but there is no first turn yet (a turn is one unit of work by the agent).

Working

Section titled “Working”

It is working.

Retrying

Section titled “Retrying”

It is retrying a model call while it works.

Waiting

Section titled “Waiting”

It waits for a person’s answer or approval. This is a different number from the number of Inbox requests. Inbox requests are approvals and questions that seek an answer, and Waiting is Sessions that wait for a person.

Waiting for Workers

Section titled “Waiting for Workers”

It is explicitly waiting for the Workers it handed work to to finish. The name of what it waits for shows with it.

Done

Section titled “Done”

It finished one turn. In the marks on the board, the same word means the handed-off work is finished.

Monitoring

Section titled “Monitoring”

The turn ended, but a background shell the agent started is still running.

Interrupted

Section titled “Interrupted”

A turn that a person stopped. It is not a failure.

Failed

Section titled “Failed”

An error occurred. It shows in red. As an open state, it means the session could not be started or continued. Workflow runs use the same word.

Unknown

Section titled “Unknown”

The state could not be read. Lyra does not guess another state.

No status

Section titled “No status”

An agent that cannot send its state has not received a state yet.

Status off

Section titled “Status off”

This Session’s status display is turned off.

Open state

Section titled “Open state”

Whether the Session is open. From Opening below to Failed · Unverified.

Opening

Section titled “Opening”

It is opening.

Active

Section titled “Active”

It is open. The work state shows then.

Closing

Section titled “Closing”

It is closing.

Closed

Section titled “Closed”

It is closed. The row stays in the list.

Failed · Unverified

Section titled “Failed · Unverified”

The start is known to have failed, but it could not be confirmed whether the process that started first has stopped. See Failed · Unverified Session.

Appears in (all the states): Home, Lyra, Explorer, Open a Session, Start work, Run screen, Orchestration

Connected

Section titled “Connected”

It is connected to the server now.

Disconnected

Section titled “Disconnected”

The connection to the server was lost, or it could not connect.

Connecting

Section titled “Connecting”

It is waiting for an answer to connect to the server. Then the current step, such as SSH sign-in, Check version, or Install, appears below the server row. The steps are in Steps shown while connecting.

Not checked yet

Section titled “Not checked yet”

A state that has not been read or confirmed yet. It is not a failure. This word is used for a server’s connection state, for an issue connection that has never been read or could not be read, and for a version that has not been read yet.

Appears in (connection states): Servers and Hosts, Remote, Connections in Issues, App

Creating

Section titled “Creating”

A workspace is being created.

Preparing

Section titled “Preparing”

A workspace is being set up after it was created.

Ready

Section titled “Ready”

The workspace is ready to use.

Setup failed

Section titled “Setup failed”

Creating or setting up the workspace failed. A half-made workspace stays as it is.

Partly set up

Section titled “Partly set up”

The setup of the workspace was not completed.

Appears in (setup states): Worktree and Workspace

Alive

Section titled “Alive”

On a process card, the process is running.

Not observable

Section titled “Not observable”

On a process card, the state of the process could not be read. The row shows the time it was last confirmed.

Appears in (process states): Top and bottom of the window

Roles and orchestration

Section titled “Roles and orchestration”

Orchestrator

Section titled “Orchestrator”

The side that splits up work. Any Session can take this role.

Lead

Section titled “Lead”

The side that takes work under an Orchestrator or another Lead and can start Workers in turn.

Worker

Section titled “Worker”

The side that does only the work it was given. It is a role that a Session takes.

Appears in (the three roles): Orchestration, Settings › Orchestration

Depth limit

Section titled “Depth limit”

The number of levels work can be handed down under an Orchestrator. It is also the depth of the session tree that can be newly started. The initial value is 2, and Sessions already running keep running even if you lower the limit.

Appears in: Orchestration, Settings › Orchestration

Task DAG

Section titled “Task DAG”

Work split into pieces, with their order written down. Only the work whose earlier work has finished is handed out.

Appears in: Orchestration

Decision gate

Section titled “Decision gate”

A decision point that does not start later work until it is decided. The screen says “The Orchestrator session decides”, and the person tells that session so that it decides. It is different from an Inbox question, which stops only one Worker.

Appears in: Orchestration

Board

Section titled “Board”

A tab of the bottom panel that shows the progress of handed-off work in one table for each Orchestrator.

Appears in: Orchestration, Top and bottom of the window

Run information

Section titled “Run information”

The lower part of the Session information tab. It shows the state it continues in, the conditions it is waiting on, the Task DAG, and decision gates.

Appears in: Orchestration, Right side panel

Handoff

Section titled “Handoff”

Passing the ownership of one task to another Session (handoff). The Session that receives it stays where it is and becomes the parent of the Worker that does the work. Unlike a message, the owner changes.

Appears in: Orchestration, Settings › Orchestration

Watching

Section titled “Watching”

A group in the Orchestration settings that sets when to tell about a Session that seems stuck.

Appears in: Settings › Orchestration

Recovery budget

Section titled “Recovery budget”

The limit on the number and time of the attempts Lyra makes to recover from a temporary error by typing “continue” into the same conversation. When it is used up, Lyra tells the Session that handed out the work once and does not try any more. A sign-in error is reported at once.

Appears in: Settings › Orchestration

Inbox and notices

Section titled “Inbox and notices”

Inbox

Section titled “Inbox”

A mailbox where things pile up that an agent must ask a person. The agent waits until you answer. The number of requests to answer appears on the button in the left rail.

Appears in: Inbox, Top and bottom of the window

Approval

Section titled “Approval”

A request that asks permission for what the agent is about to do. You answer with Approve, Reject, or Modify. In a Workflow, it waits when you have set a step to need a person’s approval before it starts.

Appears in: Inbox, Home, Waiting runs

Question

Section titled “Question”

A request where the agent gives choices and asks for an answer. You answer by choosing a choice or Enter your own. A Workflow’s question is in the agent’s terminal, so you answer it in the terminal.

Appears in: Inbox, Home, Waiting runs

Decision

Section titled “Decision”

A request that comes to a person when a Workflow step failed and no retries are left.

Appears in: Inbox, Waiting runs

Check

Section titled “Check”

A request that comes to a person when an agent’s turn in a Workflow ended without a completion report.

Appears in: Inbox, Waiting runs

Pending only

Section titled “Pending only”

A tab in the Inbox list that shows only the requests not yet answered. It is the initial state.

Appears in: Inbox

All

Section titled “All”

A tab in the Inbox list that shows all requests, including the ones already answered.

Appears in: Inbox

While you were away

Section titled “While you were away”

The group of requests waiting for an answer in the Inbox list. The count is next to the title.

Appears in: Inbox

Earlier

Section titled “Earlier”

The group of requests already handled in the Inbox list. It appears in the All tab.

Appears in: Inbox

Show context

Section titled “Show context”

A button that expands what the agent is about to run.

Appears in: Inbox

Cannot be undone

Section titled “Cannot be undone”

A mark on something that cannot be undone once it is done.

Appears in: Inbox, Home

Notices

Section titled “Notices”

Things the app must tell a person, such as a Session stopped, a server connection was lost, or an agent finished a turn. They gather in the bell at the right end of the header. Approvals and questions that seek an answer are Inbox requests, not notices.

Appears in: Notice list, Top and bottom of the window

Current problems

Section titled “Current problems”

The group of problems confirmed now in the notice list.

Appears in: Notice list

Past notifications

Section titled “Past notifications”

The group of things that already happened in the notice list.

Appears in: Notice list

N notices with the same cause

Section titled “N notices with the same cause”

When notices with the same cause repeat within a minute, they are folded into one row with a count.
