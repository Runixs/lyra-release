Lyra input box

The input box is one card attached below the conversation. The top row has buttons to choose the agent, the model, the thinking depth, and the workspace. In the middle is the field where you write, and the bottom row has the permission mode and the send button.

The input box in this version

Section titled “The input box in this version”

Conversations on the Lyra screen are paused in this version (see the first part of the Lyra screen), so the input box of a Lyra conversation is locked like this.

  • The writing field is blocked and says “Conversations on the Lyra screen are paused in this version.”
  • Send cannot be clicked.
  • Instead of the buttons for the agent, model, and workspace, you see a one-line summary (agent · model · workspace) and a lock. The explanation is “After sending, it is fixed to this conversation.”
  • The @ file list and the / command list do not open.
  • The thinking depth and permission mode buttons are not blocked. But because you cannot send, the values you choose are not used.
  • If an approval or a question is above the input box, it says “Answer the request above first” and the field is blocked.

The explanation below is for the input box when Lyra conversations are turned on again. The same input box is used when you see a Claude terminal session as cards on the Projects screen, but it is not paused there.

Send a message

Section titled “Send a message”
  1. In the writing field (“Ask Lyra…”, or “Keep talking…” when you continue), write your request.
  2. Press Enter or click Send. To start a new line, press Shift+Enter. An Enter that only confirms characters in an input method such as Korean does not send.
  3. While it is sending, you see the agent working, and a Stop the response (Esc) button appears. Click it or press Esc to stop.

When you cannot send, a reason appears.

Sentence you see Meaning
“Write what you want to send.” The field is empty
“A message can be up to 16,384 bytes in UTF-8.” It is too long
“Choose a workspace.” · “Choose a profile.” You did not choose one in a new conversation
“Sending.” What you sent before has not finished

If it cannot be sent, “It could not be sent. What you wrote is still there.” and Send again appear. If Lyra does not know whether it was sent, “It could not be confirmed whether it was sent. It will not be sent again automatically.” and Check again appear. The field grows with the number of lines, and Expand and Shrink open it even larger.

Choose the agent, model, and workspace

Section titled “Choose the agent, model, and workspace”

You choose only before the first message. After sending, it is fixed to the one-line summary above.

  1. Click Choose an agent. A list of the profiles you can use in this workspace (names that say which agent to call and how) appears. An agent that is not Claude cannot be clicked, with the reason “Conversations on the Lyra screen can use only Claude for now. Use this agent in a project’s terminal tab.” If the list is empty, it says “No agent is available in this workspace.”
  2. Click Choose a model. Choose Default or a model the agent read. At the top of the list, “Model list read at” appears, and models written in the settings file are shown as a separate group. If the model list cannot be read, “The model list could not be read. It opens with the default model.” and Read again appear.
  3. Click Host to choose which computer to open it on. This computer is localhost. Add SSH host… at the end of the list opens the Settings screen.
  4. Click Choose a workspace to choose one of that host’s recent workspaces, or choose a folder with Add another workspace….

Enter text in the search field inside the list to narrow it. If there is no workspace at all, it says “Add a workspace to open a conversation in.” If what you can choose could not be read, the reason appears.

Choose the thinking depth

Section titled “Choose the thinking depth”
  1. Click Choose thinking depth.
  2. Choose one. The list depends on the model.
Level Description
default Follows the agent’s own setting
low Quick answers · short questions
medium Everyday work
high Editing several files · debugging
xhigh Long tasks · hard design
max Deepest · slowest and uses the most tokens

For an agent that is not Claude, it says “This agent does not support choosing a thinking depth”, and if Lyra does not know which levels the model supports, “The thinking depths this model supports could not be confirmed”. If you change it in an open conversation, it is marked “Applies from the next message”. When you point at the button, the shortcut appears.

Choose the permission mode

Section titled “Choose the permission mode”
  1. Click the permission mode button in the bottom row.
  2. Choose one.
Mode Description
Ask according to my Claude settings Asks about actions that my Claude settings or hooks do not allow
Auto-accept edits Edits files directly. Asks about other actions according to my Claude settings
Plan first Reads and only makes a plan. Edits once you approve the plan
No permission limits Skips the permission checks of Claude Code. Company policy and tool limits still apply

If Lyra cannot confirm the result of the change, “The result of the change could not be confirmed. Start in a new conversation” appears.

Use commands

Section titled “Use commands”
  1. Type / in the field. The command list opens beside the field.
  2. Narrow it by name or description, move with ↑↓, and choose with Enter (or Tab). Close it with Esc.

Only a message that is just “/command as one word” runs as a command. A / inside a sentence is normally ordinary text.

Command What it does
/new · /clear Opens an empty conversation in the same location with the same model. The earlier conversation remains
/model · /agent · /workspace · /effort Open the matching pick list
/permissions Choose the permission mode
/rename Changes the name of the conversation
/resume Opens an earlier conversation
/stop Stops the response and the work
/usage · /cost Show usage and cost. If the values were not passed along, Lyra tells you to check /usage in the terminal
/help · /status Show the command help and the state of the conversation (conversation ID, agent, model, thinking depth, workspace, state)

Besides these, the commands and skills that Claude Code has appear with their source (default command, project, user, plugin, MCP, and so on). If you put one in the input box and send it, Claude Code runs it. A command you cannot use now cannot be clicked, and it gives the reason. Before the conversation starts, it says “Start a conversation to load its Claude Code commands and skills.”

Add a file

Section titled “Add a file”
  1. Type @ in the field. The list of files in this workspace appears.
  2. Keep typing a path to narrow it.
  3. Choose with ↑↓ and Enter, and the file name goes into the text.

If the file list cannot be read, it says “The file list could not be read.”

See the context and the cache

Section titled “See the context and the cache”

In the bottom row there is a Context mark that shows how full the conversation is, and a cache mark. When the context is nearly full, “Context is nearly full. You can start a new conversation.” and Start new conversation appear. For the cache (which saves the cost of reading again when you continue), the “Cache time remaining” gets shorter, and Keep warm extends the time. If you send to a conversation whose cache has expired, the “Conversation cache expired” window asks you to choose one of Continue as is, Compact, then continue, New conversation from summary, or Cancel.

Words on this screen

Section titled “Words on this screen”

See what each word means in Terms.

Word On this screen
Profile · Agents The list for choosing the agent that takes the conversation
Thinking depth How deeply the agent thinks
Permission mode How much the agent asks for permission
Lyra workspace · Host The folder and the computer where the conversation works

When it does not work

Section titled “When it does not work”
What you see What to do
The writing field is blocked Lyra conversations are paused in this version. If an approval or a question is waiting, answer it first
The model list could not be read Click Read again. Check the agent run settings
It could not be sent What you wrote is still there, so click Send again
It keeps failing See Troubleshooting
