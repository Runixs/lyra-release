Run screen

The Run screen is where you watch one run, one time a Workflow was run. In one place you see which node is working, where it failed, and what the agent left.

You open the Run screen from these places.

  • The state mark on a row of the list on the Workflows screen, or a row of Recent runs on the right
  • The Recent runs tab of a saved Workflow screen
  • Right after you start a run with Run now
  • Open run in the Inbox (see Workflow requests)
  • Right after you use Start with a Workflow in Start work

While a run is going, the screen is read again by itself every 2 seconds. It does not read while this screen is not visible.

This picture was taken with sample data.

How the screen is put together

Section titled “How the screen is put together”
Place Contents
Top The run header: the issue key or the run name, the state mark, Run information, and Stop run if it is going
Middle The main area. At the front is the Graph tab, followed by tabs for files, outputs, and workspaces you opened
Above the graph A band: what is waiting for my answer, and the result of a finished run
Bottom The session panel. You see the agent’s terminal of a node
Side panel on the right Three tabs: Run log, Evidence, Node

State marks

Section titled “State marks”

Runs and nodes carry a state mark. The marks mean this.

Mark Meaning
Not started It has not started yet. Sometimes a reason is added: “Not started · Waiting for upstream”, “Not started · Waiting to start”, “Not started · Worker slot”, “Not started · Same folder”
Starting · Checking The engine is starting the step, or is checking the state of the session
Working The agent is working
Waiting It is waiting for a person. A reason is added: “Waiting · approval needed”, “Waiting · decision needed”, “Waiting · needs a person’s check”, “Waiting · needs an answer”
Idle The session has not started its first turn yet
Interrupted A turn a person stopped
Done It finished
Failed It failed
Stopped It stopped
Skipped It was not done this time (nodes only)
Unknown The state could not be confirmed

A mark never tells you by color alone; it always carries text.

Read the header and stop a run

Section titled “Read the header and stop a run”
  1. In the top row, read the issue key (the run name if there is no issue) and the state mark. If you click the issue key, the page of that issue opens in a browser.
  2. In the row below, read the Workflow name, the connection mark, the reason it started (“Started because it was assigned to me” or “Run manually”), and the time it took.
  3. If you click Run information, a window shows the issue, the Workflow, the Run ID (with a Copy ID button), the connection, the start, and the start time. A value that is not known is “Unconfirmed”.
  4. To stop a run that is going, click Stop run. It cannot be clicked when writing is blocked.

When you stop a run, the state mark changes to Stopped. If it cannot be stopped, the reason appears below the header.

If the run cannot be read anew, the header says “The latest information for … could not be read. The state and information above are what was last read.” and the state mark changes to something like “Last checked · Done”. If you click Open problem log, you go to the problem log in Settings. At that time the buttons that go to the Inbox also cannot be clicked.

Read the graph

Section titled “Read the graph”

The graph is a picture of nodes wired together with lines. A node card has a name, a kind, and a state mark, and below it a Trigger shows the issue key and the others show the time they took. If there are outputs, a count mark is added. After the last nodes there is an End mark.

  • When a step fails, the line that sends it back to an earlier node is drawn with the marks “Sent back on failure” and “Up to N”. A line that sends it back because approval was denied is written “Deny”.
  • The line in front of a step that is waiting for approval carries “Approval needed”.
  • If you click a node or press Enter, the Node tab of the side panel opens.
  • With the tools at the lower left, you Zoom out, Zoom in, Fit the whole graph, and change the direction (Left → right · Top → bottom).

Use the node menu

Section titled “Use the node menu”
  1. Click ⋯ on a node card (the right mouse button or Shift+F10 also works) to open the menu.
  2. Choose an item.
Item What it does
View details Opens the Node tab in the side panel
View terminal Opens the session panel and shows that node’s terminal
View outputs Goes to the output list of the Node tab
View evidence Goes to the Evidence part of the Node tab
View workspace Opens that node’s workspace tab in the main area
Copy session ID Copies the session ID

What does not exist yet is dimmed, with a reason: “This node has no session yet”, “This node has no outputs yet”, “This node has no evidence records yet”, and “This node has no workspace yet”.

See one node in detail

Section titled “See one node in detail”
  1. Click a node, or choose View details in the menu.
  2. The Node · name tab of the side panel opens. Before you choose a node, this tab cannot be clicked.

At the top of the tab are the node name, the kind, the state mark, and the two part buttons Details · Evidence. Details shows these.

  • Show in session panel: opens this node’s terminal in the session panel.
  • If the state has a reason, it appears on one line.
  • Session: the state of the session. If the session closed or the turn ended, a time is added.
  • Attempt: “Attempt 2 / 3” · “1 send-back left” · “… started” · the time it took.
  • Workspace: the name of the workspace this node worked in.
  • Comment: the comment an Agent node left on the issue. If there is one, Open the comment left; if not, “No comments yet”.
  • Outputs: the results the node left. See Open an output below.
  • Changed files: files that changed in the workspace. If you click one, a comparison tab opens in the main area. If there are none, it says “No changed files”. Open workspace opens the workspace tab.
  • Attempt history (when there is more than one attempt): each attempt shows its state and start time. It tells you why it was done again: “The … step failed, so it was sent back.”, “A later step failed, so it was sent back to this step.”, “Approval was denied, so it came back to this step.” View terminal on a row opens the session of that attempt.

When a step fails, the same step is done again as Attempt 2 and Attempt 3.

See a session terminal

Section titled “See a session terminal”

The session panel is below the graph. When it is folded, “Session panel” and the counts by state (for example “1 Working”) appear on one line.

  1. Click the terminal button in the top row (“Toggle session panel”) or the folded row to open it.
  2. In the “Sessions” list on the left, choose a node. Each row has the node name, the agent, the session state, and the time it took, and you move with the up and down arrows, Home, and End.
  3. On the right, the terminal of that node appears. It is the same session as the agent, so you can type into it directly.

The buttons at the top of the panel are these.

Button What it does
Maximize (“Maximize or restore session panel”) Makes the panel larger or brings it back
Close (“Close session panel”) Folds the panel
Show current attempt Goes back to the newest attempt when you are viewing an earlier one
  • Drag the border at the top of the panel (“Session panel height”), or use the arrow keys, to change the height. Double-click to return to the first height. Whether it is open and its height are remembered while the window is open.
  • Sometimes a reason appears instead of a terminal. “Select a session to show its terminal here”, “This node does not run an agent and has no session”, “The terminal will appear here when this session starts”, “Not started yet. The session starts after … finishes.”, and “Attempt N of node … has no recorded session information, so its terminal cannot open. Check that attempt in the execution log.”
  • If the session closed or failed, Reconnect appears. For a session that is not the first one opened, or one that failed or is closing, Close session also appears.

Read the run log

Section titled “Read the run log”

The Run log tab of the side panel is open at first. Under the title “Run log”, it says “Run state recorded by the Lyra engine · in time order”, and what happened appears one line at a time with its time.

  • Sentences such as “ABC-123 was assigned to me — run started”, “work — attempt 1 started”, “work — start approved”, “Workspace … created”, “work — Worker started”, “Left a comment on ABC-123”, and “Run ended”.
  • A finished item has a state mark and the time it took, and if there is a reason, it is added below on one line.
  • A note a person left on an approval or a decision appears as a quote.
  • A row that has a comment or an issue address opens a tab for that address in the main area when you click it.
  • Less important rows are grouped under “Expand N records”. The order does not change and no row is dropped.
  • If there is nothing yet, it is “No records yet”.

Read the evidence records

Section titled “Read the evidence records”

When a Workflow step finishes its work, it leaves evidence. It is proof of “what was chosen and why”. A person looks at it and judges before approving.

  1. Click the Evidence tab of the side panel. If there are records, the tab carries a count.
  2. Filter by Node and Written by. “Whole run” is a record that belongs to no node.
  3. To read it widely, click Read in a wider view. A window opens, and when you close it, you return to where you were.
  4. If you expand Writer details above a record, you see the record ID, the session or person who recorded it, the attempt, and the records seen when deciding.
Kind of record Meaning
Choice Which of the Options considered was chosen (Chosen) and the reason
Assumption An assumption the agent made
Finding Something found while working
Approval A person’s approval or denial
Waiver · Skipped A record that a check requiring evidence was waived or skipped. What it is about appears as “Target: …”

Who wrote a record is written as one of “Step work” (a step name added), “Run Orchestrator”, “Person”, or “Lyra”.

Each record carries evidence, and how far it can be trusted is divided into three marks. When you point at a mark, its meaning appears.

Mark Meaning
Checked by Lyra A check that Lyra ran itself and saw the result of
Kept by Lyra · written by the agent A file or output that Lyra kept as it was written. The agent wrote the content
Stated by the agent Content only the agent said. Lyra did not check or keep it

Do not trust evidence with the third mark as it is; check it yourself if you need to.

  • An evidence row can be a file, output, check, command with exit code, link, or quote. If you click an output or a check, you go to that node.
  • View all on file evidence shows only a preview of a file over 64 KiB.
  • If a step left no evidence and gave no reason for skipping, “The … step left no evidence records and gave no reason for skipping them.” appears. What a person waived is shown separately as “The evidence records were waived by a person. This does not mean they passed.”
  • If the list cannot be confirmed, it says “The list of evidence records for this run could not be confirmed. This does not mean there are none.” If only part was read, it says “N records and N pieces of evidence could not be read. Only the items that can be read are shown.”
  • If there are no records, it is “There are no evidence records for this run yet.”

Open an output

Section titled “Open an output”

An output is a result a node leaves. The kinds are text, markdown, file, link, and list.

  1. In Outputs on the node tab, click a row. The row name is “Open name in a tab beside the graph”.
  2. It opens as a new tab in the main area. If it is already open, you go to that tab.
  3. To see the outputs of the whole run at once, click Entire run under the node tab. The “Outputs of this run” tab opens, with the Workflow’s output and the outputs of each node grouped together.

A markdown output has Expand, and a file output that is in the workspace has View in the file. If the node’s workspace information was not received, it says “The workspace information for output … was not received, so …” and it does not open. An output that does not exist yet carries “Not yet”, and one that a finished attempt did not leave carries a mark like “… · Missing · no reason”.

Add a tab to the main area

Section titled “Add a tab to the main area”
  1. Click the New tab button at the end of the tab row.
  2. Choose Open file… or Open Browser.
  3. In the window, enter a file path or an address and click Open.

Files and addresses that open only inside this computer open in the node’s workspace. The window description says “Workspace: node · attempt N · name”, and if you have not chosen a node, it says “Choose a node that has a workspace first.” Close a tab with its close button (“Close tab”). You cannot close the Graph tab at the front.

See the result after a run ends

Section titled “See the result after a run ends”

When a run ends as Done, the band above the graph says “The run ended with passed status.” The band also has the link to the comment the agent left on the issue.

  • If there is one, click Open the comment left; if there are several, click “View N comments left” and choose from the list by step and attempt.
  • If there is none, it is “No posted comment link was reported for this run.”
  • The reason for a failure or a stop appears on one line in the same band.

Delete the workspaces a run created

Section titled “Delete the workspaces a run created”

For a finished run (a run that is not going) that created workspaces, Manage workspaces appears below the side panel. Before you delete, you first check what will be deleted.

  1. Expand Manage workspaces.
  2. Click Preview cleanup. “Counting the workspaces to delete and the uncommitted files…” appears.
  3. The window shows the workspaces this run created and the number of files. Each row says whether uncommitted files will be deleted, whether the files are already gone, and whether they could not be counted. A branch that has commits is kept, like “The branch … has commits, so it was kept.”
  4. If it is fine to delete, click Delete; if not, click Cancel. A deleted workspace cannot be restored.
  5. It handles only a few at a time, so if some are left, “The remaining N workspaces will be shown again after this deletion finishes.” appears, and you repeat the check and the delete.
  • If the workspaces changed after the check, nothing is deleted and the new list is shown again.
  • If a Worker is still working in that workspace, a sentence such as “… could not be deleted. Try deleting again in a moment.” appears. After the session ends or closes, click again.
  • If a folder remains after deleting, a warning “While deleting workspace …, folder … was left. …” keeps showing at the top of the screen. After you delete the folder yourself and click delete again, Lyra checks.
  • A workspace that cannot be confirmed as one this run created is not deleted and is left. If you do not need it, delete it on the Projects screen.

Words on this screen

Section titled “Words on this screen”

See what each word means in Terms.

Word On this screen
Run One time a Workflow was run
Attempt One time a step was done. If it fails, it is done again as Attempt 2 and Attempt 3
Session panel The area below where you see a node’s agent terminal
Run log The order of what happened, written by the engine
Evidence · Evidence record The proof of “what was chosen and why” a step leaves, and one record of it
Outputs A result a node leaves
Working · Waiting · Idle · Done · Failed · Interrupted · Unknown State marks

When it does not work

Section titled “When it does not work”
What you see What to do
“The latest information for … could not be read.” The state above is what was last read. Look for the reason with Open problem log
“has no recorded session information” instead of a terminal Look at the state of that attempt in the Run log and in the attempt history on the node tab
An output does not open It needs the node’s workspace information. Open it again from the node’s Outputs
You cannot delete a workspace Read the reason in the sentence (a Worker is working, or it cannot be confirmed) and try again after the session ends
A run is waiting for my answer See Waiting runs
