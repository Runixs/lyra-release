Edit

On the Edit screen you create and change Workflows. In the middle is a graph with nodes wired together, and in the side panel on the right you set up the node you chose or the Workflow itself. Instead of the graph, you can also edit the text of the Workflow file directly.

There are two ways to open Edit. If you click New Workflow in the list on the Workflows screen, a new Workflow opens. If you click Edit on a row, or Edit on a saved Workflow screen, that Workflow opens.

This picture was taken with sample data.

The top of the screen

Section titled “The top of the screen”
  • List: goes back to the list. If there are unsaved changes, it first asks you (see Leave without saving).
  • Title: the name of the Workflow. If the name is empty, it is “New Workflow”.
  • v3: the saved version. For a new Workflow, it appears after the first save.
  • “There are unsaved changes”: a mark that edits are still not saved.
  • Save: saves the text as it is now. While saving and when writing is blocked, it cannot be clicked, and the whole screen is read-only.
  • Graph · Text: choose whether to edit as a picture or as text. Its name is the “View” group.

A new Workflow opens from a base text. Its name is issue-to-comment, and it has one Trigger node assigned with a Jira start condition, wired to one Agent node work where Claude Code works, and the run time limit is 2 hours. The connection and the project name are examples, so choose your own (see Set up a Trigger node). If the connection is not in Settings, the side panel says “The connection … does not exist.”

Add a node

Section titled “Add a node”
  1. Click the + button at the top left of the graph (its name is “Open add node”, and “Close add node” when it is open). In a new Workflow it is open from the start.
  2. Choose the node to add from the list.
  3. Drag it onto the graph, or click it (Enter or Space also work) and drop it on an empty spot you see.
Group Rows
Trigger Run by hand · Jira · GitHub
Agent Claude Code · Codex · OpenCode
  • A Workflow can have only one Trigger. If there already is one, the Trigger row is dimmed, and when you point at it, it says “A workflow can have only one trigger, so it was not added. Edit or delete the existing trigger …, then add it.”
  • A Trigger added with the Jira or GitHub row starts with the “Assigned to me” event. If Settings has only one connection of that kind, that connection goes in by itself, and if there is none or there are several, you choose in the side panel (see Set up a Trigger node).
  • An Agent added with the OpenCode row starts in the form that works with a command in a terminal. The Command field (see Set up an Agent node) takes the place of the Prompt field.
  • If there is no node at all, it says “Press the add-node button at the top left, then drag a node onto the canvas or press it.”

When you add or delete a node, a screen reader is told, like “Added node ….” and “Removed node ….”.

Wire, unwire, and delete nodes

Section titled “Wire, unwire, and delete nodes”

A Workflow flows only from front to back. A line means “when this node ends, that node starts”.

  1. Drag a connection point on the edge of a node card (each card has several) and drop it on a connection point of another node.
  2. To remove a wire, open the node menu (⋯ on the card, the right mouse button, or Shift+F10 on the node). In Remove a wire, choose the line (from → to) to remove.
  3. You can also choose Wire to the next node in the menu and click the name of the node to wire to.
  4. To delete, choose Remove node in the menu, or press Delete or Backspace with the node chosen.

When a wire cannot be made, the reason appears above the graph. Close it with Close the reason.

Reason Meaning
Wiring to itself It tells you to wire it to another node
A line coming into a Trigger A Trigger does not wait for a node before it, so it does not take one
A loop It is already wired in the opposite direction, so wiring it would make it go around
A line that already exists The same wire already exists

Menu items are dimmed with a reason: “There is no other node to wire to.” when there is no node to wire to, and “No wire touches this node.” when there is no line to remove.

Below a card, one line shows a problem caught when saving, with a count added like +2 more. The details are in Save the Workflow.

The End mark is drawn by Lyra after the last nodes. You cannot choose, move, wire, or delete it.

Tidy up the graph

Section titled “Tidy up the graph”
  • Move a node by dragging it, or choose the node and press Alt+arrow. On a node, an arrow key goes to the next node, and Enter chooses the node.
  • With the tools at the lower left of the graph you Zoom out, Zoom in, Fit the whole graph, and change the direction with Left → right · Top → bottom. This computer remembers the direction for each Workflow.
  • If you click Lay out automatically (the diagram-shaped button) at the end of the same tool row, the nodes are laid out again to fit the current direction. It cannot be clicked when there is no node.
  • The node positions and the line positions go into the file together when you save.

Set up the Workflow itself

Section titled “Set up the Workflow itself”

When you have not chosen a node, the side panel shows the settings of the Workflow itself. The head shows the name and “Workflow · 3 nodes · led by the Lyra engine”.

  1. Name: the name used by the list and the lyra workflow command.
  2. Description: a description you want to write.
  3. Run time limit: enter a number and choose a unit (seconds · minutes · hours). If a run goes over this time, it is stopped. If you leave it empty, it is “No limit”. If the file has a value written together like 1h30m, it appears as a text field.
  4. If you expand Nodes, the node names appear one per row. If you click one, that node is chosen, so you use this to choose a node without a mouse.

“Who walks a run” appears as read-only only when the file has a value other than lyra.

Set up a Trigger node

Section titled “Set up a Trigger node”

Choose a Trigger node in the graph. The head shows “Trigger · where a run starts”.

  1. In How a run starts, choose one of Run by hand, Jira, or GitHub.
  2. For Jira or GitHub, choose a connection you created in Settings in Connection. The host of the service address is added next to the connection name.
    • If there is no connection of that kind yet, it says “There is no … connection yet. Add one in Settings → Issue connections.”
    • If the connection written in the file is not in Settings, it appears as “(not in Settings)” and says “The connection … does not exist.”
  3. Event is “Assigned to me”. For now, that is the only one.
  4. If the start method is Jira, enter the Jira project key; if it is GitHub, enter the Repository (owner/name). Only issues of that project or repository start a run.
  5. In Lyra project, choose the Project where the run’s workspace will be created. If the list cannot be read, “The list of Lyra projects could not be read.” and Read the project list again appear. If the project written in the file is not in Lyra, it says “There is no Lyra project named …. Add it in Projects or choose another project.”
  6. If you expand Names handed to the next nodes, you see the names you can put in the prompt of a later node (such as key, title, body, and url).

If the connection list cannot be read, the reason appears at the top of the edit screen with Read the connection list again.

Set up an Agent node

Section titled “Set up an Agent node”

Choose an Agent node in the graph. The head shows “Agent · after the node before it”.

  1. Node name: used when another node points to this node’s result. It must start with a letter and may use only letters, digits, _, and -. If the name cannot be used, or another node already uses it, a reason appears and the name does not change. Rename under ⋯ next to the name goes to this field, and Delete node deletes the node.
  2. In Agent, choose one of Claude Code, Codex, or OpenCode.
  3. In Prompt, write what you want the agent to do. If you type ${, the names handed over by the earlier node appear as a list; choose with the up and down arrows and press Enter to insert. If it is not wired to an earlier node, it says “Wire it to an earlier node and you can insert the names that node hands over with ${”.
    • A step that works with a terminal (OpenCode) shows Command instead of the prompt. Enter the Program to run and Argument 1, Argument 2 …, and use Add argument and the delete button on each argument. This command runs in the workspace’s terminal, and if it ends with 0, it passes.
    • If the command is not in the form opencode run <message>, a note says it cannot be changed to another agent.
  4. Outputs are the results a step leaves. Click Add output and set a name and a kind (Text or File). For a file, enter the File path too. Delete with the button at the end of the row.
  5. If you expand Model · reasoning, you choose the Model and Reasoning. If you leave them empty, it is “Agent’s default”. The list is read from that agent, and while it is being read, “Reading the list…” appears. If it cannot be read, or there is a reason it cannot be read (the trigger has no project, the project has no workspace, the agent profile is missing, there are several, or it cannot be used), the reason appears, and Read again and a field to type it yourself remain.
  6. If you expand Workspace, you choose between Create new (it creates a workspace and branch with this name; the name can also use ${ names) and An earlier node’s workspace (it continues working in the place the earlier node made). If there is no Agent node before it, the second one cannot be chosen.
  7. Expand Pass · approval · on failure and set the rules of the step.
Field What you choose
Pass rule “Passes only with a comment on the issue”. If you turn it on, an attempt with no comment fails
Approval “A person approves it before it starts”. If you turn it on, an approval request comes to the Inbox before the step starts (see Workflow requests)
If denied Shown only when Approval is on. Stop the run, Run this step again, or Send back to an earlier node. There is no limit on how many times it is sent back
If it fails Stop (the run fails too), Retry (if the same session is open, as a new job in it), or Send back (the earlier node receives what failed and starts again)
Retries Up to 4 times
Send back to, At most Choose from the earlier Agent nodes, up to 10 times

At the right of a folded row, what you set now appears on one line. For example, “Issue comment needed · Approval needed · a denial stops the run · A failure retries 2 times”. A folded row opens by itself for a field where a problem was caught when saving.

If you point at the ? next to a field name, or reach it with the keyboard, an explanation appears. Close it with Esc.

If the file has a node that is neither a Trigger nor an Agent, it says “The settings of a … node are edited after switching to the text editor.” Only two nodes can be newly added from the graph.

Edit as text

Section titled “Edit as text”
  1. Click Text at the top.
  2. Edit the text in the “Workflow file to save” field. It tells you, “Saving saves this text. Going back to the graph reads this text again and draws it.”
  3. To go back to the picture, click Graph. It reads the text again and draws it.

If the text cannot be read as a picture, you stay in the Text view, and the reason and the line number appear. Cases it cannot read are when the YAML shape is wrong, when anchors, aliases, or tags such as & · * · ! are used, when nodes is not a list, and when a node has no id or its id is duplicated. After you fix it, click Graph again. At that time the side panel says “The file could not be read as a graph, so the node settings cannot be shown. …”. A file that cannot be read as a picture from the first time you open it opens in the Text view.

Save the Workflow

Section titled “Save the Workflow”
  1. Click Save.
  2. If it succeeds, “Saved.” appears at the top and the version goes up. Warnings caught when saving stay in the list at the top.

If it cannot be saved, a count appears like “Not saved · 3 problems”. A problem that belongs to a node shows below that node’s card and at the top of the side panel, and a problem that belongs to no node is gathered in the list at the top of the screen. Fix them and save again. Even if saving fails, what you edited stays as it is.

A run goes with the version at the time it started. A version you save later does not affect a run that started before.

Leave without saving

Section titled “Leave without saving”

If there are unsaved changes and you click List or try to go somewhere else (for example, Open run on an Inbox card), the “There are unsaved changes” window opens first. What changed appears as lines: “Nodes added: …”, “Nodes deleted: …”, “Nodes whose settings changed: …”, “Workflow name · description · limits”, “Node layout and connector positions”, and “Text of the workflow file”.

  1. Save and leave: saves, then leaves. If it cannot be saved, “It could not be saved, so you did not leave. Fix the problem shown on this screen, then save again.” appears, and the window and your edits stay as they are.
  2. Discard and leave: throws away what you edited.
  3. Stay: closes the window and you keep editing.

Words on this screen

Section titled “Words on this screen”

See what each word means in Terms.

Word On this screen
Node One box in the graph, that is, one step
Trigger · Agent The two kinds of node
Outputs A result an Agent node leaves
Workspaces The folder a node works in. Create new or An earlier node’s workspace
Send back Making an earlier node start again on a failure or a denial
Graph · Text Two shapes of looking at the same file

When it does not work

Section titled “When it does not work”
What you see What to do
Save cannot be clicked It is saving, or writing is blocked. Wait a moment
“Not saved · N problems” Choose the node where a problem was caught, open the folded row, and fix it
You cannot wire a node Read the reason shown above the graph. You cannot make a loop or a line coming into a Trigger
You click Graph but stay in the Text view Fix the text at the line number shown above the text
The model list is empty Read the reason sentence and click Read again, or type the model yourself
“The connection … does not exist.” Create the connection in Settings, or choose another connection
