Worktree and Workspace

Inside a Project, the place where you divide up the work is called a workspace. In a Git Project the workspace is a Worktree (a separate working folder for each branch of the same repository). In a Project that is not Git it is a Workspace. Worktrees do not overwrite each other’s files, so two agents can work on their own branches. A Workspace is one folder that several agents share.

The pictures on this page were taken with sample data.

Create a Worktree

Section titled “Create a Worktree”

This creates a new branch and a new working folder together in a Git Project.

  1. Click the + button on the Project row. You can also choose Add Worktree in the row menu, or press the shortcut ⌘N (Ctrl+N on Windows). If you open it with the shortcut, a Project field at the top of the window lets you choose which Project to create it in.
  2. The Create Worktree window opens. If the Project is on several computers, choose where to create it in the Host field. If there is only one place, this field does not appear.
  3. Enter a Name. This name becomes the new branch name, and the folder name is derived from it. If the folder name is different, the Estimated folder: name line shows it in advance.
  4. In Starting branch, choose the branch to branch off from. At first the remote’s default branch is chosen (in the order origin/main, origin/master, main, master), and the list marks Default, Current branch, and Remote branch. You can search with the Find a branch field.
  5. In Agent, choose the profile of the Session to open right after creating, or choose No session. If it is not in the list, Manage agents… takes you to Settings. If no profile is turned on, it says “No profile is turned on for this host. You can create it without a session.” If no agent was found on that computer, it says “No installed agent (Claude Code, Codex, OpenCode) was found on host. You can create it without a session.” with View in Settings › Agents.
  6. Click Create.

While it is being created, progress appears under the Worktree row. When it finishes, the row looks normal, and if you chose an agent, that Session opens.

A name is blocked in these cases.

What you see Meaning
“Enter a name.” The name is empty
“This branch already exists.” A local branch with the same name exists
“It cannot be used as a Git branch name.” It contains a space, characters such as .. or ~^:?*[, or a leading or trailing / or .
“The folder name must have at most 64 characters and cannot use Windows reserved names such as CON or NUL. Change the name.” The folder name made from the name cannot be used

If a workspace with the same name already exists, a message such as “A Workspace with this name already exists.” and an Open button appear under the name. If it was left behind because its setup failed, there is also Prepare again. If the name is already used by a different branch, you must enter another name.

Setup Script

Section titled “Setup Script”

If .lyra/config.yaml in the project folder has a Setup Script (setup commands to run after the workspace is created), Lyra reads it before creating.

  1. If a command is new to Lyra or differs from one you allowed before, the Run Setup Script window opens. The list of commands is shown with numbers.
  2. Click Run to run the setup commands and create the workspace. Click Do not run to create it without the commands. If you close the window, nothing happens.
  3. If you turn on Always trust this project and click Run, Lyra will not ask again, on any host of this Project, about commands that change later. How to turn this off is in Setup Script of Project settings.

If the file cannot be read or its format is wrong, the window says “Setup Script is invalid” or “could not be read”, and offers Read again and Do not run Setup Script this time. If you turn on the latter, you can create the workspace without the commands.

When setup fails

Section titled “When setup fails”
  • If creating fails, a line under the row shows “name could not be created” or “name was not fully set up” with the reason. It also says “The half-created workspace is left as it is.”
  • Try again continues from where it stopped. Close closes only the notice.
  • If only the setup command failed, the notice “The workspace setup command failed” has Run again and View log. The workspace stays as it is.
  • A mark such as Setup failed or Partly set up appears at the right of the row. For a workspace that already existed and was registered, so that Lyra did not run the setup command, the info card says Setup command not run.

Create a Workspace

Section titled “Create a Workspace”

This creates one more workspace in a Project that is not Git.

  1. Click the + button on the Project row. The menu name is Add Workspace and the window title is Create Workspace.
  2. Enter a Name. It must be 64 characters or fewer, and invisible control characters are not allowed.
  3. The window tells you: “These Workspaces share one folder, so agents can edit the same files.” It does not create a new folder.
  4. Choose an Agent and click Create.

Rename

Section titled “Rename”
  1. Choose Rename in the workspace row menu. On macOS you can also select the row and press Enter; on Windows, press F2.
  2. A Display name field opens under the row. Enter a name and click Save. Esc or Cancel leaves it as it was.

If it was changed somewhere else first, the save is refused and the reason appears. Click Read again, then save again. The display name is a name inside Lyra. The folder name and the branch name do not change.

Delete a workspace

Section titled “Delete a workspace”
  1. In the workspace row menu, choose Delete Worktree… (Delete Workspace… if it is not Git).
  2. The Delete workspace window shows the name, kind, host, and path.
    • For a Worktree that Lyra created, it says “Deletes the Worktree at this path and tries a safe delete of the branch name. If there are modified files, nothing is stopped and the delete is refused.”
    • For any other workspace (the original folder, a folder that is not Git, a Worktree that already existed), it says “Deletes it only from Lyra’s list. The folder and branch on disk stay as they are.”
  3. If Sessions and terminals are running, a list appears: “Before deleting, the sessions and terminals below are stopped in this order. If any of them cannot be confirmed as stopped, it stops there and leaves the folder as it is.”
  4. To avoid being asked every time, turn on Don’t ask again. While it is on, this window does not open next time and the workspace is deleted right away. Lyra still asks if the server connection is lost or the server dropped out of the list, and for a branch that has commits that are not merged.
  5. Click Delete workspace.

When there are commits that are not merged

Section titled “When there are commits that are not merged”

If the branch has commits that are not yet merged, the window says “The branch name has N commits that are not in the base branch.” and the buttons change to two.

Button What it does
Delete and keep the branch Removes only the folder and keeps the branch and its commits
Delete the branch too Deletes the branch as well. You may lose those commits

Kept branches are collected under Kept branches in Project settings (see Kept branches). If Lyra could not read whether the branch is merged, it tells you: “When you delete, the branch gets only a safe delete, and it is kept if it has commits.”

Force delete

Section titled “Force delete”

If a Worktree that Lyra created has changes that are not saved, an ordinary delete is usually refused. The Force delete window then opens.

  1. Read “The ordinary delete was refused: reason.”
  2. Read “Discard uncommitted changes and new files and delete the folder (path) on host?” and click Force delete. To cancel, close the window.

Because it discards the changes, you cannot undo it. Force delete does not appear when Lyra could not confirm whether there are changes, or for a workspace that Lyra did not create.

When a deletion does not finish

Section titled “When a deletion does not finish”

If a deletion stops partway, a warning mark stays at the end of the row. Examples are “Deletion incomplete · some files remain” and “Could not delete · in use by name”. Click the mark to open a small window with an explanation and buttons. The same items are also at the bottom of the row menu.

Menu What it does
Delete again Tries the same deletion again
Remove from list only Leaves the folder and deletes only Lyra’s record
Forget uncertain record Deletes only the record whose outcome is unknown. It asks once more to confirm, and does not touch the folder and branch on the server

If the deletion is blocked because the server connection was lost, Lyra tells you to reconnect or re-add the server in Remote in Settings, then delete.

Words on this screen

Section titled “Words on this screen”

The Terms page explains Worktree, Workspace, primary, Setup Script, and the setup states (Creating, Preparing, Ready, Setup failed, Partly set up).

When it does not work

Section titled “When it does not work”
What you see What to do
Create cannot be clicked Read the message under the name and fix it. You may not have chosen a starting branch or a host
“The branch list could not be read” Check that the host is connected. Close the window and open it again
“The host list could not be read” Click Read again on the same row
“This workspace has already been deleted. Read the project list again.” Click Read again on the list
“The workspace was deleted, but the project list could not be read again.” The deletion is done. Only read the list again
The delete is refused The refusal sentence gives the reason. If a Worktree that Lyra created has modified files, save or discard them and try again, or use Force delete. For other reasons there is no force delete
