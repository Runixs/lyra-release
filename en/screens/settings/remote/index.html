Remote

Remote is the list of servers you connect to over SSH (other computers that run agents and terminals). You add servers, connect, read their state, edit them and delete them. What a server is and what runs where is in Servers and Hosts.

This computer does not appear in this list. See this computer’s agents in Agents.

The pictures on this page were captured with sample data.

Add a server

Section titled “Add a server”
  1. In the settings contents on the left, open Remote in the Connections group.
  2. Select Add server at the top. The Add server window opens.
  3. Choose how to register. Enter manually means you write the address yourself. From SSH settings means you pick a Host alias from ~/.ssh/config on this computer.
  4. If you enter it manually, write the Name, Address, Port and User. You can leave the port empty, and if you write it, only numbers are allowed.
  5. Select Save. To back out, select Cancel.
  • The window says “Sign-in follows the methods the server accepts when connecting. If you have a key, it signs in with the key, and if the server asks for a password, it asks once at that point.” There is no password field when you add a server.
  • If you choose From SSH settings, the aliases appear as a radio list. When you pick one, the Name field is filled with that alias if it was empty or held the alias you picked just before. Only Name is left in the fields. Save cannot be selected until you pick an alias.
  • While the aliases are being read, it says “Reading Host aliases from the SSH configuration on this computer.” If there are none, it says “No Host alias was found in the SSH configuration file. Enter the server address with manual entry.” If they could not be read, a notice says so. In both cases you can go back with the Enter manually button. If only part could be read, a notice says the list is incomplete.
  • If a field is empty, “This cannot be left empty.” appears under it. If it is too long, “This is too long.” If the port has anything but digits, “Only numbers are allowed.” The address format and a duplicate name are reported when you save.

The steps for adding your first server are also in Connect a Linux server.

Read the connection state

Section titled “Read the connection state”

The small mark at the right of a server row is its current state.

Mark Meaning What to do
Connected It is connected now Nothing
Disconnected The connection dropped or failed Select Connect, or see When you cannot connect below
Not checked yet The connection state has not been checked yet Select Connect. If you select the mark, it says “The connection state of the server “(name)” could not be checked. Press [Connect] to connect again.”
Connecting You selected Connect and it is waiting for the answer Wait

Not checked yet is not a failure. It means it is not known yet. If the time is known, it also says since when, as in “Not checked yet · since 14:05”.

A server row has an SSH mark next to its name, and under the name the facts about the server.

Item Meaning
SSH host · Port · User The values you registered
OS The server’s operating system. Shown only while it is connected
lyra-daemon · Protocol The version and protocol of the lyra-daemon (Lyra’s execution engine) running on the server. Shown only while it is connected
Last checked When these values were last checked
Differs from the app version (…) The server’s lyra-daemon version differs from this app’s version, or the version was refused
Installed agents The agents and versions found on the server while it is connected

Values that are not known are written as Not checked yet.

Connect and disconnect

Section titled “Connect and disconnect”
  1. Select Connect at the right of a server row that is not connected.
  2. To disconnect, select the server row’s name to expand the row, then select Disconnect.
  3. To find the server’s agents again, select Check now on the row of a connected server. The result appears in Installed agents.

If the connection fails, the row expands by itself and the reason appears under the row. If you selected the wrong server, select the name again to collapse the row.

Steps shown while connecting

Section titled “Steps shown while connecting”

When you start a connection, the step in progress appears as one line under the server row, with the step name and its state together, as in “SSH sign-in · in progress”. Only the steps Lyra reports appear, and it does not move on by itself just because time passed.

Step What it does
SSH sign-in Reaches the server and signs in. If it asks for a password or a one-time code, it stops and waits at this step
Start distribution Starts the distribution of a WSL server
Check version Reads the server’s operating system and the lyra-daemon on the server. If the server does not have this version and this computer has no package for that server, this step downloads the server package (it waits up to 2 minutes)
Send over SSH Sends the lyra-daemon file to the server
Install Puts the sent file in place
Stop older lyra-daemon So that this version can take over, it stops the server’s older lyra-daemon. If there was nothing to stop, this step does not appear
Start lyra-daemon Starts lyra-daemon on the server and waits until it is ready
Open connection Opens the command path to the server’s lyra-daemon

Only the steps it actually went through appear. A step skipped because it was already installed is not written as done. When it connects, the line disappears.

  • When it stops, the step it stopped at appears, as in “Stopped at the SSH sign-in step.”, and under it the reason it stopped and what to do next. If you selected Connect and the row already shows a reason below, the same reason is not written twice.
  • If you close the connection while it is connecting, it says “The connection was closed at the (step) step.”
  • If it could not be confirmed whether the older lyra-daemon was stopped, it says “(step): the result could not be confirmed. An older lyra-daemon may still be running.” This step is not counted as finished.
  • If an older lyra-daemon is running on the server at the version check, it says “An older lyra-daemon is running → switching to version (…). Its sessions continue on (…).” If the server lacks the needed version, it says “This server does not have lyra-daemon version (…), so it is being installed.” It only tells you and does not ask.
  • If you select View previous steps, the steps already past appear one per line, as in “Check version · Done”. The state is one of Done, In progress, Stopped, Closed, Not confirmed. The list stays after it connects, and when you start connecting again it is closed and replaced with the new steps.
  • A screen reader reads out the server name with the step when the step changes, when it stops, and when it connects, once each.

On the command line, lyra server connect writes the current step on each status line. Details are in Servers: server.

What you see in an expanded row

Section titled “What you see in an expanded row”

Select a server’s name to expand the row.

Item Meaning
Address address:port
User The sign-in user
Authentication The sign-in method. See Sign-in method below
Connection The connection state

At the top of the expanded row are the server’s lyra-daemon records.

What you see Meaning
Recorded current version · Previous version The versions recorded for the server. If there are none, No recorded version, No previous version
Last checked When the records were last checked. If not known, Last checked unknown
Matched to the new version The server was matched to the new version
Matching — not matched yet It is in progress. The current step is shown with it, as in Step: Check server
It was not connected at update time — this does not mean it was matched The server was not connected at the time of the update
Could not be matched — not confirmed It could not be matched. The reason is shown with it
Version refused · app protocol … · lyra-daemon protocol … The protocols of the app and the server do not match
Other lyra-daemon versions Other versions on the server. Each row shows the version, one of Work remains, No work, connections remain, Empty, Ended, Could not be checked, and the number of jobs and connections

When the app gets a new version and the server’s lyra-daemon is older than the app, Lyra switches it to the new version. If the server has live work, it keeps the old version until the work is gone. You do not have to upgrade it yourself.

If it could not be matched, or Version refused appears, select Check now while the server is connected, and if it stays the same, see Troubleshooting.

Sign-in method

Section titled “Sign-in method”

The Authentication field tells you how this server signs in.

What you see Meaning
SSH key It signs in with a key file
SSH key (passphrase) It signs in with a key that has a passphrase
Authentication agent It uses this computer’s SSH authentication agent
SSH config (alias) It follows an alias in ~/.ssh/config
Password It signs in with a password
SSH key (name) (fingerprint) · password if the key does not work Your key is registered on this server. It signs in with the key first, and uses the password if that fails
Password (key not registered: reason) The key could not be registered

When you connect with a password

Section titled “When you connect with a password”

When the server asks for a password, the Enter the password to connect window opens. Select Enter and connect.

  • The window says “It is kept only in the memory of lyra-daemon on this computer and is not written to disk. It is erased when lyra-daemon ends.”
  • The password must be 64 KiB or less. If it is empty or over that, it says “Enter the password. The input must be 64 KiB or less.”
  • For a server that asks for a one-time code (OTP), the Enter one-time code (OTP) window opens. The code is not saved, and it must be 256 bytes or less.
  • If it failed because the password was wrong, Fix password appears on the expanded row. Select it and the edit window opens with the cursor in the password field.
  • To try again with the same password, select Check again with the current password.

Sign in without a password

Section titled “Sign in without a password”

For a server you connected to with a password, if you put your SSH key on the server, it will not ask for the password from the next time.

  1. The first time you connect to a server with a password, the window “Sign in to (server) without a password?” opens once. Select Register on this server.
  2. To do it later, select Later. Closing the window is the same as Later. It will not ask again for this server.
  3. To register later, select Register SSH key on the expanded row of a connected server.

The window says this.

  • Lyra adds the public line of your SSH key to ~/.ssh/authorized_keys on the server. Company gateway servers are not included.
  • If you have no SSH key, Lyra first creates ~/.ssh/id_ed25519 on this computer without a passphrase.
  • A key file with no passphrase is like a password that never expires. Anyone who can read that file, or a backup that contains it, can sign in to every server that trusts this key.
  • Lyra only adds. If you delete the server in Lyra or change the key, the line on the server stays. To block access, delete that line on the server.

The result of the registration shows for a moment as a notice. If it registered, it says “The SSH key (…) was added to this server — from now on no password is needed.” If it was already there, “The SSH key (…) is already on this server — from now on no password is needed.” If it did not, “The SSH key was not registered: reason”. If the key has a passphrase, the reason is “The key has a passphrase. Add it with ssh-add, then register again”, so add the key with ssh-add as it says, then register again.

If the server did not accept the key, or the connection dropped while the key was being added, a warning stays on the server row instead of a notice, and a Reconnect button is added. In that case Lyra does not delete the server’s line.

Servers added by alias

Section titled “Servers added by alias”

Some servers added by an alias in ~/.ssh/config connect through the ssh program on this computer (when they use ProxyJump, ProxyCommand, a security key and so on). These servers sign in with a key, and the password field of the edit window is locked with a notice, “The server (…) is connected with the ssh program on this computer …”. In a terminal, register your key on the server with ssh-copy-id <alias>.

An alias whose user name looks like a company gateway sign-in is different. If it does not need the ssh program on this computer (when it uses no ProxyJump-like setting and no security key) and you do not choose the sign-in method yourself, it is registered as Password. When you select Connect, a window asks for the company ID password and a one-time code, like a server added by address. If you choose the sign-in method yourself, Lyra follows it. The automatic connection when the app opens stops without opening a window, and you can connect again with the Connect button in the notice below.

When you cannot connect

Section titled “When you cannot connect”

If a server row says Disconnected, do this.

  1. Select the server’s name to expand the row, and read the reason under it.
  2. Select Connect to connect again.
  3. If it still does not work, see When server sign-in fails or times out.

If Lyra tried to reconnect to a server by itself when the app opened and stopped, a notice appears.

Notice title Notice text Button
Automatic connection stopped One of Password or key passphrase needed, Saved settings changed, Saved credential access needed, or the reason for the failure Connect
Server identity check Server identity unverified Open server settings

If you select Open server settings, this Remote screen opens. If Server identity unverified appears when you did not change or reinstall the server, do not connect.

How a server’s terminals look while the connection is down is in Servers and Hosts.

Edit a server

Section titled “Edit a server”
  1. Select the server’s name to expand the row.
  2. Select Edit. The Edit server window opens.
  3. Change the Name, Address, Port, User and Password, then select Save.
  • If you leave the Password field empty, the current secret is kept.
  • For a server added by alias, you can change only the Name and the Password.
  • If you write a password and save, it is kept only in the memory of this computer’s lyra-daemon.

Delete a server

Section titled “Delete a server”
  1. Expand the server row and select Delete.
  2. In the Delete server window, read “Delete the server “(name)” from the list?” and select Delete. To back out, select Cancel.

The server is removed from the list, and the sign-in information for that server stored on this computer is deleted too. If it is a server you sign in to with a company ID password, the saved password of that company ID is deleted, so other servers that use the same company ID will also ask for the password again at the next connection. The server’s sessions and files are left as they are. The SSH key line you put on the server is also left, so to block access, delete it on the server yourself.
