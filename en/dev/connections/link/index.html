Link

This content is not available in your language yet.

Link는 이 컴퓨터의 엔진과 서버의 lyra-daemon을 잇는 길입니다. 서버 하나에 SSH 연결 하나가 서고, 그 연결의 명령 채널 입출력 위로 Link 줄이 흐릅니다. 코드는 crates/lyra-link(연결을 세우는 쪽)와 crates/lyra-link-protocol(줄의 모양)입니다.

두 끝

섹션 제목: “두 끝”
끝 하는 일
엔진 lyra-link로 연결을 세우고 지키며 link-state를 앱에 알립니다.
서버의 lyra-daemon lyra-daemon serve로 떠 있다가 attach가 이어 주는 입출력으로 Link 줄을 받습니다.

서버의 lyra-daemon이 어디서 도는지는 Server daemon에서 다룹니다.

통로

섹션 제목: “통로”

연결은 단계를 차례로 밟습니다. 단계 이름은 코드의 ConnState입니다.

단계 하는 일
resolving 등록된 서버에서 주소와 계정을 풀어냅니다.
connecting SSH 전송을 세웁니다.
verifying-host-key 서버가 낸 호스트 키를 기억한 키와 견줍니다. 인증보다 먼저 합니다.
authenticating 인증합니다.
installing 서버에 맞는 버전의 lyra-daemon이 없으면 올리고 띄웁니다.
handshaking bootstrap 버전 맞추기. 5초 안에 끝나야 합니다.
connected Link 줄이 흐릅니다.
reconnecting · failed · closing · closed 끊긴 뒤 · 멈춤 · 닫는 중 · 닫힘

앱 화면이 보는 상태는 이 가운데 여섯 가지로 줄어듭니다(LinkState): connected · disconnected · reconnecting · installing, 그리고 WSL 배포판에만 있는 distribution-stopped · distribution-state-unknown(WSL channel).

  • 서버나 WSL 대상에 연결할 때마다 link-state 알림이 progress를 싣습니다(ConnectProgressView, version 1). attempt는 연결 세대로 시도마다 오르고, steps는 실제로 거친 단계만 차례로 담습니다. 단계 이름은 ssh-login · starting-distribution · version-check · ssh-transfer · install · retire-older · engine-start · relay-open이고, 단계의 끝은 running · succeeded · failed · cancelled · not-confirmed입니다. 멈춘 단계는 그 연결의 실패 코드(failure)를 달고, 사람이 닫으면 cancelled입니다. 이전 버전 lyra-daemon을 멈춘 것이 확인되지 않으면 not-confirmed이고 완료로 읽지 않습니다. version-check 단계는 versions(needed와 found: this-version · not-installed · older-running · other-running)를 싣습니다. 마지막 시도의 단계는 연결되거나 멈춘 뒤에도 다음 시도가 시작될 때까지 남고, 시도가 끝나면 더는 바뀌지 않습니다. 이 컴퓨터의 lyra-daemon에는 없고, 모르는 단계 이름은 읽는 쪽이 빼고 보여 줍니다. 화면은 원격의 서버 줄에, 명령줄은 lyra server connect의 상태 줄에 이것을 보입니다.
  • 전송은 셋입니다. 내장 SSH(russh), OS의 ssh 프로그램, 그리고 WSL 채널입니다. 환경변수 LYRA_SSH_FORCE_SYSTEM_TRANSPORT가 정확히 1이면 OS의 ssh를 강제하고 link-system-ssh-forced를 알립니다.
  • 호스트 키 정책은 accept-new(처음 보는 키는 기억하고 받음, 기본)와 known-only(기억한 키만 받음)입니다. 검사를 끄는 값은 없습니다. 기억한 키와 다르면 link-host-key-rejected, 알던 호스트가 다른 종류의 키를 내면 link-host-key-kind-changed, 기록을 읽을 수 없으면 link-host-key-record-unreadable입니다.
  • 서버에서는 명령 채널 하나로 <서버 프로그램> attach --socket <서버 소켓>을 실행합니다. 이 명령이 서버의 lyra-daemon의 소켓과 채널의 입출력을 이어 주고, 그 입출력이 전송이 됩니다. 이 채널은 30초 안에 붙어야 하고, 못 붙으면 link-attach-timed-out입니다.
  • 내장 SSH에서는 같은 SSH 연결 위에 명령 채널을 여러 개 엽니다. 설치 단계의 원격 명령은 하나씩 30초(EXEC_TIMEOUT) 안에 끝나야 합니다.

줄의 모양과 version

섹션 제목: “줄의 모양과 version”

SSH 명령 채널의 입출력에는 세 가지 덩어리가 섞여 흐르고, 첫 바이트로 구별합니다.

첫 바이트 덩어리 한도
L 첫 교환(bootstrap): 19바이트 LYRA-LINK-BOOTSTRAP, 4바이트 길이, JSON JSON 65,536 바이트
{ 제어 봉투: JSON 객체 하나 16 MiB(16,777,216 바이트)
그 밖 바이트 프레임: 19바이트 머리, payload 받는 쪽 16 MiB, 보내는 쪽 64 KiB

제어 봉투는 아래 칸을 갖고, 모르는 칸은 거부합니다(deny_unknown_fields).

  • v는 모든 봉투에 실리는 버전입니다. op는 request와 notify에만, err는 error에만 있습니다.
  • 제어 채널의 번호는 0이고 연결마다 하나입니다. seq는 채널마다 1부터 하나씩 올라갑니다. 이미 본 번호는 버리고, 건너뛰면 link.resend로 빠진 구간을 다시 청합니다.

바이트 프레임은 터미널 출력, 파일, mcp 표준 입출력이 가는 길입니다. 머리는 big-endian 19바이트입니다.

자리 크기 뜻
0–1 2 짧은 버전 표기(bootstrap이 정해 줍니다)
2 1 opcode: Data=1 · Ack=2 · Pause=3 · Resume=4 · End=5 · Error=6
3–6 4 채널 번호. 0이 될 수 없습니다.
7–14 8 순번
15–18 4 payload 길이

바이트 채널은 link.channel.open으로 열고 link.channel.close로 닫습니다. 채널마다 흐름 제어가 따로 붙습니다: 보내는 창 256 KiB(DEFAULT_WINDOW_BYTES), 받은 양을 64 KiB마다 또는 50 ms마다 Ack로 알립니다. 받는 쪽이 감당하지 못하면 Pause로 그 채널만 멈춥니다. 다시 붙을 때 이어 받을 수 있도록 보낸 줄은 10분 30초(REPLAY_RETENTION_MS) 동안 보관합니다.

버전 맞추기. 연결을 세운 쪽이 hello에 자기 버전 PROTOCOL_VERSION을 싣습니다. 지금 값은 0.2.6입니다. 받는 쪽은 자기 버전과 글자 하나까지 같을 때만 accepted를 돌려줍니다. 세 숫자 중 하나라도, 빌드 꼬리표라도 다르면 이을 수 없습니다. 제품 버전이 달라도 이 버전이 같으면 이어집니다.

거부 errorCode 조치(remediation)
핵심 버전이 다름 core-version-mismatch install-required-version: 상대가 요구한 버전을 나란히 설치하고 새 bootstrap을 시작합니다.
꼭 필요한(required) 기능이 한쪽에 없음 link-feature-mismatch retry-later: 광고나 설치 상태가 바뀐 뒤 새 bootstrap으로 다시 시도합니다.

엔진은 install-required-version을 받고 설정 auto_install이 켜져 있으면(기본 켬) 그 버전의 lyra-daemon을 서버에 올리고(installing) 다시 bootstrap합니다. 방금 올린 것이 또 거부하면 다시 올리지 않고 link-daemon-install-failed로 멈춥니다. 필수가 아닌 기능이 한쪽에 없으면 그 기능만 빠진 채 이어집니다. 지금 광고하는 선택 기능으로 lyra.link-health(link.ping)가 있습니다.

형태가 바뀌면 PROTOCOL_VERSION을 올리는 규칙은 코드가 지킵니다. 닫힌 메시지 모양의 지문을 crates/lyra-link-protocol/tests/shape_fingerprint.rs가 재고, 버전을 올리지 않고 모양만 바뀌면 이 시험이 실패합니다.

누가 붙을 수 있나

섹션 제목: “누가 붙을 수 있나”
  • 서버 쪽에서는 SSH 인증을 통과한 계정만 명령 채널을 열 수 있습니다. 인증 방법은 비밀번호, 개인 키, 키보드 대화(일회용 코드 포함)이고, 실패하면 link-authentication-failed · link-authentication-method-unsupported · link-authentication-otp-needed · link-reconnect-needs-one-time-code 같은 코드로 멈춥니다.
  • 엔진 쪽은 호스트 키 검사가 인증보다 먼저입니다. 키가 맞지 않으면 인증 정보를 서버에 보내지 않습니다.
  • Link는 자격 증명 저장소에서 받은 바이트를 메모리에만 두었다가 인증이 끝나면 지웁니다. 저장소가 어디인지는 Credentials에서 다룹니다.

한도

섹션 제목: “한도”
한도 값
SSH 전송이 서기까지(CONNECT_TIMEOUT) 10초
원격 명령 하나(EXEC_TIMEOUT) 30초
비밀번호 로그인 한 번에 사람이 입력하는 시간을 뺀 전체(LOGIN_EXCHANGE_LIMIT) 30초. 키보드 대화의 응답 하나는 10초(CONNECT_TIMEOUT)이고, 사람의 일회용 코드를 실은 응답만 이 30초의 남은 시간까지 기다립니다. 그래도 답이 없으면 link-one-time-code-reply-timed-out(limitSeconds에 기다린 초)로 멈추고 다시 시도하지 않습니다.
처음 보는 호스트 키를 기록하는 시간 5초
명령 채널 붙기(ATTACH_TIMEOUT) 30초
서버의 attach가 서버 소켓에 붙기(ATTACH_CONNECT_TIMEOUT) 5초
버전 맞추기(HANDSHAKE_TIMEOUT_MS) 5초
요청 하나 기본(DEFAULT_REQUEST_TIMEOUT_MS) 30초
SSH 무응답 확인 5초마다 확인하고(KEEPALIVE_INTERVAL), 응답 없는 확인이 셋째가 되면 끊음(KEEPALIVE_MAX 2) → 15초
link.ping(lyra.link-health를 고른 연결) 연결을 세운 쪽이 5초마다 보내고, ping을 보낸 상대에게서 20초 동안 줄이 없으면 받는 쪽이 그 상대를 뗍니다(LINK_PING_INTERVAL_MS · LINK_PEER_SILENCE_MS).

끊기면

섹션 제목: “끊기면”

끊긴 연결은 실패의 분류로 다시 붙을지를 정합니다. 분류는 protocol · transport · busy · absent · refused · internal 여섯이고, 다시 시도해도 되는 것은 transport와 busy뿐입니다. 나머지는 같은 일이 같은 결과일 것으로 보고 멈춥니다.

일 일어나는 일
전송이 끊김 다시 붙기 계획을 시작합니다. 최대 5번이고, 기다림은 즉시 · 1 · 2 · 4 · 8초에 ±20% 흔들림이 더해집니다(BACKOFF_BASE_MS, MAX_RECONNECT_ATTEMPTS). 전부 합쳐도 20초(RECONNECT_BUDGET_MS) 안에 들게 되어 있습니다.
계획의 시도가 재시도 가능한 이유로 실패 다음 시도로 갑니다.
계획이 다 소진됨 link-reconnect-exhausted(transport)로 failed입니다.
재시도할 수 없는 이유로 실패(호스트 키 불일치, 인증 실패, 버전 불일치 등) 바로 failed입니다.
failed 뒤 사람의 다시 연결이나 컴퓨터의 잠 깸 신호가 있을 때만 다시 돕니다(UserReconnectOrHostWake). 잠에서 깨면 5초 간격으로 최대 두 번 서버에 닿는지 봅니다.
되풀이해도 안전하지 않은 요청의 답을 못 받고 끊김 다시 보내지 않고 결과 모름(link-request-outcome-unknown)으로 닫습니다.

연결이 link-state 사건으로 어떻게 화면까지 가는지는 Window bridge와 Sidecar line protocol에서 다룹니다.

코드와 주석이 다른 곳

섹션 제목: “코드와 주석이 다른 곳”

crates/lyra-link/src/view.rs의 모듈 설명(3번째 줄)은 “연결 상태 넷”만 말하지만 LinkState의 값은 여섯 개입니다. 타입 설명(11번째 줄)은 WSL 대상의 둘을 덧붙여 맞게 쓰여 있습니다. Implementation에 올립니다.
