Project MCP

This content is not available in your language yet.

프로젝트 폴더의 .mcp.json은 그 프로젝트에서 에이전트가 쓸 MCP 서버(에이전트가 부르는 도구 서버)를 적어 둔 파일입니다. 파일을 쓰는 사람은 프로젝트 쪽 사람이므로 밖에서 더해지는 것은 이 서버 정의입니다. Lyra는 이것을 그냥 켜지 않습니다. 서버마다 지문을 만들고 사람의 승인을 받은 것만 에이전트를 띄울 때 켭니다. 승인이 없거나 서버가 바뀌었으면 그 발사를 막습니다.

이 길은 지금 화면에서 닿지 않습니다. 승인은 Claude Code 대화 Session을 열 때만 일어나고, 이 빌드에서 Lyra 화면의 대화는 멈춰 있기 때문입니다(Sessions and Turns). 엔진과 daemon의 코드는 그대로 있고 시험으로 지켜집니다.

무엇을 더할 수 있나

섹션 제목: “무엇을 더할 수 있나”

.mcp.json의 mcpServers에 적힌 서버입니다. daemon은 작업 폴더에서 루트까지의 모든 폴더에서 .mcp.json을 찾고(ancestors), 한 이름이 두 파일에 나오면 거절합니다. 한 번에 256개까지 받습니다.

서버 하나의 형식은 이렇습니다.

칸 받는 값
type stdio(기본), http, sse, ws, streamable-http. url만 있고 type이 없으면 http입니다. 그 밖의 값은 거절합니다.
command · args stdio일 때 실행 파일과 인자
url 나머지 전송일 때의 주소
headersHelper 머리글을 만드는 보조 프로그램 이름
env · headers 문자열 값만. 이름만 승인 글에 보입니다.

파일 한 개는 1 MiB까지만 읽고 JSON이 아니면 session.project-mcp-config-unreadable입니다. 글 칸에 눈에 안 보이는 글자(제어 문자, 글 방향을 바꾸는 글자 등)가 있으면 사람이 읽는 글을 속일 수 있어서 거절합니다.

어디에 꽂히나

섹션 제목: “어디에 꽂히나”

세 곳에서 이어집니다.

곳 하는 일 코드
실행 위치의 daemon .mcp.json을 읽고 지문을 만듭니다. 승인된 이름의 --settings 글을 돌려주고, 발사 직전 다시 확인합니다. crates/lyra-daemon/src/project_mcp.rs
엔진 결정을 home_project_mcp에 두고, 모르는 서버를 Inbox의 Approval 카드로 올립니다. crates/lyra-app/src/engine/project_mcp.rs
엔진의 대화 열기 발사 전에 두 번 session.mcp.project를 부릅니다. 한 번은 읽기, 한 번은 승인(발사 operation_id를 묶음). engine/producer.rs의 open_conversation_in_tree

session.mcp.project는 daemon이 알리는 기능 목록에 들어 있고, 엔진은 그 이름이 목록에 없는 daemon에는 보내지 않고 session.project-mcp-approval-unavailable로 거절합니다. 서버의 daemon(serve --remote)도 같은 이름의 연산을 받습니다. 요청과 응답은 protocolVersion이 1이어야 하고 모르는 칸은 거절합니다. 연산 틀의 전체는 Operations에 있습니다.

지문과 승인

섹션 제목: “지문과 승인”

지문은 ("project-mcp-v1", 파일 경로, 서버 이름, 서버 정의 전체)를 직렬화한 값의 HMAC-SHA-256입니다. 서버 정의에는 env와 headers의 값과 주소의 비밀도 들어가므로 정의가 한 글자만 바뀌어도 지문이 바뀝니다. 값 자체는 daemon 밖으로 나가지 않고, 쓰고 나면 지워지는 버퍼에만 있습니다.

HMAC 열쇠는 실행 위치마다 따로 있는 32바이트 무작위 값입니다. 기본 배치에서는 agent-config-data/project-mcp/fingerprint.key이고, 소유자만 읽을 수 있는 폴더와 파일이어야 합니다. 이 열쇠는 아무것도 열지 않으므로 자격증명이 아닙니다. 있는 열쇠가 깨졌거나 권한이 열려 있으면 새로 만들지 않고 session.project-mcp-key-unreadable로 멈춥니다. 처음 만들 때는 한 번에 하나만 만들고, 읽는 쪽은 만든 쪽을 기다립니다.

승인 카드는 엔진이 만듭니다.

  1. 서버마다 (작업공간, 서버 이름)의 기록을 home_project_mcp에서 읽습니다. 지문과 실행 위치가 둘 다 같으면 그 결정을 그대로 씁니다.
  2. 기록이 없거나 바뀌었으면 이전 카드를 ExecutionCancelled로 거두고(이전 답은 철회됩니다) 세대를 하나 올려 새 기록과 카드 본문을 한 번에 쓴 뒤 Approval 카드를 올립니다. 카드의 제목은 서버 이름, 설명은 환경 값이 빠진 명령 글입니다. 항목은 inbox.modify로 고칠 수 없습니다(inbox.project-mcp-modification-refused).
  3. 카드가 열려 있으면(Pending) 그 서버는 아직 결정이 없습니다. 서버를 모두 훑은 뒤 열린 카드가 하나라도 있으면 발사를 session.project-mcp-approval-pending으로 거절합니다. 사람이 카드에 답하면 승인은 allowed: true, 거절은 false입니다. 사용자와 프로젝트의 Claude 설정(disabledMcpjsonServers)에서 이미 끈 서버는 승인해도 false입니다.
  4. 카드를 올리지 못하면 이 발사가 쓴 기록과 본문을 되돌립니다. 되돌리지 못했거나 이전 답을 거둔 채 남았으면 거절 코드가 session.project-mcp-approval-incomplete입니다.

할 수 있는 것과 없는 것

섹션 제목: “할 수 있는 것과 없는 것”
  • 켜는 것은 이름뿐입니다. 에이전트의 발사 인자 끝에 --settings <JSON>이 붙고, JSON은 disabledMcpjsonServers, enabledMcpjsonServers(서버 이름 배열)와 enableAllProjectMcpServers: false뿐입니다. 서버의 명령, 주소, env 값은 이 글에 들어가지 않습니다. 승인된 이름은 enabledMcpjsonServers, 나머지는 disabledMcpjsonServers입니다. 8192바이트를 넘으면 거절합니다.
  • 모든 서버에 결정이 있어야 합니다. 승인 요청의 decisions가 서버 수와 다르거나 카탈로그에 없는 이름 · 지문이 있으면 session.project-mcp-unverified입니다.
  • 승인된 것이 발사 직전에 그대로여야 합니다. daemon이 승인 때 만든 목록과 설정 글을 operation_id별로 기억합니다(4096개까지). 준비 단계에서 발사 인자 끝이 그 --settings 글과 같은지 확인하고, 발사 직전 .mcp.json을 다시 읽어 지문 목록이 같은지 확인합니다. 다르면 project MCP configuration changed after approval로 멈춥니다. 그 사이 열쇠가 바뀌어도 멈춥니다.
  • 승인 글에 비밀이 없습니다. 주소의 이름·암호 칸은 지우고 쿼리와 조각은 ?[redacted], #[redacted]로 가립니다. env와 headers는 이름만 보이고, 글 전체를 한 번 더 비밀 가리기에 거칩니다. 명령 글은 4096바이트까지입니다.
  • 결정은 작업공간에 묶입니다. 작업공간을 지우면 그 기록과 카드가 함께 지워집니다.

어떻게 읽고 거절하나

섹션 제목: “어떻게 읽고 거절하나”
코드 언제
session.project-mcp-approval-unavailable 이 실행 위치의 daemon이 session.mcp.project를 알리지 않음
session.project-mcp-config-unreadable .mcp.json 또는 Claude 설정을 읽지 못함, JSON이 아님, 모양이 틀림, 같은 이름이 두 파일에 있음, 모르는 전송. 문장 끝에 파일 경로가 붙습니다.
session.project-mcp-invalid 요청이나 응답의 모양 · 버전 · 길이가 틀림
session.project-mcp-key-unreadable 지문 열쇠를 안전하게 읽지 못함
session.project-mcp-unverified 승인이 없거나 그 사이 바뀜, 결정과 카탈로그가 맞지 않음
session.project-mcp-approval-pending 승인 카드가 열려 있음. 카드에 답한 뒤 다시 보냅니다.
session.project-mcp-approval-incomplete 이전 답을 거둔 채 남았거나 되돌리지 못함
session.project-mcp-store-unavailable home_project_mcp의 버전이나 내용이 맞지 않음
inbox.project-mcp-modification-refused 승인 항목을 고쳐 보내려 함

승인 요청(operation_id를 묶은 두 번째 호출)이 거절되면 엔진은 그 Session의 열기를 LaunchRejected로 실패시킵니다. 열기 실패의 길은 Opening a Session에 있습니다. 전체 코드 목록은 Errors가 정합니다.

아직 없는 것

섹션 제목: “아직 없는 것”
  • 대화 Session의 열기에만 걸립니다. session.mcp.project를 부르는 곳은 엔진의 대화 열기(open_conversation_in_tree) 안의 두 호출뿐이고, 터미널 Session을 여는 길에는 이 호출이 없습니다.
  • 화면에서 닿는 길이 없습니다(위). 승인 카드는 받은 요청에 뜨지만 새 카드를 만드는 대화가 멈춰 있습니다.
  • 한 번 승인한 서버 정의를 사람이 따로 고치거나 해제하는 입구는 없습니다. 지문이 바뀌면 새로 묻습니다.

이 목록은 구현 현황에 올립니다. 카드의 모양과 답하는 길은 Inbox가 설명합니다.
