Overview

This content is not available in your language yet.

Lyra는 프로세스 몇 개가 서로 이어져 돌아갑니다. 이 쪽은 그 전체를 한 장에 담고, 프로세스마다 짧게 소개한 뒤 어느 쪽에서 더 읽을지 알려 줍니다. 쓰는 사람의 눈으로 본 같은 그림은 사용 안내의 구조 설명에 있습니다.

프로세스

섹션 제목: “프로세스”

Lyra 앱

섹션 제목: “Lyra 앱”

화면을 그리는 Electron 프로그램입니다. main이 창과 sidecar를 맡고, renderer는 lyraBridge가 허락한 연산만 부릅니다. 기능을 직접 실행하지 않습니다. 자세한 내용은 Lyra app에 있습니다.

Desktop sidecar

섹션 제목: “Desktop sidecar”

lyra-desktop-sidecar는 main이 띄우는 Rust 실행 파일입니다. 표준 입출력의 한 줄 JSON으로 main과 이어지고, 엔진에는 손님으로 붙습니다. 업데이트와 Jira · GitHub 요청 같은 앱 쪽 네트워크도 여기서 합니다. Desktop sidecar가 설명합니다.

엔진

섹션 제목: “엔진”

lyra-daemon이 OS 계정마다 하나만 돕니다. 앱 자료와 SQLite 장부를 혼자 쓰고, 모든 기능 연산을 결정합니다. sidecar와 명령줄은 엔진의 손님입니다. Engine이 찾기, 띄우기, 하나만 도는 규칙을 설명합니다.

Keeper

섹션 제목: “Keeper”

lyra-daemon --pty-keeper는 PTY와 에이전트 자식을 쥡니다. 엔진이 다시 떠도 터미널이 살아 있게 하려고 따로 있습니다. Keeper가 엔진이 바뀔 때 무엇이 남는지와 넘기기 스위치를 설명합니다.

서버의 lyra-daemon

섹션 제목: “서버의 lyra-daemon”

서버나 WSL 배포판에서 도는 lyra-daemon serve --remote입니다. 이 컴퓨터의 엔진이 SSH 위에서 올리고, 띄우고, 붙습니다. Server daemon이 설치 폴더, 버전, 한가함 규칙을 설명합니다.

명령줄

섹션 제목: “명령줄”

lyra는 명령 하나마다 엔진에 붙었다가 끝납니다. 서버에서는 에이전트가 부른 lyra가 서버의 lyra-daemon을 거쳐 이 컴퓨터의 엔진에 닿습니다. Command line이 두 길을 설명합니다.

에이전트와 셸 자식

섹션 제목: “에이전트와 셸 자식”

Session이 여는 에이전트 CLI와 사람이 여는 셸입니다. keeper나 서버의 lyra-daemon이 띄우고, 환경과 시작 폴더 규칙을 따릅니다. Agent and terminal children이 설명합니다.

다음에 어디로 가나

섹션 제목: “다음에 어디로 가나”
알고 싶은 것 갈 곳
프로세스 사이의 메시지 모양, 버전, 한도 Connections: 창 다리, sidecar 줄, 손님 소켓, keeper 소켓, Link, WSL, CLI 다리
파일과 테이블이 어디에 있고 누가 쓰는지 Data: 폴더, home.sqlite, 서버 상태, 자격 증명, 로그
화면의 기능이 코드에서 어떻게 지나가는지 Features: Sessions, Inbox, Orchestration 등
시간 순서로 본 하나의 일 Lifecycles: Session 열기, 엔진 시작, 업데이트
확장하는 길 Extending: 플러그인, 모듈, 스킬, 프로젝트 MCP
연산 이름과 오류 코드 전체 Lookup: 연산, 오류, 계약, crate, 구현 현황

Connections, Data, Features, Lifecycles, Extending, Lookup의 쪽은 차례로 채워지고 있습니다. 아직 없는 쪽의 링크는 올라오면 열립니다.
