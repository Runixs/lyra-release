Agent and terminal children

This content is not available in your language yet.

자식은 Lyra가 일을 시키려고 띄우는 프로그램입니다. 둘로 나뉩니다. Session이 여는 에이전트 CLI(claude_code, codex, opencode)와 사람이 여는 셸입니다. 둘 다 의사 터미널(PTY) 안에서 돕니다. 자식을 띄우는 것은 앱도 엔진도 아닙니다. 이 컴퓨터에서는 keeper가, 서버에서는 서버의 lyra-daemon이 띄웁니다. 두 프로세스는 같은 프로세스 감독자(lyra-process의 ProcessSupervisor)를 씁니다.

어디서 도는가

섹션 제목: “어디서 도는가”

자식은 그 자식을 띄운 프로세스와 같은 컴퓨터, 같은 OS 계정에서 돕니다. 에이전트 CLI는 Session이 고른 프로그램이고, 셸은 사람이 고른 셸입니다(Windows의 New Terminal, New PowerShell, New Git Bash, 그 밖의 OS의 셸).

누가 언제 시작하고 끝내는가

섹션 제목: “누가 언제 시작하고 끝내는가”

시작

섹션 제목: “시작”
  • 에이전트: 엔진이 Session을 열면 keeper(이 컴퓨터) 또는 서버의 lyra-daemon이 open_agent_terminal로 띄웁니다. Session 열기의 전체 흐름은 Session 열기에 있습니다.
  • 셸: 엔진이 터미널을 열면 open_terminal로 띄웁니다. 에이전트 쪽 통로와 달리 셸은 사용자 환경 위에 요청한 값을 얹습니다.

띄우는 순서는 같습니다. 먼저 프로세스 무리(process group)를 만들고, 그 안에서 자식을 띄우고, 플랫폼 표식을 붙이고, 살아 있는 동안만 목록에 올립니다. 에이전트 자식은 한 번 더 확인을 받습니다. open_agent_terminal은 서비스 종류의 요청만 받고, 명령 제한 시간이나 정상 종료 콜백, 붙들린 폴더가 있으면 거절합니다. PTY 크기(칸과 줄)가 범위를 벗어나도 거절합니다.

끝

섹션 제목: “끝”
어떻게 일어나는 일
자식이 스스로 끝남 뿌리가 끝난 뒤 자손에게 유예를 주고(settle, 기본 5초), 그 안에 끝나지 않으면 무리째 끊습니다. 끊었으면 종료 결과의 cut이 참입니다.
명시적 닫기 무리째 곧바로 끊고(close), 최대 2초 안에 무리가 비었는지 확인합니다. 살아남은 자손이 있으면 StopSurvivor로 알립니다.
손잡이를 버림 닫지도 settle하지도 않고 PTY 손잡이를 버리면 무리를 끊습니다.
띄운 프로세스가 죽음 남은 자식은 플랫폼 표식으로 고아(orphan)로 잡힙니다. PTY의 주 쪽 손잡이도 사라져 다시 붙들 수 없습니다.

끝난 PTY는 목록에서 빠집니다. 터미널은 장부에 쓰지 않고 살아 있는 동안만 목록에 나옵니다. keeper는 별도로 PTY마다 custody 기록을 남깁니다(keeper).

누구와 말하는가

섹션 제목: “누구와 말하는가”

환경 규칙

섹션 제목: “환경 규칙”

이 쪽에는 값이 없습니다. 이름과 규칙만 있습니다.

에이전트와 터미널: 사용자 환경에서 거른다

섹션 제목: “에이전트와 터미널: 사용자 환경에서 거른다”

에이전트와 터미널 자식은 사용자 환경을 물려받되 다음을 걸러 냅니다.

  • LYRA_로 시작하는 이름은 모두 뺍니다(Windows는 대소문자 무시). 부모의 Lyra 내부 값이 자식에게 새어 가지 않게 하려는 것입니다.
  • 다른 에이전트 실행기의 자식 신원과 메시지 통로를 가리키는 값(여러 이름)과 Electron의 ELECTRON_RUN_AS_NODE, ELECTRON_NO_ATTACH_CONSOLE, NO_COLOR도 뺍니다.
  • FORCE_COLOR와 CLICOLOR는 값이 0이면 뺍니다.
  • 부모의 TERM과 COLORTERM은 뺀 다음, 터미널 자식에게 TERM=xterm-256color와 COLORTERM=truecolor를 정합니다. 요청이 직접 정한 값이 있으면 그 값이 이깁니다.
  • Profile에 끝점이 따로 정해져 있으면, 부모에서 온 경로 키를 뺍니다. claude_code는 API 키, 인증 토큰, 기본 주소, 클라우드 사용 표시 같은 값이고, opencode는 설정 경로를 가리키는 값입니다.

명령과 서비스: 허용 목록만 넘긴다

섹션 제목: “명령과 서비스: 허용 목록만 넘긴다”

명령과 서비스 자식은 걸러진 환경입니다. 기본으로 넘기는 이름만 갑니다. PATH, HOME, USER, LANG, Windows의 SystemRoot, USERPROFILE, APPDATA, LOCALAPPDATA, TEMP 등이 들어 있고, 요청이 더 청한 이름은 허용 목록에 있을 때만 갑니다. 비밀이 담긴 값은 이 목록에 없으면 가지 않습니다.

Lyra가 정해서 넣는 값

섹션 제목: “Lyra가 정해서 넣는 값”
이름 누구에게 무엇
LYRA_SESSION_ID, LYRA_SESSION_GENERATION 호출자 Session이 있는 에이전트 lyra 명령을 부른 Session의 번호와 세대. 요청이 호출자 Session을 가리킬 때만 넣고, 사람이 연 터미널에는 넣지 않습니다. codex는 자기 셸 환경 정책이 부모에서 온 표지를 버리므로, 같은 두 값을 -c 인자로도 싣습니다.
LYRA_TERMINAL_ID, LYRA_TERMINAL_INCARNATION, LYRA_TERMINAL_NONCE 셸 이 터미널의 표지 셋. 셸은 부모에서 온 표지를 받지 않고 자기 것만 갖습니다.
LYRA_CLI_DAEMON_ENDPOINT, LYRA_CLI_ROUTE_REF 서버의 에이전트 서버의 lyra-daemon의 CLI 다리 끝점과 길 표지(명령줄). 자식의 메모리에만 있습니다.

요청이 LYRA_SESSION_ID, LYRA_SESSION_GENERATION, LYRA_CLI_DAEMON_ENDPOINT, LYRA_CLI_ROUTE_REF를 환경 키로 스스로 청하면 session-caller-environment-reserved로 거절합니다. 이 이름들은 daemon만 정합니다.

폴더 규칙

섹션 제목: “폴더 규칙”

에이전트는 Session이 정한 폴더(cwd)에서 시작합니다. 이 폴더는 실행 위치의 철자를 갖는 경로로 바뀌어 전달되고, 띄우기 전에 있는지 봅니다. 없으면 띄우지 않습니다. 셸도 시작 폴더가 있으면 같은 확인을 받습니다. 에이전트가 lyra를 찾는 폴더는 같은 실행 호스트의 lyra-daemon 옆 폴더이고, 자식의 PATH 맨 앞에 놓입니다. 부모와 전역 PATH는 바꾸지 않습니다.

무엇을 지니는가

섹션 제목: “무엇을 지니는가”
  • 자식의 PID와 시작 세대(OS가 본 시작 시각): pid 재사용과 구분하려는 것입니다.
  • 프로세스 무리의 표식과 목록 줄
  • 마지막으로 적용한 PTY 크기

글자는 자식 쪽 층을 지나지 않습니다. 읽는 끝과 쓰는 끝은 한 번만 꺼낼 수 있습니다.

전역 설정을 가리는 실행 조건: lyra-sandbox

섹션 제목: “전역 설정을 가리는 실행 조건: lyra-sandbox”

lyra-sandbox는 에이전트가 사용자의 전역 설정과 전역 프롬프트를 볼 수 없는지 확인하는 선택적 실행 조건을 가집니다. 이 빌드에서는 어떤 프로그램도 이 crate를 부르지 않아서, 위의 자식 시작은 이 조건을 거치지 않습니다(구현 현황).

  • 조건이 만들어지는 진입점은 셋입니다: Projects에서 직접 여는 Session(ProjectSession), 오케스트레이션 아바타가 여는 Session(OrchestrationAvatar), 워크플로 실행이 여는 Session(WorkflowExecution). 사람이 켜고 끈 선택과 진입점의 기본값을 구분해 기록합니다.
  • 준비(prepare)가 증거를 모아 판정하면 결과는 Passed(모든 증거가 판정됐고 전역 표식이 보이지 않음)나 Failed(실패 또는 미확인)입니다. 결과에는 민감한 원문이 들어가지 않습니다.
  • 통과한 조건은 한 Session과 그 자식이 함께 쓰는 불변 조건이 되고, 자식마다 임대(SandboxChildLease)를 받습니다. 조건의 상태는 Ready → Active → Closing → Releasing → Released로 가고, 정리가 실패하면 같은 출처의 재시도만 받습니다.
  • 도구의 의미 프로필과 운영체제별 산출물 지문(SandboxToolManifest)을 비교하는 대상은 macOS와 Windows 둘입니다. 다른 곳에서는 UnsupportedPlatform입니다.

멈추면 어떻게 되는가

섹션 제목: “멈추면 어떻게 되는가”

위 “끝” 표가 그것입니다. 정리 못 한 자식이 있으면 lyra process list에 error 줄로 보이고, 고아는 orphan-<pid>-<start> 이름으로 나옵니다. 사람은 그 PID를 확인해 해당 프로그램에서 끝내면 됩니다.
