Command line

This content is not available in your language yet.

lyra는 사람이나 에이전트가 터미널에서 부르는 실행 파일입니다. 명령 문법, 입력 확인, 결과 표현, 종료 코드를 맡고, 일 자체는 엔진에 시킵니다. 저장소를 열지 않고 명령 하나마다 엔진에 붙었다가 끝납니다. 명령의 사용법은 명령줄 안내가 설명합니다. 이 쪽은 프로세스로서의 lyra를 설명합니다.

어디서 도는가

섹션 제목: “어디서 도는가”

apps/cli는 인자와 표준 입출력을 crates/lyra-cli에 넘기고 그 종료 코드로 끝나는 얇은 실행 파일입니다. 판단은 모두 lyra-cli에 있습니다.

자리 위치
이 컴퓨터 앱 설치본의 bin/. 앱이 스킬 명령을 부를 때 이 파일을 씁니다. 에이전트와 터미널의 PATH 맨 앞에는 실행 호스트의 lyra-daemon 옆 폴더가 놓입니다.
서버 서버의 lyra-daemon을 올릴 때 같은 버전 폴더에 lyra도 함께 올립니다(<home>/.lyra/daemon/<version>-<target>/lyra).

종료 코드는 넷입니다.

코드 뜻
0 성공
1 실패. 결과를 아는 실패입니다.
2 사용법이 틀림
3 결과를 모름

누가 언제 시작하고 끝내는가

섹션 제목: “누가 언제 시작하고 끝내는가”

사람이나 에이전트가 부르면 시작하고, 명령 하나를 마치면 끝납니다. 시작할 때 이 계정의 설치 잠금을 먼저 확인합니다. 설치가 잠금을 쥐고 있으면 아무것도 열지 않고 거절합니다. 다음에 Ctrl-C 표시를 하나 설치하고, 명령을 처리합니다.

lyra는 엔진을 띄우지 않습니다. 못 붙으면 lyra daemon start를 안내하며 코드 1로 끝납니다. 엔진을 띄우는 명령은 lyra daemon start이고, 그 명령은 셸에서 엔진을 떼어 띄웁니다(엔진).

누구와 말하는가

섹션 제목: “누구와 말하는가”

길은 환경에서 정해집니다.

  • 엔진이 있는 컴퓨터: 환경에 서버 길 표지가 없으면 lyra는 계정의 엔진 폴더(<account home>/.lyra/runtime/engine)의 메타 파일 home-runtime.json을 읽어 home.sock(Windows는 파이프)에 붙습니다. 이 폴더는 환경 변수가 아니라 계정의 프로필에서 구합니다. 필터링된 에이전트 환경이 폴더를 가리지 못하게 하려는 것입니다. 계정 홈을 읽지 못하면 app-data-unavailable로 끝납니다.
  • 서버: 앱이 서버에 띄운 에이전트의 환경에는 LYRA_CLI_DAEMON_ENDPOINT와 LYRA_CLI_ROUTE_REF가 들어 있습니다. 둘 다 있으면 lyra는 계정 폴더를 찾지 않고 그 서버의 lyra-daemon 끝점에 붙고, daemon이 Session을 준비한 바로 그 엔진 연결로 프레임을 전합니다. 둘 중 하나만 있으면 거절합니다. 이 값은 자식의 메모리에만 있고 자격 증명이 아닙니다.

누가 부르는지는 환경에서 읽습니다. 에이전트 Session이 띄운 명령에는 LYRA_SESSION_ID와 LYRA_SESSION_GENERATION이 있고, 터미널에서 부르면 LYRA_TERMINAL_ID, LYRA_TERMINAL_INCARNATION, LYRA_TERMINAL_NONCE 셋이 있습니다. Session 쌍이 먼저이고, 없으면 터미널 표지 셋이 모두 있어야 합니다. 둘 다 없으면 사람입니다. 일부만 있거나 모양이 틀리면 caller-context-invalid로 거절합니다. 값은 여기 쓰지 않습니다.

서버에서 이 길로 가는 에이전트의 lyra는 엔진 폴더가 없으므로, 요청 기록 같은 작은 파일을 설치된 daemon 버전 폴더 옆 cli/에 둡니다. 설치된 사본이 아닌 lyra는 그 폴더를 만들지 않고 app-data-unavailable로 끝납니다.

무엇을 지니는가

섹션 제목: “무엇을 지니는가”

명령 사이에 남는 상태는 없습니다. 요청 기록과 기다림 기록 같은 작은 파일만 위의 폴더에 둡니다. 비밀(--key-file이나 표준 입력)은 64KiB까지만 읽습니다.

문자 화면 lyra tui: lyra-tui와 lyra-vt-toolchain

섹션 제목: “문자 화면 lyra tui: lyra-tui와 lyra-vt-toolchain”

lyra tui는 동사 없는 명령으로, 터미널 안에 Lyra의 문자 화면을 엽니다. 도움말 문장은 “Linux, root가 아닌 계정”을 말합니다. 시작 점검은 엔진을 부르기 전과 터미널을 바꾸기 전에 lyra-tui가 순수 함수(check_start)로 합니다. 보는 사실은 다섯입니다.

  • 이 빌드가 칸의 터미널 에뮬레이터를 갖고 있는지(Linux와 macOS 빌드는 갖고 Windows 빌드는 갖지 않습니다)
  • 계정이 root가 아닌지
  • 표준 입력과 표준 출력이 둘 다 터미널인지
  • 터미널 크기가 열 40 이상, 행 10 이상인지(MIN_COLUMNS · MIN_ROWS)
  • 운영체제가 알려 주는 크기를 읽을 수 있는지

통과하면 lyra-tui의 host가 터미널을 raw 모드로 바꾸고 표준 입력을 읽는 스레드, 신호, 엔진 읽기를 돌립니다. 키 해석, 트리, 연결과 상태, 문장, 칸 나누기와 붙기는 모두 값만으로 도는 logic이 결정하고, view는 그 모델을 버퍼에 그립니다. 칸 안의 터미널은 emulator가 맡습니다.

lyra-vt-toolchain은 그 터미널 에뮬레이터 라이브러리를 고정된 버전으로 쥐는 crate입니다. 쓰는 버전 둘은 정확한 커밋으로 고정되어 있고, 에뮬레이터 쪽 라이브러리는 어떤 빌드 설정에서도 릴리스로 지어야 하며, 필요한 빌드 도구가 없거나 맞지 않으면 이름을 대고 멈춥니다. 이 규칙은 tests/toolchain.rs가 검사합니다. lyra-tui는 Linux와 macOS에서만 이 crate의 기능을 켭니다.

멈추면 어떻게 되는가

섹션 제목: “멈추면 어떻게 되는가”
  • 엔진이 없음: 코드 1과 lyra daemon start 안내로 끝납니다. 결과를 아는 실패이므로 코드 3이 아닙니다.
  • 명령 도중 끊김: 결과를 알 수 없으면 코드 3입니다.
  • Ctrl-C: 표시를 하나만 세웁니다. 이 처리기를 설치하지 못하면 경고를 쓰고, Ctrl-C가 명령을 곧바로 끝냅니다.

설계와 다른 점

섹션 제목: “설계와 다른 점”

crates/lyra-cli/src/lib.rs와 guest.rs의 머리말은 엔진을 아직 home이라 부르고 home 손님이라고 적습니다. 이름만 낡았고 동작은 위와 같습니다. 구현 현황에 올립니다.
