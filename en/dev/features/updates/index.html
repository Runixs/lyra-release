Updates

This content is not available in your language yet.

업데이트는 앱 묶음(앱, lyra-desktop-sidecar, lyra-daemon, lyra)을 새 버전으로 바꾸는 일입니다. 이 페이지는 연산 · 기록 · 설정을 모읍니다. 시간 순서(확인 → 내려받기 → 적용 → 다시 열기)와 각 걸음이 실패할 때는 Updates lifecycle이, 서버의 daemon을 올리고 버전을 맞추는 일은 Server daemon이 설명합니다. 표는 Updates details에 있습니다.

화면에서 하는 일

섹션 제목: “화면에서 하는 일”
  • 아래 막대의 버전 칸(VersionCell)에 새 버전이 있으면 New 표시가 붙고, 누르면 업데이트 카드(UpdateCard)가 열립니다.
  • 설정 › 정보 › 앱(AppSection)에서 버전, 업데이트, 서버의 lyra-daemon의 버전, 기록을 봅니다. 조작은 설정 화면에 있습니다.
  • 명령줄에서는 lyra update status · check · apply · rollback · remote-status · recover입니다. check는 업데이트의 확인과 내려받기를 앱이 맡는다고 알릴 뿐이고, apply는 앱이 받아 둔 것을 선택한 엔진에 적용합니다(lyra).

새 버전의 출처, 서명자, 채널(pilot · stable)은 설치본이 빌드할 때 굳히는 값(ReleaseBuildConfig)이어서 화면에서 바꾸는 설정이 없습니다.

코드 속 길

섹션 제목: “코드 속 길”

확인과 내려받기: 앱 쪽

섹션 제목: “확인과 내려받기: 앱 쪽”

app.update.check · app.update.download는 앱이 직접 합니다(app_http/updates.rs). 엔진은 HTTP를 하지 않고, 앱이 서명과 지문을 확인해 돌려준 검증된 설치본 참조(artifactRef)만 받습니다. 화면은 설치본을 고를 수 없고, 적용할 때 엔진이 자기 쪽 목록에서 다시 찾습니다.

  • 설명(descriptor)은 1 MiB, 설치본은 512 MiB까지 받고, 이동 응답은 5번까지 따라갑니다(release.rs).
  • 출처는 허용 origin 목록 안에 있어야 하고, 설명의 서명(Ed25519)과 채널, 대상 OS가 설치본의 설정과 같아야 합니다. 내려받기 진행은 update-progress 사건으로 화면에 가고, 바이트 사건은 1초에 네 번까지입니다(BYTE_EVENT_GAP 250 ms).

적용: sidecar와 선택된 엔진

섹션 제목: “적용: sidecar와 선택된 엔진”

update.apply는 ops.rs에서는 update-source-app-only(Absent)로 거절합니다. 적용은 sidecar의 explicit_apply.rs(사람만 부르는 입구)가 선택된 엔진의 자기 단계 설치본을 적용하게 하는 길이고, 렌더러는 설치본을 고르지 못합니다. 적용에는 두 방식이 있습니다.

  • now(지금 바로): 바로 적용합니다.
  • quiet: 기다리는 업데이트가 쓰는 방식입니다. 응답 중인 대화나 도는 명령이 있으면 엔진이 끊지 않고 engine-update-deferred로 거절하고, 업데이트는 다시 기다립니다.

엔진이 engine-update-in-progress로 답하면 이미 도는 업데이트가 있다는 뜻이어서, update.await-running이 끝나기를 기다린 뒤(최대 630초) 새 요청 번호로 한 번 더 보냅니다.

기다리는 업데이트

섹션 제목: “기다리는 업데이트”

update.arm이 내려받은 뒤 아무것도 멈추지 않는 점검을 하고 update-armed.json을 씁니다. update.await-quiet이 엔진의 update.activity를 2초(WAIT_POLL)마다 읽다가 한 번에 600초까지 기다린 뒤 같은 수로 답하고, 앱이 다시 부릅니다. 고요해지면 앱이 quiet 방식으로 적용을 보내고, update.disarm(취소)이 기록을 지웁니다.

update.activity가 바쁨으로 세는 것은 대화에 답하고 있는 Lyra 화면 대화와 Command 줄입니다. 터미널과 서비스는 세지 않습니다. 세지 못한 수는 0이 아니라 null입니다. 도는 명령을 키퍼가 가진 전체 목록으로 다시 세는 listing은 고요해 보일 때만, 30초(QUIET_RETRY_AFTER)에 한 번까지 합니다.

서버의 lyra-daemon

섹션 제목: “서버의 lyra-daemon”

서버의 daemon은 이 앱 묶음이 올립니다. 연결할 때마다 엔진의 lyra-link가 버전 관찰을 남기고, ServerVersionGate가 버전이 맞지 않거나 설치에 실패한 서버의 새 작업을 막습니다. 더 나중 순번의 맞는 악수만 막은 것을 풉니다. 버전 자료 없는 실패를 버전 불일치로 꾸미지 않고 통상의 연결 실패로 둡니다. 서버의 버전은 설정 › 정보 › 앱의 서버 목록(DaemonVersions)이 update.remote-status로 읽어 보입니다. 이 엔진 코어는 보조 기록을 쥔 감싸개가 없으면 이 연산을 update-remote-status-unavailable로 거절합니다.

빌드 정체: lyra-build-identity

섹션 제목: “빌드 정체: lyra-build-identity”

이 crate는 컴파일 때 정해져서 실행 중에는 환경, 파일, 요청 어느 것으로도 바꿀 수 없는 값을 가집니다. 제품 버전(PRODUCT_VERSION), 빌드 번호(BUILD_ID, 커밋), 대상(TARGET, Rust 대상 이름), 릴리스 신뢰 설정(RELEASE_CONFIG_JSON, 없으면 null), 제품 빌드 대상(internal 또는 external, 정하지 않으면 없음)입니다.

앱의 release_config.rs와 apps/daemon의 authority/images.rs · authority/lifecycle_artifacts.rs가 이 값으로 “이 빌드가 기대하는 설치본”을 만들고 설치본의 서명 증거와 견줍니다. 제품 빌드 대상이 없는 빌드는 설치본을 놓지 않고 거절합니다. 빌드 스크립트는 test-seams 기능으로 짓는 빌드에 릴리스 키를 함께 넣으려 하면 빌드를 멈춥니다.

남기는 기록

섹션 제목: “남기는 기록”
어디에 무엇
<앱 자료>/release-ledger.json 버전 기록: 지금 버전(active), 바로 앞 버전(previous), 받아 둔 버전(staged)과 진행 중인 전환. 문서 release-ledger
<앱 자료>/update/last-result.json 마지막 적용 · 되돌림의 결과(formatVersion 1, outcome, action, warningCode)
<앱 자료>/update/native-transition.json 끝나지 않은 전환. 있으면 update.check가 activation-unverified로 거절합니다.
update-armed.json 기다리는 업데이트(formatVersion 1). 앱을 다시 켜도 같은 로그인 안에서는 남고, 컴퓨터를 다시 켜거나 로그아웃하면 버립니다.
app-update-result.json · update-ended-work.json 앱 단계의 결과와, 업데이트가 끝낸 일의 기록. 다음에 열리는 앱이 app.update.result · app.update.ended-work로 읽고 …-ack로 확인합니다.
home.sqlite의 update_companion 구성 요소 서버 보조 기록(COMPANION_FORMAT_VERSION 1)의 자리. 이 빌드의 lyra update remote-reset은 이 기록이 없어졌다고 알립니다.

release-ledger는 버전을 적용하다 중단됐을 때 다음 시작에서 읽습니다. 되살린 전환이 activating이면 recovery-required입니다. 폴더의 위치는 Folders가 설명합니다.

연산

섹션 제목: “연산”

연산 이름과 한 줄 설명은 details에 모았습니다. 전체 연산 목록은 Operations가 정합니다.

한도와 기본값

섹션 제목: “한도와 기본값”
값 크기
설명 · 설치본 1 MiB · 512 MiB
따라가는 이동 응답 5번
기다림이 활동을 읽는 간격 2초, 못 읽으면 두 배씩 늘려 최대 30초
update.await-quiet 한 번 600초
이미 도는 업데이트를 기다림 630초

실패할 때

섹션 제목: “실패할 때”

UpdateReason의 코드로 알립니다. 뜻은 details에 있습니다. 모르는 상태를 성공으로 바꾸지 않아서, 적용을 확인하지 못했으면 activation-unverified이고 그 뒤의 새 확인을 거절합니다. 같은 일이 이미 도는 중이면 update-in-progress입니다.

아직 없는 것

섹션 제목: “아직 없는 것”
  • 서버 보조 기록과 update remote-reset은 이 빌드에서 없어졌고(lyra update recover가 대신함), 엔진 코어는 update.remote-status를 보조 기록 감싸개가 없을 때 거절합니다. 설계와의 차이는 구현 현황에 적어 둡니다.
