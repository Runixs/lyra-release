Profiles and agents

This content is not available in your language yet.

Profile(프로필)은 어느 에이전트 프로그램을 어디서 돌릴지 가리키는 이름표입니다. 모델과 노력 단계는 Session을 열 때 고르고 Profile에 들지 않습니다. 에이전트의 종류는 claude · opencode · codex 셋(RuntimeKind)입니다. 연산과 표의 전체 목록은 Profiles and agents details에 있습니다.

화면에서 하는 일

섹션 제목: “화면에서 하는 일”
  • 설정 › 연결 › 에이전트(RunSection)에서 이 컴퓨터와 서버의 에이전트 설치 상태를 보고, Profile을 복사해 더하고(profile.add), 고치고(profile.update), 지우고(profile.remove), 실행 명령(LaunchCommandEditor)을 고치고 시험합니다. 조작은 설정 화면에 있습니다.
  • 설정 › 에이전트 스킬(AgentSkillsSection · HostSkillsSection)에서 이 컴퓨터와 서버마다 Lyra의 스킬이 설치됐는지 보고 설치 · 고치기를 합니다.
  • 새 Session을 열 때 작성 칸의 선택(Profile, 모델, 노력 단계)을 고릅니다(Sessions and Turns).

코드 속 길

섹션 제목: “코드 속 길”

route_unguarded는 profile. · runtime.을 ops.rs에서, session.configuration.* · session.defaults.* · session.models*를 engine/sessions.rs에서, skills.*를 engine/skills.rs에서 받게 합니다.

Profile

섹션 제목: “Profile”
  • 정본(canonical): 탐지가 만든 것이고, Host마다 에이전트 종류마다 하나입니다. 처음 이름은 종류 이름(claude · codex · opencode)입니다. 정본은 고치거나 지울 수 없습니다(canonical-profile-read-only).
  • 파생(derived): 사람이 정본을 복사해 만든 것입니다. 이름(64자 이하), 모델, 아이콘 · 이미지 · 색, 실행 위치를 정합니다. 지우기를 시작하면 Removing이 되어 고를 수 없고, 지움이 끝나면 그 Profile의 남은 모델 목록도 지웁니다.
  • 버전 번호(revision)가 맞아야 고칩니다. 어긋나면 stale-profile-revision입니다.
  • 이 빌드에서 명시 엔드포인트와 자격증명 참조는 받지 않습니다. profile.add · profile.update에 endpoint(runtime-default가 아닌 것)나 credentialRef를 주면 profile.endpoint-removed로 거절하고, 에이전트 실행 파일 · 설정 파일 · 실행 전 명령으로 설정하라고 알립니다. 모델에는 엔드포인트 종류(공급자 셋)와 주소를 담는 자리가 남아 있지만 쓰는 길이 없습니다.

에이전트 탐지

섹션 제목: “에이전트 탐지”

runtime.detect는 Host의 daemon에 세 에이전트 종류의 설치를 묻고, 그 답으로 정본 Profile을 맞춥니다. 상태는 Confirmed · NotOnPath · NotChecked · NeedsFixing 넷입니다. 같은 Host의 두 번째 요청은 새로 보내지 않고 첫 답을 함께 기다립니다. 한도는 전체 15초이고, 파일 찾기 5초, 버전 읽기 5초(다시 시도 8초)입니다. runtime.detect-connect는 연결이 없으면 연결한 뒤 탐지하고, runtime.detect-kind는 한 종류의 확인 안 한 프로그램만 읽습니다(--agent용).

실행 명령과 기본 모델

섹션 제목: “실행 명령과 기본 모델”
  • session.configuration.show · set: Profile 하나의 실행 명령 설정을 읽고 씁니다. 버전이 맞아야 쓰고 어긋나면 session.configuration-conflict입니다. 모르는 필드는 session.command-template-invalid(unknown-field)이고, guarded는 읽기 전용입니다. session.configuration.test.*로 시험해 봅니다.
  • session.defaults.show · set: 에이전트 종류마다 기본 모델을 읽고 씁니다. 버전이 맞아야 쓰고, 모델 이름은 안전한 글자만 받습니다. 캐시 수명은 범위별로 off(타이머 숨김)나 값 없음(자동, Lyra가 수명을 청하지 않음)으로 둡니다. 5m · 1h도 받지만 화면은 쓰지 않습니다. cacheOnly와 profileId를 주면 Profile 하나의 행을 읽고 씁니다(설정 › 에이전트의 캐시 타이머). 고를 때는 Profile 자기 행이 값이 없어도 먼저이고, 없으면 에이전트 종류의 행을 봅니다. 전체(general) 행은 더 읽지 않습니다. 저장소는 처음 열 때 한 번 버전 2로 옮겨지며, 저장된 5m · 1h와 전체 값은 자동이 됩니다. 그 뒤 0.2.20 이하는 이 저장소를 거절합니다(engine/cache_preferences.rs, engine/producer.rs cache_defaults).
  • session.models · session.models.remembered · session.commands: 에이전트의 모델 목록과 / 명령 목록을 Host에서 읽거나 엔진이 기억한 마지막 목록을 읽습니다.

스킬 설치

섹션 제목: “스킬 설치”

skills.inventory는 Host의 daemon이 함께 설치된 lyra의 skills list --installed --json을 돌려 설치 상태를 읽고(daemon은 부르는 쪽이 고른 명령을 돌리지 않습니다), skills.apply는 install · update · link · replace-old-copy 중 하나를 에이전트(claude · codex · opencode · shared · all)에 적용합니다. 설치하는 스킬은 lyra-orchestration · lyra-cli · lyra-workflow 셋입니다. 이미 있는 연결 위에서만 부르고, 끊긴 Host에 조용히 연결하거나 같은 변경을 다시 보내지 않습니다. 옛 daemon이면 skills.management-unavailable입니다. 묶음 all의 link · replace-old-copy는 먼저 인벤토리를 읽고 설치된 에이전트만 고릅니다.

남기는 기록

섹션 제목: “남기는 기록”
어디에 무엇
<앱 자료>/profiles.json Profile 모음. { "revision": n, "body": … } 한 장이고 저장 형식은 버전 3(SUPPORTED_FORMAT_VERSION)
home.sqlite의 home_launch_configuration Profile 하나의 실행 명령 설정과 버전
home.sqlite의 home_launch_defaults 에이전트 종류 하나의 기본 모델과 버전
home.sqlite의 home_cache_preferences 캐시 수명(범위별 off 또는 자동, 버전). 표 버전 2
home.sqlite의 home_profile_test_summary Profile의 실행 명령 시험 요약

profiles.json은 문서 한 장을 짧은 쓰기 잠금과 버전 번호 비교로 원자적으로 바꿉니다. 다른 곳이 먼저 바꿨으면 쓰지 않고 data.changed-elsewhere로 알립니다. 폴더의 위치는 Folders가 설명합니다. Profile이 쓰는 자격증명은 Credentials가 설명합니다.

연산

섹션 제목: “연산”

연산 이름과 한 줄 설명은 details에 모았습니다. 전체 연산 목록은 Operations가 정합니다.

한도와 기본값

섹션 제목: “한도와 기본값”
값 크기
Profile 이름 64자 이하
탐지 전체 15초
skills.inventory · skills.apply의 링크 시한 15초 · 60초

실패할 때

섹션 제목: “실패할 때”
  • 정본을 고치려 하면 canonical-profile-read-only, 같은 이름이 있으면 name-conflict, 이름이 겹쳐 하나로 고를 수 없으면 ambiguous-profile-name입니다.
  • 명시 엔드포인트를 주면 profile.endpoint-removed입니다.
  • 설치를 확인하지 못했으면 탐지는 NotChecked로 남고, 성공으로 바꾸지 않습니다. 링크가 끊겼으면 detection-call-failed입니다.
  • 옛 daemon에 스킬 관리가 없으면 skills.management-unavailable, daemon의 답을 읽을 수 없으면 skills.answer-unreadable입니다.

코드 전체는 details에 있습니다.

아직 없는 것

섹션 제목: “아직 없는 것”

명시 엔드포인트와 자격증명 연결이 모델에는 있지만 쓰는 길이 막혀 있는 점은 구현 현황에 적어 둡니다.
