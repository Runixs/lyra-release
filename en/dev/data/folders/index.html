이 컴퓨터에서 Lyra가 쓰는 폴더는 셋입니다. OS 계정마다 하나인 계정 런타임 폴더, 앱이 로그를 쓰는 앱 자료 폴더, Electron이 자기 몫으로 쓰는 Electron 자료 폴더입니다. 모든 경로의 집은 이 페이지입니다. 프로그램 쪽 설명은 엔진, keeper, 앱, sidecar 페이지가 하고, 서버의 폴더는 Server state가 합니다.

계정 런타임 폴더

섹션 제목: “계정 런타임 폴더”

경로는 <account home>/.lyra/runtime입니다. <account home>은 OS의 계정 기록에서만 읽습니다. 환경 변수 HOME과 USERPROFILE은 읽지 않습니다. 루트 권한으로 돌거나 실제 UID와 유효 UID가 다르면 경로를 정하지 않고 거절합니다(AccountUnverified). 이 경로를 구하는 함수는 폴더를 만들지 않습니다. 만드는 쪽은 엔진의 계정 처음 준비 단계이고, 그 단계가 engine/ · keeper/ · control/을 계정 전용 폴더로 만듭니다.

계정 폴더 바로 아래

섹션 제목: “계정 폴더 바로 아래”
항목 쓰는 프로그램 범위 지워도 되는가
format.json 엔진의 계정 처음 준비 단계 계정 지우면 안 됩니다. 제품 데이터가 남아 있는데 표지가 없으면 엔진은 시작을 runtime-clean-start-required로 거절합니다.
format.json.pending, format.json.pending.tmp, format.json.tmp 같은 단계 계정 초기화하는 동안만 있는 이름입니다. 남아 있는데 계정이 증명하지 못하면 엔진은 runtime-layout-unavailable로 거절합니다.
init.lock 같은 단계 계정 계정을 처음 준비하는 동안만 쥡니다. 데이터가 아닙니다.
install.lock 설치 계정 데이터가 아닙니다. 이 파일만 있는 루트는 새 계정으로 봅니다.
logs/engine-start.log, logs/keeper-start.log 엔진 · keeper 계정 시작할 때마다 그 프로그램의 파일을 새로 씁니다. 비어 있으면 성공, 한 줄이면 실패입니다. 자세한 모양은 Logs에 있습니다.
logs/engine-start-progress.json 엔진 계정 시작 단계를 화면에 보이려는 표시입니다. 시작 성공의 증거가 아닙니다.
updates/ 업데이트 계정 release-ledger.json은 앱 설치가 이전 앱의 버전 목록으로 읽는 파일입니다. release-ledger.json과 releases.json은 계정 폴더 검사가 제품 데이터로 셉니다. staged-artifacts/(내려받아 검증한 꾸러미)는 데이터가 아니라 준비 자리입니다.
versions/<product>/<target>/ 업데이트 계정 검증을 마친 설치본 자리입니다. 데이터가 아니라 프로그램 파일이라서, 서버처럼 앱 없이 설치만 먼저 해 둔 계정도 새 계정으로 봅니다.
control/activation-app.sqlite keeper 쪽 활성화 기록 계정 업데이트와 엔진 교체의 단계를 적은 장부입니다. 제품 데이터로 셉니다.

계정 폴더가 낡은 앱 자료(옛 앱 자료 폴더의 home.sqlite, servers.json 같은 열여섯 이름)를 함께 가지고 있으면, 엔진은 새 형식으로 시작하지 않고 runtime-clean-start-required로 거절합니다. 읽을 수 없는 항목이 있으면 runtime-layout-unavailable로 거절합니다.

엔진 폴더 engine/

섹션 제목: “엔진 폴더 engine/”
항목 쓰는 프로그램 설명
home.sqlite (+ -wal, -shm) 엔진 기능 저장소 하나입니다. 표는 home.sqlite가 설명합니다.
home.lock 엔진 단일 인스턴스 잠금입니다.
home-runtime.json 엔진 손님이 엔진을 찾는 메타 파일입니다. 끝점을 듣기 시작한 뒤에 원자적으로 쓰고, 깨끗이 끝날 때 자기 것일 때만 지웁니다. 손님은 먼저 파일 권한이 사용자 전용인지 보고, 형식 버전은 1입니다. 이 안에 이번 실행의 손님 통로 토큰이 들어 있습니다(Credentials).
engine-identity.json 엔진 계정을 처음 준비할 때 한 번 만드는 엔진 신원입니다. 값은 en- 뒤에 128비트 난수를 16진수로 쓴 것입니다.
engine-format.json 엔진 새 형식 엔진 폴더라는 표지입니다. CLI와 sidecar가 이 파일이 일반 파일로 있는지로 새 형식을 고릅니다. 없으면 옛 형식으로 보고, 일반 파일이 아닌 것이 있으면 오류입니다.
install/id.json 엔진 설치 번호(16자리 16진수)입니다. 자격 증명의 이름공간 lyra-app-<설치 번호>가 여기서 나옵니다.
servers.json, profiles.json, host-keys.json, execution-map.json, release-ledger.json, credential-vault.json 엔진 { "revision": n, "body": … } 모양의 문서 파일입니다. 쓰기 전에 곁 잠금 app-data.write.lock을 쥐고, 파일을 다시 읽어 버전 번호가 다르면 쓰지 않고 data.changed-elsewhere로 답합니다. 임시 파일에 쓰고 이름을 바꾸므로 반쯤 쓴 파일이 남지 않습니다. credential-vault.json에는 비밀 값이 없습니다.
link-replay/, trace/, process/, marks/ 엔진 각각 Link의 재전송 기록, 추적 장부, 오래 사는 자식의 명단, 자식 표식입니다. 업데이트 점검이 이 이름들을 읽습니다.
execution/ 엔진 엔진 프로세스 안에서 도는 실행 호스트의 상태 폴더입니다. 그 아래 serial/<포트>/에 시리얼 포트의 보관 기록 custody.json과 port.lock이 놓입니다. 제품 시작에서는 같은 기록이 keeper/serial/에 놓이고, 엔진은 시작할 때 두 폴더를 모두 읽어 열린 포트가 있는지 봅니다.
agent-usage/ 엔진 에이전트 사용량 기록입니다(Status).
server-packages/<version>/, server-packages/incoming/ 엔진 업데이트를 받는 곳에서 내려받아 서명을 확인한 서버 패키지와, 네트워크 없이 사람이 넣어 둔 사본입니다. 이 버전과 가장 새 다른 버전 하나만 남깁니다(서버의 lyra-daemon).
home/home.sock 엔진 손님 끝점입니다. Windows에서는 소켓 파일 대신 이름 붙은 파이프 \\.\pipe\lyra-home-<tag>이고, <tag>는 실행마다 정해집니다.
home/desktop.sock 엔진 앱의 sidecar가 붙는 끝점입니다. 같은 폴더에 있고, 파이프일 때는 이름 끝에 -desktop이 붙습니다.
home/backup/ 엔진 스키마를 올리기 전 home.sqlite의 사본입니다. 새 사본을 만든 뒤 오래된 것을 지워 가장 새 둘만 남깁니다.
home/import/originals/ 엔진 옛 형식 문서를 가져올 때 원본을 보관하는 자리입니다.
home/ssh-password-cleanup.json 엔진 저장된 SSH 비밀번호 정리 작업(credential.ssh-cleanup-*)의 기록입니다.
control/engine.lock 엔진 쓰기 잠금입니다. 쥔 프로세스만 기록자입니다.
control/stop.sock 엔진 멈춤 끝점입니다. 기록된 keeper만 멈춤을 청할 수 있습니다.
control/stopped-by-person.json 엔진 사람의 멈춤을 적은 기록입니다(lyra daemon stop 쪽 코드가 이 이름을 씁니다).
control/execution-origin.sqlite, control/material.sqlite 엔진 실행의 최초 신원 색인과 위임 자료 저장소입니다. keeper는 자료 저장소의 열린 고정만 읽기 전용으로 셉니다.
logs/home.log 엔진 엔진 로그입니다. Logs가 설명합니다.

engine/에서 프로그램이 스스로 지우는 것은 셋입니다. home/backup/의 오래된 사본, logs/previous-runs/의 오래된 묶음(가장 새 셋만 남깁니다), server-packages/의 오래된 버전 폴더와 남은 .part 파일입니다. 그 밖의 항목에는 “안전하게 지울 수 있다”고 코드가 정한 것이 없습니다. engine-identity.json이 사라지면 엔진은 신원을 증명하지 못해 계정 확인에서 거절합니다.

keeper 폴더 keeper/

섹션 제목: “keeper 폴더 keeper/”
항목 쓰는 프로그램 설명
custody.sqlite (+ -wal, -shm) keeper 쥐고 있는 PTY와 자식의 보관 장부입니다. keeper의 시작 기록을 담는 표도 여기 있습니다(home.sqlite).
custody.lock keeper 보관 장부의 수명 잠금입니다.
keeper.sock, work.sock keeper 엔진이 붙는 두 끝점입니다. Windows에서는 이름 붙은 파이프입니다(Keeper socket).
activation.sock keeper 업데이트 같은 생애 연산을 받는 끝점입니다.
work/ keeper keeper가 띄우는 일의 고정된 사용자 전용 작업 폴더입니다.
process/, marks/ keeper keeper가 쥔 자식의 명단과 표식입니다.
serial/<포트>/ keeper 시리얼 포트의 보관 기록 custody.json과 port.lock입니다.
daemon.log, daemon.log.1 keeper, 엔진 둘 다 이 파일에 씁니다. 회전은 끝점 주인만 합니다(Logs).

앱 자료 폴더

섹션 제목: “앱 자료 폴더”

앱 자료 폴더는 lyra_platform::app_data_dir()가 정합니다. macOS에서는 <account home>/Library/Application Support/Lyra, Windows에서는 %LOCALAPPDATA%\Lyra입니다. 서버 리눅스에는 이 자리가 없어서 오류입니다.

항목 쓰는 프로그램 설명
logs/main.log 앱 main 5 MB씩 셋. Logs에 있습니다.
logs/sidecar.log, logs/sidecar-watchdog.log sidecar Logs에 있습니다.
home/watchdog/state-sidecar.<pid>.json sidecar sidecar의 멈춤 감시가 프로세스마다 쓰는 상태 파일입니다. <pid>는 쓰는 프로세스입니다.
update/transitions/<id>/ 앱 main 업데이트 때 lyra-desktop-sidecar 사본을 놓고 띄우는 자리입니다. 끝난 사본은 신원을 확인한 뒤 사용자 전용 폴더만 지웁니다(업데이트 생애).

Electron 자료 폴더

섹션 제목: “Electron 자료 폴더”

Electron의 app.getPath('userData')입니다. 시험 빌드는 이 자리를 시험 폴더 안으로 옮깁니다. 여기에는 두 가지가 있습니다.

항목 쓰는 프로그램 설명
recovery/ 앱 main 복구 기록입니다(createDurableRecovery가 이 폴더를 씁니다).
appearance.json 앱 main 첫 화면 전에 쓰는 테마와 팔레트의 복사본입니다. { version: 1, theme } 모양이고, 없거나 읽을 수 없거나 버전이 다르면 기본 테마(light)를 씁니다. 복사본을 잃어도 앱이 어두워지지 않습니다.

서버

섹션 제목: “서버”

서버는 <home>/.lyra/daemon/ 한 곳을 씁니다. 계정 런타임 폴더가 없고 home.sqlite 같은 저장소도 없습니다. 설치본 폴더와 상태 폴더는 Server state가 설명합니다.
