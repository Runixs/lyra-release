Logs and problem records

This content is not available in your language yet.

Lyra의 기록은 두 종류입니다. 프로그램이 파일에 한 줄씩 쓰는 로그와, 엔진이 home.sqlite에 남기는 문제 기록입니다. 로그는 프로그램마다 따로 있고 크기 한도에서 돌려 씁니다. 문제 기록은 사람이 설정 화면에서 읽는 것입니다. 파일의 자리는 Folders, 서버 쪽은 Server state, 문제 기록을 담는 표는 home.sqlite가 설명합니다.

로그 파일

섹션 제목: “로그 파일”
파일 쓰는 프로그램 한도와 돌려 쓰기 담는 것
<앱 자료>/logs/main.log 앱 main 5 MB씩 셋(main.log, .1, .2) 시각 · 종류 · 연산 이름 · 요청 번호 · 결과 코드 · 상태 전이 · 넘기기 단계. 입력과 결과 본문은 적지 않습니다. 이 모듈에는 입력을 받는 자리가 아예 없습니다.
<앱 자료>/logs/sidecar.log sidecar 5 MiB씩 셋(돌린 파일 둘) 연산 시간 기록과 상태.
<앱 자료>/logs/sidecar-watchdog.log sidecar의 멈춤 감시 1 MiB씩 셋(.1, .2) 감시가 본 멈춤과 회복의 줄입니다. 감시가 멈춤으로 보는 한도는 30초(STALL_LIMIT)입니다.
<엔진 폴더>/logs/home.log 엔진 5 MiB씩 셋(.1, .2) 코드만 있는 줄입니다. 한 폴더의 모든 줄이 쓰기 스레드 하나와 회전 하나를 거칩니다.
<계정 폴더>/keeper/daemon.log keeper와 엔진 5 MiB, 돌린 파일 daemon.log.1 하나 둘이 같은 파일에 씁니다. 회전은 끝점의 주인만 하고, 다른 쓰는 쪽은 바뀐 경로를 다시 열어 현재 파일에 이어 씁니다.
<상태 폴더>/daemon.log 서버의 lyra-daemon 5 MiB, daemon.log.1 하나 같은 쓰기 규칙입니다.
<계정 폴더>/logs/engine-start.log, keeper-start.log 엔진, keeper 파일당 한 줄, 256바이트 이하 시작에 실패했을 때의 닫힌 코드 한 줄입니다.
<계정 폴더>/logs/engine-start-progress.json 엔진 한 문서 시작 단계 표시입니다. 실패 로그를 대신하지 않고 준비됐다는 증거도 아닙니다.

쓰는 방식

섹션 제목: “쓰는 방식”
  • home.log: 줄을 1024줄짜리 대기열(QUEUE_LINES)에 넣고 쓰기 스레드 하나가 씁니다. 파일이 느리거나 막혀도 부른 쪽은 기다리지 않습니다. 대기열이 차면 그 줄들을 세기만 하고, 쓰기 스레드가 다음 줄을 쓰기 전에 버린 수를 먼저 적습니다. 로그를 닫을 때는 앞선 줄을 2초(FLUSH_DEADLINE)까지만 기다립니다.
  • daemon.log: 같은 방식으로 대기열을 쓰고, 한 줄은 고정된 사건 이름과 숫자와 코드로만 이루어집니다. 사건에는 시작(Start), 끝점 선점 실패(BindLost · BindFailed), 오래된 끝점 정리(StaleEndpointRemoved), 인사 거절(HandshakeRejected), 모든 종료(Exit), 내용 없는 패닉(Panic), 멈춤과 회복(RuntimeStalled · RuntimeResumed), 앞 프로세스가 기록 없이 사라짐(PreviousEndedUnrecorded)이 있습니다.
  • 시작 보고(engine-start.log, keeper-start.log): 로그인 시작기와 떼어 띄운 시작은 표준 오류를 버리기 때문에, 시작 실패를 앱이 읽게 하려고 파일로 남깁니다. 시작할 때마다 그 프로그램의 파일을 새로 쓰고, 실패했을 때만 한 줄이 있습니다. 줄은 lyra-daemon engine: <코드>[ <대상>] 또는 lyra-daemon pty-keeper: <코드>[ <대상>]입니다. 코드는 소문자 · 숫자 · - · .로 96자 이하, 대상은 글자 · 숫자 · ._-/로 100자 이하이고 /로 시작하거나 ..을 담지 못합니다. 계정 폴더가 아직 없으면 아무것도 쓰지 않습니다.
  • 쓰기 실패: main 로그는 첫 실패를 한 번 알리고 로그만 끕니다. sidecar 로그도 첫 실패에 한 번 알립니다. 로그가 안 쓰인다고 로그 대상 기능을 멈추지 않습니다.

이전 실행의 묶음

섹션 제목: “이전 실행의 묶음”

로컬 백그라운드 프로세스를 바꾸기 전에 home.log와 그 돌린 파일, 옛 daemon 폴더의 daemon.log를 <엔진 폴더>/logs/previous-runs/run-<밀리초>-<pid>-<번호>/ 아래로 복사하고 archive.json을 함께 둡니다. 가장 새 완료된 묶음 셋만 남기고, 모르는 폴더와 지금 쓰는 로그는 지우지 않습니다. 묶음을 만들지 못하면 home.log-archive-failed로 멈춥니다. macOS의 엔진은 시작하면서 옛 daemon 폴더를 정리하는데, 지우기 전에 이 묶음을 한 번 만들고 못 만들면 지우지 않습니다.

로그에 남기지 않는 것

섹션 제목: “로그에 남기지 않는 것”
  • 환경 변수의 값, 비밀 값, 원본 명령줄, 자식의 원본 stderr는 어느 로그에도 쓰지 않습니다.
  • main 로그는 연산의 입력과 결과 본문을 받는 자리가 없습니다. home.log와 daemon.log는 고정된 코드와 숫자만 씁니다.
  • 시작 보고의 코드와 대상은 위의 닫힌 문법만 받으므로 절대 경로, 환경 값, 문장이 들어갈 수 없습니다.
  • 문제 기록에 복사하는 로그 줄은 아래처럼 허용된 키와 값만 남기고 나머지는 ‹가림›으로 바꿉니다.

문제 기록

섹션 제목: “문제 기록”

엔진이 연산 하나가 실패하면 문제 기록 한 건을 home_problems에 남깁니다. problem.으로 시작하는 연산과, 실패가 아니라 물음의 답인 거절(예: session.resumable의 거절, 일회용 코드를 묻는 server.connect의 login-input-required)은 남기지 않습니다. 영역(area)은 연산 이름의 앞부분으로 정합니다.

연산 이름의 앞부분 영역
project · workspace · file · git projects
session · inbox lyra
terminal · server · update terminal · server · update
host · runtime host
그 밖 background

settings와 app은 화면이 problem.record로 직접 보고할 때 쓰는 영역입니다. 종류(severity)는 error · warning · info입니다. 코드가 info로 정한 것은 에이전트 기록을 아직 읽는 중이라는 답(usage.tokens-pending)과, terminal.detach가 돌려주는 pty-absent(터미널의 프로세스가 이미 사라짐)입니다.

정해진 값 뜻
30일 만든 지 30일이 지난 기록은 지웁니다(DAYS_30).
5,000건 가장 새 5,000건만 남깁니다(MAX_ROWS). 30일과 5,000건 정리는 엔진이 열 때, 기록을 쓰거나 읽을 때, 그리고 한 시간마다 돕니다.
10분 같은 merge_key의 기록이 10분 안에 다시 오면 새 줄을 만들지 않고 count를 올립니다(REPEAT_MS).

한 건에는 종류, 영역, 문장, 다음 할 일, 코드, 그리고 있으면 hostId · projectId · workspaceId · sessionId · terminalId · taskId가 담깁니다. 발생한 순간에 로그 끝을 복사해 함께 저장합니다.

  • 복사하는 파일 이름은 home.log, main.log, sidecar.log이고 각 파일의 끝 64 KiB만 읽습니다. 세 이름을 모두 home.log가 있는 폴더, 곧 엔진 폴더의 logs/에서 찾습니다. main.log와 sidecar.log는 앱 자료 폴더의 logs/에 쓰므로 그 폴더에는 없고, 없는 파일은 건너뜁니다. 그래서 이 빌드의 문제 기록에는 home.log의 줄만 복사됩니다.
  • 발생 시각에서 앞뒤 60초 안의 줄만, 성공(result: ok)과 요약 줄은 빼고, 파일마다 가장 새 12줄까지 남깁니다. 한 건의 전체 로그 줄은 6,144바이트를 넘지 못합니다.
  • 키는 op · result · reason · code · kind · state · subject · step · id · count · t · ts · durationMs · appVersion · program · own · running · pid · occurredAt만 남깁니다. 다른 키는 이름까지 ‹가림›입니다. 값도 코드 꼴이거나 숫자일 때만 남기고 나머지는 ‹가림›입니다.
  • 복사는 발생 때 한 번이므로 나중에 파일이 돌아도 복사본은 바뀌지 않습니다.

문제 기록 화면이 읽는 길

섹션 제목: “문제 기록 화면이 읽는 길”

설정 → 정보 → 「문제 기록」은 세 연산만 부릅니다.

연산 하는 일
problem.list 종류, 영역, 글(512바이트 이하), 쪽 나누기 표지, 기록 번호로 거릅니다. 한 쪽은 1건에서 50건이고 기본은 50건입니다.
problem.record 화면이 직접 보고하는 기록을 넣습니다. 알 수 없는 필드는 거절합니다.
problem.clear all: true만 받고, home_problems의 모든 줄을 지운 뒤 응답 실패 기록의 정리를 한 번 돌립니다. 되돌릴 수 없습니다.

이 호출은 화면에서 창 다리 lyra:call을 거쳐 sidecar와 엔진으로 갑니다(창 다리). 화면의 「기술 정보 복사」는 고른 기록의 기술 정보 글을 복사하고, 「로그 폴더 열기」는 앱 main이 app.reveal-folder의 고정 대상 logs로 **앱 자료 폴더의 logs/**를 엽니다. 그래서 이 단추로 열리는 것은 main.log와 sidecar.log가 있는 폴더이고, 엔진의 home.log가 있는 계정 런타임 폴더가 아닙니다.
