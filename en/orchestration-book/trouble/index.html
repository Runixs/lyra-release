When this happens

Find the symptom to see what it means and what to do, written separately for the person and for the agent.

A Worker has been quiet for over 10 minutes

Section titled “A Worker has been quiet for over 10 minutes”

No updates · worker-suspect

  • What you see: the session row shows No updates, and the Orchestrator’s wait wakes with worker-suspect.
  • What it means: no progress signal for 10 minutes. A build or test Lyra cannot observe looks exactly the same. The mark on a running tool tells only how long it has run and what a CPU measurement saw. No CPU use does not mean it is stuck, and CPU use does not mean it is fine.
  • What the person does: do not cancel right away. If in doubt, look at that Worker’s screen once.
  • What the agent does: look once: the turn in status show, what it last did in session read, the changes in git status. If the next checkpoint has no news either, tell the person what you saw. Never cancel, retry or re-dispatch on silence.

A turn ended without a report

Section titled “A turn ended without a report”

worker-stopped

  • What it means: the Worker ended its turn without reporting. That is neither success nor failure.
  • What the agent does: if it just asked you something, that question is the stop: answer it if you have not, and send nothing else. Otherwise send one message asking it to report its result or name its blocker. If it stops again, tell the person what it last said.

worker start stopped part-way

Section titled “worker start stopped part-way”

failedStep · created · next

  • What it means: one of its steps failed. What it already made (created) stays; nothing is rolled back.
  • What the agent does: read failedStep and next in error.detail. Do not run worker start again; fix the cause, then run next with a new --request-id.

A command ended with exit 3

Section titled “A command ended with exit 3”

Unknown

  • What it means: not failed but unknown: the first try may already have worked.
  • What the agent does: first read lyra request show <request-id> --operation <operation> --json for the stored response, then read the task or gate. message ask and message reply skip this lookup and repeat the same request right away. Reading a response applies nothing. When you ask again, use the same request ID and arguments. With no response it may still be in flight, so do not go around it with a new ID.

Refused by the depth limit

Section titled “Refused by the depth limit”
  • What it means: no deeper session can start from that place. The limit is a setting (2 by default). A Worker starts no session at any depth.
  • What the person does: if needed, raise the depth limit in Settings → Orchestration. Agents cannot change it.
  • What the agent does: give that part to a Worker or split it with a Workflow, or ask the task’s owner by message.

A handoff was refused

Section titled “A handoff was refused”
  • What it means: the receiver sits inside the branch being handed over (a loop), a Worker would receive a child, or the moving branch would pass the depth limit. Lyra checks before sending and again at receipt.
  • What the agent does: pick a receiver higher in the tree, or a Lead or an Orchestrator. Changing a role is planned.

A message was sent but not read

Section titled “A message was sent but not read”

delivery.pointer

  • What it means: accepted means stored, not read. Ordinary mail waits up to the Batch messages time (5 minutes by default) before its doorbell rings; --urgent mail rings at once. Lyra rings again by itself when the doorbell is briefly refused; a busy session reads it at its next check. Mail that cannot be delivered wakes the sender’s wait with message-held.
  • What the agent does: read the delivery and the doorbell (delivery.pointer) with message show. When your wait wakes with message-held: if the recipient closed, hand the work to a live session; if the outcome is unknown, do not resend — check session show and ask the person.

The agent shows a dialog

Section titled “The agent shows a dialog”
  • What it means: the Worker’s agent shows a dialog (update, folder trust, directory, model, hooks or a prompt) or never became ready. The task was not typed in.
  • What the person does: answer the dialog in that terminal.
  • What the agent does: ask the person to answer it in that terminal, then run next with a new --request-id.

An older lyra-daemon held the task for a person’s input

Section titled “An older lyra-daemon held the task for a person’s input”
  • What it means: the lyra-daemon running that Worker is an older version, so it did not type the task in while a person held that view’s input. The current version does not hold it.
  • What the person does: close that view.
  • What the agent does: ask the person to close the view, then run next with a new --request-id.

My own session ended

Section titled “My own session ended”
  • What it means: when lyra-daemon stops, every session it ran ends. A new session owns nothing until it adopts.
  • What the person does: tell a new session to take over the ended session’s work.
  • What the agent does: on the person’s word, find the ended session (failed or closed), adopt it with task adopt --from, and read the plan again with task list. If that session still runs, the adoption is refused.

A Worker cannot report

Section titled “A Worker cannot report”
  • What it means: the agent lost Lyra’s session variables. It must not guess IDs or set the variables itself.
  • What the person does: read the error and summary in that Worker’s final reply and act on them.
  • What the agent does: do not follow next. End with a final reply that quotes the exact error and gives your summary.

Cancelled, but it does not stop

Section titled “Cancelled, but it does not stop”
  • What it means: a cancel is one Ctrl-C, a request. The task reads stopped only when the Worker reports it or its process is proven to have ended.
  • What the person does: use session force-stop for a verified process stop. --abandon-unproven remains person-only and accepts that an unconfirmed dispatch may still run.
  • What the agent does: ask the Worker to report stopped. The Orchestrator or a Lead above it may explicitly force-stop it; otherwise ask a person. Retry or reassign only after termination is proven, never by starting a duplicate task.

Can I give the same task to a second Worker?

Section titled “Can I give the same task to a second Worker?”
  • What it means: no: the first dispatch may still run (the dispatch is unknown, or turn is not-started).
  • What the agent does: look first. If the attempt is returned, dispatch again with a new request ID; if it is dispatching, stop and tell the person.

terminal release does not go through

Section titled “terminal release does not go through”
  • What it means: a release first checks that the conversation and result are kept. No result yet, checking or closing means not finished; an unknown answer means nobody knows whether it was released.
  • What the agent does: no result yet: wait. Outcome unknown: tell the person. Never close the session instead of a failed release.

No more Workers can start

Section titled “No more Workers can start”
  • What it means: a person turned on “Concurrent Worker limit” in Settings → Orchestration, and the Working Workers have reached that number.
  • What the person does: raise the limit or turn it off.
  • What the agent does: wait for a Worker to finish, then start again. Only a person changes the limit.

The brief is over 16 KiB

Section titled “The brief is over 16 KiB”
  • What it means: a brief over 16 KiB with its footer is not typed in. Nothing started, and the task is still ready.
  • What the agent does: shorten the brief and point to files instead of pasting them. Then run next once with a new --request-id; the same code again → stop and report it.

lyra-daemon on this computer is not running

Section titled “lyra-daemon on this computer is not running”
  • What it means: lyra-daemon on this computer is not running, so commands cannot reach it.
  • What the person does: open the Lyra app, or start it with lyra daemon start.
  • What the agent does: tell the person; start it with lyra daemon start --json only on their word.

turn stays not-started and nothing follows

Section titled “turn stays not-started and nothing follows”

not-started

  • What it means: the text may sit unsent in its input box, or the agent sends no turn signals.
  • What the person does: look at that terminal; if text is waiting there, press Enter.
  • What the agent does: look for its changes first; none → ask the person to look at that terminal. Never dispatch it again or to a second Worker.

An escalation came from lyra-supervisor

Section titled “An escalation came from lyra-supervisor”

confirmedCause · neededDecision

  • What it means: it carries the cause Lyra confirmed and the decision needed. Lyra retries Claude rate limits before sending one.
  • What the person does: the Orchestrator asks you to decide: cancel, retry, a new Worker in the same Workspace.
  • What the agent does: for process exit, budget exhaustion, billing or login, tell the person. On their word, run task cancel, task retry, then worker start --task in the same Workspace. Pick another agent when quota is the cause.
